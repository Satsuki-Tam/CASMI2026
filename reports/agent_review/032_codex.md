**Q1：仮説は検証に値するが、効果の符号と大きさは未確定です。**

取得の独立性を判定する目的で使った `similarity ≥ 0.98` は、推論時には強い参照を排除することがあります。同一取得ではないことが保証された query に対して、類似しているという理由だけで参照を捨てる必然性はありません。一方、独立取得という条件は「高類似の参照が全て正解構造に属する」ことを保証しません。公式 identity が異なる異性体、構造識別に乏しい少数の強い断片、参照ラベルの誤り等では、高類似でも誤候補を助けます。C2/C3 の真には公開参照がないため、そのクラスで復活する参照は正解構造の参照ではありません。

これは抽象的な懸念だけではありません。保存済み特徴生成の `n_susp_dup_truth` / `n_susp_dup_other` を分子単位で数えると、次のとおりです。ここでの「疑い」は完全一致とは別に entropy 閾値で分類されたものです。

| 層 | 分子数 | 真の参照に疑いあり | 非正解候補の参照に疑いあり |
|---|---:|---:|---:|
| パネル | 250 | 0 | 0 |
| C | 100 | 20 | 0 |
| D | 100 | 0 | 0 |
| E | 100 | 16 | 4 |
| F | 100 | 3 | 0 |
| G | 100 | 0 | 0 |

E の非正解候補側は4分子・10参照です。さらに既存の `lib_sim_c2_keepdup` 診断列では、**2分子の非正解候補4件**が、標準類似 `0.949617 / 0.914645 / 0.949816 / 0` から `0.999774 / 0.999974 / 0.999930 / 0.995271` になります。4候補とも元の C2 shortlist に入っています。これで最終順位が悪化するとはまだ言えませんが、フィルタ解除が真以外を助ける経路は実データにあります。類縁体か誤ラベルかも、この集計だけでは確定しません。

上表は後段の library mask / cap より前の件数で、提出版で実際に復活する件数とは異なります。また既存の `_keepdup` は `kept + kept_susp` の順で cap を掛けます。`DUP_SIM=1.01` の実推論では参照の元の順序で通過するため、cap の結果まで一致するとは限りません。この診断列だけを既存表に差し替えて、新版の MRR を測ったことにはしないでください。

追記07:55の **183,191/275,810 構造が timsTOF 参照を持つ**ことは、装置が合う参照を利用できる候補が多数ある根拠です。ただし66%は train 構造の比率であり、隠し C1 の比率や、隠しで ≥ 0.98 になる比率ではありません。COCONUT と重なる300構造という数字も、隠しの synthetic / analog を含む選択分布を決めません。G の局所 C1 は真の enveda-180 参照を除くので、そこで除外件数0や改善なしでも、隠しの独立した同装置参照の利得は否定できません。今回の一度の比較を行う理由にはなりますが、大きな Public 上昇の予測には使えません。

「隠し query は全て新規取得であり、公開 library に同一取得が絶対にない」は、根拠を分けて記録してください。[公式データ説明](https://www.kaggle.com/competitions/enveda-CASMI26-molecule-id-mass-spectra/data)の保存版は、全 test が timsTOF、Class 1 が公開参照を持つ構造、Enveda の参照と装置が合うことを説明していますが、今回確認した本文には全取得の非重複を保証する記述を見つけられませんでした。運営の別の一次資料があるならその出典を添えるのがよいです。Web の本文は取得できず、ここは `docs/official_refresh/pages/data-description.md` の確認範囲です。仮に独立取得が保証されても、前述の誤候補の経路は残ります。

**Q2：一度の診断比較は妥当。ただし提出と基準昇格を分け、次の確認を追加する。**

変更の範囲は提案どおり、**0.370 を出した実際の full_eval kernel / dataset 版から、推論時の entropy による除外だけを無効にする**ことでよいです。`DUP_SIM=1.01` でも目的は達成できますが、実行 manifest に「完全一致の判定は維持、entropy 除外は無効」と値・コード版を明記してください。学習・既存の正式評価表・source mask・ranker・出力式は固定し、今日の T/B/band の結果でこの条件を変更しないことを勧めます。

1. **パネル16分子だけを確認集合にしない。** 保存済みパネル全250でも entropy による疑い件数が0なので、主に未発火経路の確認になります。C/E/F の真側の疑い例と、E の非正解候補側4分子を加え、完全一致は両版で除外、entropy のみの除外は新版で通過、旧閾値未満・mode/precursor 条件外は不変、cap 発火時は意図した参照が残ることを確認します。真側の復活例は実装確認に使い、取得の独立性を証明できない C1 の性能向上とは扱いません。
2. **不変性の確認は、参照段階と計算予算を含む全体で分ける。** 同じ forward スコアを与えるか、両版とも全件計算できる小集合なら、entropy のみの除外対象が無い分子について、参照特徴・shortlist・top-25 の一致を確認できます。しかし本番では `b1_pipeline.py:440` が `lib_max` の弱い順で GL を回し、時間予算と fallback があります。復活した参照が候補と実行順序を変えると、直接の発火が無い別分子にも GL 被覆の変化が及び得ます。「最終出力が変わるのは発火分子だけ」は、本番全体の必須不変条件にはできません。
3. **C2 は局所の悪化方向を確認する。** 既存の正式表を上書きせず、同じ固定 C2 台帳・真の identity/全参照除外・外部候補資格を維持した診断版で、新しい参照規則を適用します。最低限 E の4分子で候補・特徴・順位を追い、採用判断に進む前には元の C2 全分母で paired MRR を報告します。発火例だけの平均を保護スコアにせず、作業用基準との差と M2x からの累積差の既定の点条件を使います。既存 forward は同じ query/candidate 条件のものを再利用し、新規候補があれば補う形でよく、再学習は不要です。C1 の取得未確認の利得は「未測定」、C2 は「測定可能」と分けるのが正確です。C2 を未確認のまま先に一枠使う場合は、診断提出として扱い、保護済みの新基準にはしません。
4. **件数の出所を記録する。** entropy のみで落ちていた参照数、実際に mask/cap 後へ復活した参照・公式候補 key・分子数、library、cleaned peak 数、shortlist の出入り、GL 被覆・fallback・所要時間を少なくとも比較できるようにします。checkpoint/ranker/参照データ・コード・パラメータの版も固定します。011で確認済みのとおり、通常の保存 run の manifest は train 由来の可視ダミー test の記録です。今回も run の入力 ID と種類を確認し、隠し再実行の記録が取得できないなら**隠しでの発火件数は不明**とします。可視の件数から隠しの利得を説明しないでください。
