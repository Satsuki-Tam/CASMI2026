## 1. 主実験の停止(`028_decision.md` §7)
- 台帳(`exposure_ledger.py`)は trainer の `Data.tr` を再現し、fold0 の正例 key 数 219,155 が公開 kit の SPLIT_AUDIT と一致。opt-in の特徴 `fp_pos`・`negpool` を feature module・trainer・評価器に追加し、回帰試験(特徴なしの再学習が rank_rk_fx と同値 = 111,026 トークン中 2 つが相対 6e-15 で違うだけ、評価器の rank_v4b の予測がバイト一致)は合格。
- 学習した rank_rk_exp の gain の首位が negpool(204,245、z_gl の約 4 倍)で、原因を調べて**二つの漏洩**を見つけ、評価結果を見ずに停止・隔離した:
  - **negpool**: 学習・評価の分子はすべて train 構造なので、C2 view でも真は v2 pool にいる(train 由来の項目)→ 「negpool = 0 = PubChem のみのデコイ」で Pc を全部落とす規則になる。view に整合させると negpool ≈ in_train ∨ in_coconut で、意図的に外した in_train を戻すだけ。
  - **fp_pos**: rkfit・dev2・locked2 は identity ごと FPNet から保留 → その C1 行では真だけが「正例でない train 候補」。隠しのクラス 1 の真は全 train FPNet で既見なので逆向き。dev2 C1 の評価も水増しされる。
- 提案する漏洩のない設計: **C1 行 = identity 既見・query 未見の分子のみ**(eval_c1 の既見 281、W7 の既見 84)、**C2 行 = identity 未見の分子のみ**(rkfit 600、W7 未見 516、eval_c1 未見 19)、対照 = 同じ構成で fp_pos なしに再学習した ranker(一変更)、評価 = パネル C1(既見)と dev2 C2(未見);dev2 C1 は保留なので露出モデルの評価に使わない、negpool は使わない。
  - 問題: C1 の学習行が 365 分子に減る(rank_rk_fx の C1 は rkfit を含む)。対照も同じ構成で学習し直すので比較は公平だが、ranker 自体は弱くなり得る。
