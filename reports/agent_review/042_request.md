## 3. 評価設計(案、結果の前に固定したい)
**C3 view(クラス 3 の代理)**: 各分子の C2 view の候補から真(公式 key・raw key・互変異性 alias・identity group)を除く = 「真がどの DB にも無い」。登録主出力の MRR は定義上 0。
- 生成候補: 親 = C2 マスクのアナログ上位 P=10、目標 = query の前駆体 m/z と adduct から求めた中性質量(パイプラインと同じ)、生成物のうち **その分子の窓(全 window key)に無いもの**を「新規」とする(C3 では真の key を窓から除いて判定)。窓の key と FPNet の query logits は登録表と同じ引数の `b1_features.py --dump_gen` で出力(表が登録版と同一であることを確認する)。
- 生成候補のスコア: f·z(登録表の FP と同じ関数・同じ logits)、GLACIER(生成候補を runner に追加)、アナログ ap、親の類似度、変換の段数。
- **統合規則(候補、tune で 1 つ選んで eval で 1 回だけ読む)**: 登録主出力(anaw0.5)の順位はそのまま、生成候補をゲート付きで挿入:
  - g1: 生成候補の最良 f·z − DB 候補(shortlist)の最良 f·z > δ なら 1 位に、そうでなければ k 位(k ∈ {3, 6, 11})に最良の生成候補 1 個。
  - g2: g1 + GLACIER: 生成候補と DB 上位 5 の z(FP)+z(GL) を同じ尺度で比べて上回れば 1 位。
  - δ・k は tune(パネル前半 + dev2 の奇数 identity)で選び、eval(残り)で 1 回読む。
- **C1/C2 view への影響**: 同じ規則で生成候補を足す(真は DB にある)→ 登録主出力からの Δ(押し下げの損失)。
- **判定(案)**: J(w3) = (1 − w3)·Δ_C12 + w3·Δ_C3、w3 = 0.3(隠しのクラス 3 比率の控えめな値)で J > 0、かつ C1(パネル clean 202、dev2 C/E/F/G)と C2(dev2 C/D/E/F/G)の全層で Δ ≥ −0.01(点推定)。損益分岐の w3* も報告。Public は一変更の比較(読み +0.008 以上で暫定採用)。
