## 3. 提出候補 E4(公開 v18 = E0 からの最小変更、class-1 経路は不変)

1. PubChem 専用チャネルの出力 K: 25 → 100(`CORE` の `K = 25`)。
2. GLACIER の入力に、lib_max < 0.9 の分子の PubChem リスト全 100 件を追加(ICE の入力は不変。T4 で GL 約 75 pred/s、追加 ≈ 240 分子 × 100 候補 × 2〜3 CE ≈ 6〜7 万予測 ≈ 800〜1,000 秒、GL_BUDGET 4,000 秒内)。
3. PubChem リストの再順位を「上位 25 同一分子式 slot 再順位(ICE+GL)」から「リスト全体の z(pc_fz) + w·z(GL)」に置換(pc_fz は z(f·z)+0.15·pop の融合値で、Notebook 側には候補ごとの生 f·z と pop が無いため base 形)。w は 2 を第一候補(模擬で確認中)。ICE は PubChem リストから外す。
4. ゲート・slot・昇格(S, top_pop, rel)は不変。base リストの ICE/GL 再順位も不変。

期待値の粗い見積: 公開 LB ≈130 分子のうち class 2 が 4 割なら、PubChem リスト MRR +0.07 は最終リスト(slot 2 or 4、昇格時 1)で約 +0.03〜0.04/分子 → 全体 +0.012〜0.016。不確実性は大きい(class 構成、ゲートの挙動、hidden の化学が A と異なる)。B の結果(天然物化学、CE 欠損の交絡あり)で方向が一致するかを見てから決める。

## 4. 質問

1. P1 の設計で見落としはあるか。特に (a) class-2 模擬として「正解の学習構造としての存在だけを隠し、他の学習構造は競合候補として残す」扱い、(b) 窓全体の z 標準化(shortlist 内 z)と Notebook の pass-2 集合内 z の差、(c) 到達不能な正解(window_external=False)を 0 とする「strict」値と、残す値の併記。
2. 公開規則の再現(`p1_evaluate.public_rerank`)は `gl_fuse.rerank_multi` の意味(上位 25、同一分子式 ≥2 件、被覆 ≥2、群内 z、slot 固定)を保っているか。差が「規則の形」によるという結論は妥当か。
3. E4 を本日提出する価値はあるか。私の判断は「B で方向が一致し(GL 融合が公開規則を上回る)、tune 群で w=2 が w=1 を下回らなければ提出する。E0 と同じ Docker/データ版で変更点を 3 つに限定し、LB 差を変更に帰属できるようにする」。反対理由があれば示してほしい(例: 提出枠の温存、hidden の class 構成が不明、K=100 による GL 予算超過時の挙動)。
4. 重みの選び方: 300 分子全体で選んだ w=2 / prior 0.5 を、fit/tune/eval のどの群で確定し、どの群で報告すべきか。P3(LambdaRank)に進む前に、この固定 z 和を基準として凍結してよいか。
5. B(公開 NP ライブラリ、CE 欠損 96%)の結果が A と食い違った場合の解釈ルールを先に決めたい。案: 「timsTOF・CE 既知が本番条件なので A を主、B は化学の層別として方向のみ確認。B で GL 融合が公開規則を下回る場合は E4 を見送る」。
