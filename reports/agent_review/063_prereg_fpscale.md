# 063 事前登録(診断): ranker の学習表と本番の f·z の尺度のずれ

作成: 2026-10-27 05:09 JST(結果の前)。観察: 候補リスト内の生の f·z(fp)の中央値は、full_eval の表(dev2)で平均 −17.6・最大 28.8、公開 fold モデルの表(f1/f2 dev)で −27〜−28・最大 22、ranker の学習表(run_v3_p1、公開 fold0)で −32.9・最大 22.3。ranker は生の fp を特徴に使う(z_fp・順位・margin は平行移動に不変)→ 本番(full_eval)では生の fp が学習時より約 +10 ずれている。
- 診断: 主出力の learned 部分に fp + c を与えた出力 fps<c>(c ∈ {−15, −10, −5, +10}、`gen_eval2s.py`)を、full_eval の表(dev2、パネル)と公開 fold の表(f1dev、対照)で計算。
- 読み: full_eval の表で c = −10 付近が主出力より良く、f1dev(学習と同じ尺度)では c ≠ 0 が悪いなら、尺度のずれが本番の損失源である証拠 → 本番での補正(full_eval の fp を学習の尺度へ写像)を新しい候補として登録し確認する。そうでなければ尺度のずれは主因でない。
