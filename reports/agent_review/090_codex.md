# 090 回答: 人気度への依存と、隠しの分布について推定できる範囲

2026-10-27。090_request、090_prereg_popshift（18:48追記まで）、088_codex、041 の登録と結果、保存済み prior 診断、特徴定義・評価器・090 の起動スクリプトを確認した。090 の変種の評価結果・途中ログは読んでいない。再計算、学習、ジョブ変更、提出は行っていない。

**人気度への依存を弱める実験を支持する。ただし「053 は隠しより有名な正解に偏る」は有力な仮説であり、prior-only=0.135から確定した事実ではない。主指標は実データの f1/f2 dev NP C2、再重み付けは感度分析にする。パネル C1 clean は保護から外さず、R0〜R3で固定則とrankerを切り分け、R4はより強い変更として扱うのがよい。**

**Q1: 仮説は検証に値するが、prior-only の一つの平均から隠しの順位分布は復元できない。**

E0 の engine1 ranker に明示的な人気度特徴が無いことは、B1 と比較する新しい根拠になる。一方、E0 の BASE には人気度の再順位があり、ranker の library 件数・analog・候補源・学習母集団にも、研究や収載の多さと相関する情報が残る。「E0 は証拠だけ」「B1 の7特徴が主因」とまで進めるには、今回の ablation が必要である。BASE の 0.15 と B1 の 0.15 も、prior の項・正規化・候補集合が違うので同じ強さではない。

「公開スペクトルが無い」から「論文・物質登録が少ない」は必然ではない。既知の有名な化合物でも公開スペクトルを欠く可能性がある。また、prior 順位が低い群で v7f が弱いという相関には、候補数、同式の難しいデコイ、FP の適合、装置、GL 不足等も含まれる。**同じ query・同じ shortlist で prior の扱いだけを変えた差**を取ることで、少なくともこの変更の局所的な効果は測れる。

prior-only probe は、実際には「現在の shortlist 上の pop 順位＋FP tie-break」である。絶対的な知名度の測定ではなく、候補生成と競合候補にも依存する。以下では、この probe と共通の shortlist に真がある事象を A、到達率を a、prior-only の RR@25 を Yp とすると、

`0.135 = E[Yp] = a × E[Yp | A]`

である。a=0.5/0.6/0.7 と仮定すれば、条件付き平均はそれぞれ 0.270/0.225/約0.193 になる。しかし平均が0.225だと分かっても、例えば次の二つを区別できない。

| 到達した分子の prior 順位分布 | MRR@25 |
|---|---:|
| 22.5%が1位、残り77.5%が26位以下 | 0.225 |
| 半分が4位、半分が5位 | 0.225 |

前者は「一部が非常に有名で、多くは下位」、後者は「全て中程度」で、prior を弱めたときの効果は違い得る。したがって、提案の 9%/18%/30%/43% は一つの仮定であって推定された分布ではない。11位以下は11〜25位と26位以下を分けると、打ち切りによる情報の欠落も見える。

さらに重要なのは、**0.135はT/B/Pc等を混ぜた全 Public の平均なのに、053 NP C2だけへ合わせようとしている**点である。到達分子内にも C1 と C2 の混合が残る。全体の平均に合わせた NP C2 の重みを「隠し C2 の人気度」と解釈できない。f1/f2 dev の prior-only が0.135に近いことも、それだけで隠しに近い証明にはならない。

追加の観測から得られる制約は次の程度である。

- 同じ Public cohort・同じ候補集合と確認できた主出力のスコアを m とすれば、`a ≥ m`。例えば m=0.379なら、条件付き prior MRR は概ね `[0.135, 0.356]` に入る。0.390版まで shortlist が共通と確認できれば上端は約0.346となる。これ以上の a=0.6 等は仮定である。
- B の真の母集団割合を sB とすれば、B probe は最大でも sB。固定した同じ所属定義なら、E0_B=0.259から `sB ≥ 0.259` は言える。しかし E0 の到達率が B1 と同じとは言えず、B1 の prior 順位にも直接変換できない。
- 同じ版・同じ最終25件から作った T/B/Pc probe が揃えば、その和は主出力以上、かつ同じ shortlist の到達率以下になる。真の所属が互いに排他的だからであり、到達率の下限を強められる。ただし、各 probe は別の順位方策の平均なので、人気度分布は依然として決まらない。旧版のTと現在版のBは合算しない。
- prior-only と B probe は、同じ分子で同時に得点し得る。その二つを足して到達率とすることはできない。prior-only を所属別に分けた追加 probe でも得られるのは各群の平均であり、分布全体ではない。今すぐそのために提出枠を増やす優先度は低い。

再重み付けを使うなら、**一つの最適な重みを当てるより、許容する複数の重みで差の符号が変わるか**を見る。各層の prior-only 平均を μh、変種の平均差を δh とし、到達率・クラス混合について明記した仮定の下で、観測と矛盾しない重みの範囲における `Σ wh δh` の最小・最大を報告する方法がある。ただし、層内の δh まで隠しへ移せるという追加仮定が必要で、順位層だけでは装置・候補難度の違いを補正できない。過去の Public に合わせた mixture 推定も、この仮定を置いたシナリオとして読む。

041 の「低 prior 群で +0.016、高 prior 群で −0.020、登録条件不合格」という結論は維持する。090 は ranker の特徴除去も加えた新しい検証であり、041 を未検証の案に戻したり、重みを変えて過去の不合格を合格へ読み替えたりしない。

18:48追記の、学習側の一律な `prior_iw` を今回に加えなかった判断も支持する。学習C2の84%がprior 11位以下でも、その多くが合成分子なら、NP条件付きでの人気度依存とは別の話である。「学習全体が有名な正解だらけ」という説明は支持されず、NP/合成、COCO/非COCO、GL経路を条件にした依存を調べるべきである。低priorが実際の登録数の少なさなのか、prior表の未対応key・欠測なのかも既存の列で区別できるとよい。

**Q2: 主指標は(i)。ただし「隠しに近い集合」ではなく、低 prior が多い実在の開発集合として扱う。**

090 の暫定登録にある「foldを等重みのblock、各fold内のC/D/E/Fをプール」は支持する。各集合の重みは結果前に固定し、**全対象を分母にした strict C2 の一対差**を使う。候補外の真は0のまま残す。複数 view や query がある場合、CI は identity 単位でまとめて再標本化する。

全体平均と併せて、C/D/E/F、COCONUT所属/非所属、GL被覆あり/保険経路を必ず出す。f1/f2 dev の E/F は保険経路が多いため、平均改善がそのまま「ranker の人気度依存が律速」という証拠にはならない。B 優位の説明が目的なら、COCONUT所属 C2 での B 内順位と最終25件への採用も別に確認する。

(ii)は副次的な感度分析にとどめ、単一の人工的な重みで非負かどうかを候補の必須条件にすることは推さない。到達分子だけを再重み付けした差は条件付きの値であり、strict の(i)と同じ尺度ではない。候補集合を固定した実験なら、対象の到達率を仮定して初めて全分母の差に戻せる。層は全変種に共通の基準候補・pop順位で固定し、変種の出力に応じて所属を変えない。

**090 の保護条件は修正を推す。** 「害が確認されなかった」と「許容範囲内と確認できた」は違う。差のCIを `[L,U]`、ε=0.01 とすると、

| 状態 | 条件 | 読み |
|---|---|---|
| 非劣性を確認 | `L ≥ −0.01` | 許容損失内という根拠がある |
| 害を確認 | `U < −0.01` | 許容損失を超える根拠がある |
| 保留 | それ以外 | 許容損失を超える可能性が残る |

暫定登録の「U < −ε でなければ選択可」は、保留まで合格に含めている。通常の採用候補としては、G C1、053 NP C1、**パネル C1 clean**を上の非劣性基準で確認する方を推す。053 と G だけでは、panel にある FP の identity 学習済み・query 未見という C1 条件を代用し切れない。なお、再学習を伴う変種まで「パネルは確実に下がる」と決めつけず、実測する。

未知の隠し分布を調べる目的で、パネルの明確な損失を伴う比較提出を考える余地はある。その場合は **保護合格とは別の、損失を承知した診断**として扱い、結果前に費用と判定を記録する。例えば、同じ全分母での C2 利得を g、C1 損失を c とし、その二群だけの仮定なら、利益が勝つのは `C1割合 < g/(g+c)` である。複数のC1条件とその他の層も含めて、どの混合で符号が変わるかを示す。C1の人気度が不明であることは、パネルの損失を0扱いする根拠にならない。

**Q3: 5変種は診断として妥当。点推定最大の一本を選ぶ規則は避ける。**

R0〜R3は、rankerの4特徴除去と固定則のprior重みの2×2比較になっている。

| 差 | 主に調べること |
|---|---|
| R1 − R0 | 元rankerのまま、固定則・保険の重みを弱める効果 |
| R2 − R0 | 固定則0.5のまま、rankerの4特徴を除く効果 |
| R3 − R1 | 固定則0.15で、rankerの4特徴を除く追加効果 |
| R3 − R2 | 4特徴除去後に、固定則を弱める追加効果 |
| R3 − R2 − R1 + R0 | 二つの変更の相互作用 |

`gen_eval2fd.py` の分岐では GL 不足時にrankerを使わない。したがって、その同じ行では **R0=R2、R1=R3** になるはずで、これは有用な実装確認にもなる。利得が E/F のfallbackに集中して R3−R1 がほぼ0なら、支持されたのは主に固定則の変更である。R3へranker差し替えまで含める必要性は弱く、より小さいR1の変更を別途検討する根拠になる。

R4−R3は、残り3特徴の除去と固定重み0.15→0を同時に変えるため、どちらの効果か分けられない。しかも `in_coconut`、`in_tier`、library/analogの情報やpriorを使ったshortlistは残る。**「指定した7特徴と明示的な加算を除いた変種」と呼び、「証拠のみ」とは呼ばない。** 評価器は3モデルそれぞれのmain/pw0.15/pw0も出すので、登録5変種を超える出力が存在する。余剰の比較を機構診断に使う場合も、提出候補を後から増やさない。

結果未読の時点で、R3/R4から一つ選ぶなら以下の順序を推す。

1. **資格条件**：主指標(i)の差が登録どおり +0.005以上、fold1/2とも差が正、結合したidentity単位のpaired CI下限が0を超える。加えて、上記C1保護の非劣性を満たす。(ii)は複数シナリオと層別の費用を併記する。
2. **基本候補はR3**。R4へ進めるには、R4自身が資格条件を満たすだけでなく、R4−R3の主指標に +0.005以上の追加利得とCI下限>0があり、C1の追加費用も許容範囲内であることを要求する。小さい点推定差だけならR3を残す。
3. どちらも資格条件を満たさなければ、通常の採用比較の候補は作らない。保護が保留または不合格でもPublicを使う場合は、前述の費用を測る診断として別に登録する。

これは開発集合上の選択規則であり、複数比較後のCIをそのまま「独立した95%確認」とは呼ばない。既に使っている053/f1/f2の再利用でもある。083を使うなら、候補を一つに固定して割当てを別途登録する。ただしCOCO確認だけで低prior全域やC1保護が済むわけではない。

**Q4: 090の診断と088(a)は並行してよい。組み合わせの採否は、単独比較の後にする。**
