# 150 下書き(2026-10-30 12:34 JST、Claude Code。登録ではない)— S3: class 3 の生成物を第二エンジンの中で採点するための学習行の設計

Codex 147 Q4 の「S3 の行の設計」。149(S2 の MIST の比較)の結果を待たずに、エンジンの FP の源とは独立に設計できる部分をまとめる。

## 1. 何を作るか
- E2(または E2′)が、DB の候補(E 窓)と生成物を、一つの順位で採点できるようにする。
- いまの gt3(生成物を 3 位に挿入する規則)のような外付けの規則ではなく、生成物を候補の一種としてエンジンに学ばせる。
- E0 の engine 1 は、窓に生成物(最大 150)を含めて、本体の ranker で採点している(069)。
- W135 の確認(139)では、選択の損失(17 RR 点)が位置の損失(12.2)を上回った。順位器が生成物を見分ける力が、主な制約である。

## 2. 世界(Codex 147: 正解を窓から消すだけにしない)
- W135 の共通の世界(b1_world)を使う。バッチの全分子で、C1 / C2 / C3 を同じ規則で隠す。
- C3 の identity は、その世界の全ての DB(pool / COCONUT / PCL / BIO)、参照、analog、上流の学習資産から一貫して隠す。
  - FPNet は fold-safe 版を使う。
  - MIST を使う場合は、MSG との交差を記録する。
- 親は、同じ世界の mask を通した analog の検索から作る(真の構造を手で加えない)。
  - 生成は b1_gen v2(36 の編集、1〜2 段)。
  - 質量の照合は max(2 mDa, 10 ppm)。目標の質量は query から求め、真の式は使わない。
- 生成物が 0 の分子や、正例の無い分子も、母集団に残す。

## 3. 生成物の特徴(DB の候補と同じ経路で作り、生成物に固有の列を足す)
- **共通の列**: f.z(同じ zlog)、MetFrag-lite、analog(Morgan Tanimoto × sim³)、ppm、窓の中での順位 / z / gap。生成物は、DB の候補と同じ窓の中で比べる。
- **生成物の列**
  - is_gen(DB の候補は 0)
  - 段数(1 / 2)
  - 親の analog の類似度(親のスペクトルと query の類似度)
  - 親との Tanimoto
  - 編集の種類の事前確率(学習の fold だけで推定する)
  - 同じ生成物を作る親の数
- ライブラリの列は、生成物では 0(参照が無い)とする。nref 0 との区別のために、is_gen を使う。

## 4. 学習行
- **C1 / C2 の行**: いまの E2 と同じ(窓に生成物を加える)。DB に正解がある分子でも、生成物は負例として窓に入る。こうして、生成物が DB の正解を押し下げる失敗(752356 の gen20 の −0.010 と同じ型)を学ぶ。
- **C3 の行**: 正解が全ての DB から隠れた分子。
  - 正例は、生成物の中に正解の official key がある場合だけ(生成で届く場合)。
  - 届かない群は、正例の無い群として残す。点ごとの学習では、負例だけを与える。
- **重み**: 群ごとに総重み 1。C1 : C2 : C3 の群の比は、混合 π を固定して与える(開発の結果を見て変えない)。
- fold 3/4 の交差で学習する(149 と同じ)。

## 5. 評価
- W135 の世界で、π = 0 / 0.3 の混合(139 と同じ π の表)。
- 完成系 F(P + E2 + 生成物)と、F(生成物なし)を、同じ query で比べる。
- **主指標**: 混合の世界での通常の MRR の差。
- **保護**: C1 / C2 の層(生成物が DB の正解を押し下げないか)。
- **記述**: C3 の到達(生成物の中に正解)、到達した場合の順位、構造の近さ別(親との Tanimoto の帯)。
- 予約した確認の集合は、S2 と S3 で使い回さない(147)。

## 6. 未決の点(Codex と決める)
- C3 の学習行の数と、W135 の既存の世界(fold 1/2 は使用済み)を学習に使ってよいか。
- 生成物の特徴を E2 の学習に入れると、C1 / C2 の順位も変わる。S2 の比較(149)とは、別の候補として扱う。
- 隠しテストの class 3 の割合が分からないので、π の感度の表を必ず併記する。
