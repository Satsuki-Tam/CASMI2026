# 019b: full_evalのパネル取得保留

**設計変更には賛成する。ただし現時点の名称は「学習済みidentity・query由来の重複を除外したC1代理」とし、取得の独立性が確認済みとはまだ言わない。** 同じ分子の独立スペクトルを学習に残すことは018の評価設計と整合する。パネルC2を記憶残存の診断とし、dev2/locked2をgroup単位で保留する分け方も妥当。

1. **0.95は重複候補を拾う基準で、同一取得の判定ではない。** 独立取得でも同じ分子なら高類似になり得る一方、同一取得のピーク除去・強度処理・質量再校正等で0.95未満になり得る。同adduct・前駆体差5 mDaという前段フィルタも、表記違いや再処理で取りこぼす。0.98より多く除外する方向ではあるが、0.95を採ったこと自体は独立性の証明にならない。閾値はMRRを見て選び直さず、由来が分かる例と除外件数・失われる取得数で妥当性を見る。

2. **実装に監査対象の漏れがある。** `prep_full_eval.py`はパネルと同じraw `inchikey14`だけを検索する。集計すると、パネル250キーのidentity groupには計265キーがあり、**別キー15件・490スペクトルが現在の重複検索対象外**だった。これらが重複だと確認したわけではないが、検索をidentity group／公式同一性まで広げる必要がある。由来IDや完全一致ハッシュによる検査は、構造ラベルが異なるコピーにも適用する。

3. **取得単位の監査を補う。** 元のaccession・USI・run/scan・公開元などが利用できれば最優先し、同一取得から派生した別処理版をまとめて除外する。各queryについて「最も近い残存学習スペクトル、由来、類似度、前駆体差、adduct/CE、判定理由」を保存する。全1,184行を除いた点はよいが、別ライブラリというだけで残り約55,600行を独立と断定しない。由来が確認できないものは「不明」とし、評価値を見る前に監査済み／不明の分子群を固定して両方報告する。学習側だけでなく、C1参照検索側にも取得除外を適用する。

4. **fold0との差は「記憶の利得を直接測定」ではない。** full_evalはパネルidentityの露出に加え、他の学習分子・学習量の配分も変わる。まずは同じquery・窓・参照条件での二つの学習方針の差と報告する。記憶だけを切り分けるには、同じfull_evalレシピで「パネルの他ライブラリ取得を含む／パネルgroup全体を除く」の対照が必要。パネルは参照が豊富な既知NPに偏り、開発に繰り返し使われているため、C1全体や隠しクラス比率へ外挿しない。

現在のrunの入力は変更せず、監査と結び付けて保存する。残存コピーが見つかれば、完成後に参照検索から消すだけでは学習済みの記憶は消えない。独立取得での性能を主張する版は、修正した除外条件で再学習する。疑いがある現版は診断用として区別する。

補足: 実行引数の`--holdout hold,lock`は確認できた。ただし準備コードの`holdout_training_overlap=0`は直書きなので、検査は実際の`D.tr`／サンプラのSIDとhold・lockの交差から算出するのがよい。

確認: `019_decision.md`、`prep_full_eval.py`、full_evalのgate・launch・trainer、trainメタデータとidentity対応表。学習プロセスや入力は変更していない。
