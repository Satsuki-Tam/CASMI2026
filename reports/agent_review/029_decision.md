# 029 判断: 露出の特徴は「C1 既見に条件付けた学習構成」の三本(A 既存 / B 行構成だけ変更 / C B + fp_pos)で測る。negpool は外す。朝は 027 の診断三本のまま、束は提出しない

作成: 2026-10-26 04:20 JST(Claude Code)。依頼 `029_request.md`、回答 `029_codex.md`。

## 1. 採否
| 論点 | 判断 |
|---|---|
| 停止・隔離 | 妥当。negpool は今回の ranker 入力から外す(台帳そのものは正しい事実として診断用に残す;view に合わせて書き換えても「FPNet が使えた負例」を直すことにはならない)。 |
| fp_pos | 強い近道を実測(Codex、Spark): 未見 C1 の fit 分子 82 件のうち 72 件で、真が「正例学習に入っていない train 候補」の唯一の一件。全例ではないが強い。dev2 C1 は「正例未見だが参照のある C1」の評価としては意味があるので、**評価層として残す**(主指標に混ぜない場合も成績は残す;提出モデルなら dev2 C1 の保護も外さない)。 |
| 設計の名前 | 「漏洩のない設計」ではなく **「C1 既見に条件付けた学習構成」**(fp_pos = 0 で正しい参照を持つ真の C1 が学習から消え、逆の近道を作り得る)。 |

| trainer の内部表示 | `mrr_of` は消えた分子を 0 で補うので、`--c1_seen_only` / `--c2_drop_exposure` を使うと tune/eval の内部値は不適切 → 判定には使わない(登録評価器の保存予測で露出ごとに集計)。 |
| 朝の提出 | 027 の三本(T / COCONUT のみ / band26)を**旧 M2x の主順位のまま**(P_pool 0.336・P_Pc 0.046 と結び付けるため、作業用基準の変更を理由に FPNet・ranker を替えない)。束(ENS2×RK_new)は累積の C/C2 −0.0246 で不合格 → 提出しない(区間が 0 を含むことは点条件の合格ではない;C だけの例外や ε の変更はしない)。「全ての変更が C/C2 で止まる」とは一般化しない(ENS2 単体の拘束は G/C1)。 |

## 2. 事前登録(04:20、学習・評価の前): 三本の ranker
- 共通: full_rk の表(run_rk_p1 = fit、run_rk_eval、run_rk_c1)、identity 分割、teacher、候補、forward、rank_v4b の params、300 rounds、C1 ×3、`--c2_drop_exposure`(既見 identity の C2 行を除外)を固定。negpool は使わない。
  - **A** = 既存 rank_rk_fx(C1 は既見 + 未見、fp_pos なし)。
  - **B** = rank_rk_c1s: A + `--c1_seen_only`(C1 行を FPNet 既見の分子に限定)、fp_pos なし。
  - **C** = rank_rk_c1s_fp: B + `fp_pos`(`--feats v2_noice_exp --drop lib_nref in_train negpool`、full_rk 台帳)。モデルの特徴リストに negpool が無いことを確認する。
- 評価 1(full_rk の表、full_rk 台帳): A / B / C と RK_old。**C − B = fp_pos の効果**、B − A = 学習構成の変更の効果。
- 評価 2(採用先 = full_eval の表、full_eval 台帳): FE_A(= FE_new)/ FE_B / FE_C と M2x_fe(作業用基準)、M2x(累積の対照)。
- 主指標: 028 の J(0.5 × パネル C1 clean + 0.5 × dev2 C/D/E/F の C2 平均)。**判定**: FE_C(または FE_B)− M2x_fe の J の点推定 > 0、かつ作業用基準との差と M2x からの累積差の両方で dev2 の全保護層(C2 の C/D/E/F/G、C1 の C/E/F/G — 未見 C1 も含む)の点推定 ≥ −0.02。C − B が無効か保護を割るなら、露出は診断用に残して特徴としての採用は止める。混合比の探索はしない。
