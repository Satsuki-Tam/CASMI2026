## 採用する優先順位(Codex §1)

1. **W7 評価/提出の一致 + 固定した評価分母**: scenario(query / reference のマスク / 候補源)を作る段階で固定し、以後はラベルを見ない共通経路に渡す。評価器と提出パイプラインを別実装のまま揃えるのではなく、**提出パイプラインに評価用のマスク入力(除外する identity・取得行)を追加し、同じコードで評価する**方向にする。20〜50 分子の固定集合で機械的一致(台帳・候補鍵・出典・shortlist 所属・top-25・公式 RR)を確認する回帰テストを作る。
2. **W4 / W8**: molecule/view 台帳を先に固定し、参照が使えない分子も fallback で評価に残す。C1 は事前 eligible・usable・欠落数・usable 群の条件付き値を併記。「確実な複製」は「ピーク列一致群」、「疑い」は「近似重複を疑う群」と呼ぶ。adduct/極性の層(forward 対応正モード・負モードのみ・未対応 adduct・両極性)を molecule 単位で明示。
3. **W1 限定診断**: 公開パネル 250 分子(timsTOF・天然物)を FP / 参照検索 / prior / 融合規則の形の診断に限定利用(GL/ICE は shortlist・候補順からも外す。FPNet は fold-safe の除外監査済み)。locked とは呼ばない。装置差は「同一 identity の timsTOF query と他装置 query の組」で測定条件差として比較。A の中に NP score 等の事前固定した化学層を作る(閾値は開発側で固定)。A/B の差分や E4 の LB 差から装置差と化学差を分離推定しない。
4. **W9 学習融合**: source×identity×view×正解到達の件数を出してから A/B の総重みを揃える。bootstrap は identity 単位(全 view を一緒に)。単調制約は「無し」を対照に、FP/GL/ICE 代表スコア正・絶対質量誤差負の 1 変種だけ比較。bagging_by_query を検討。
5. **W5 標本拡大**: 開発側 各 500〜1,000、locked 側 初回 各 1,000(未開封)。+0.02 の検出に約 1,000〜1,200、+0.01 に約 4,000〜5,000 分子が目安。結果を見ながら追加しない。CI が 0 を含む差は「点推定は正だが未確定」。
6. **W6 負荷試験**(並行): 学習データから実測スペクトルを test 形式へ抽出(正解は別ファイル、query 取得と複製は参照から除外、C2 条件では正解参照と train 由来候補も除外)。代表 400 分子・候補窓が大きい分子・重い構造・短い予算の 4 試験。精度試験と負荷試験を分ける。
7. **W3 C3 代理**: 「DB holdout の C3 代理」として正解 identity を全候補源から除き、主指標は生成候補の公式 identity による exact recall@N と統合後の公式 MRR@25。純検索対照で recall=0 を先に確認。生成器の実装はまだ増やさない。

## 考え方の修正(Codex §2, §3, §10, §11)

- Class 比率は LB から一意に逆算できない。純検索型なら p3 ≤ 1 − S(上限のみ)。比率は一点推定せず感度分析の補助に使い、未知比率に合わせた重み調整を LB からしない。
- 「locked eval 最高を選ぶ」は locked を tune 集合にしてしまう。開封前に主候補と保険候補(失敗の仕方が異なるもの)と採否規則を固定し、locked では 1 回だけ比較。C1 の保護は非劣性幅 ε を事前に決める。LB は不整合の兆候を見る材料。
- 文書の表現: 「Public 約 130 分子」は推定、「採点 4.5 時間」は観測値、「±0.03」は区間幅の目安、「同一候補での比較」は融合規則の比較に限る。
- `b1_locked_eval.py`: 分母は凍結した台帳から、正解 SMILES が引けなければ停止、予測 CSV と分子別 RR を保存。
