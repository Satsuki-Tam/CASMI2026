## 私の読み(批判してほしい)
1. **開発の候補源の構成が隠しと違い、E 源を重くする融合を開発で落としている可能性**。根拠:
   - 102 の rrf_e1r_0.5(v8w7a + 人気度・候補源を使わない第 2 ranker を E 窓 = COCONUT / train / PubChemLite / BIO で、identity RRF α 0.5): **053 NP C2(COCONUT 正解)+0.039、G C1 +0.048、053 NP C1 +0.027** だが、D C2 −0.035、旧 B −0.047、E 源の外(PubChem のみ)の正解 −0.116、パネル C1 clean −0.035。主指標 +0.0021 で関門を通らなかった。人気度の低い正解では E の順位は一貫して得(パネル C1 の費用は「正解が最も人気」の層 66% に集中、Public の prior-only は 0.135)。
   - 隠しでは、E 窓の設計の E0 が P より +0.07。B 群(COCONUT・非 train)へ絞ると E0 の後段(2 本の融合 + forward)が +0.036 で、E0 の両単体は P と同等。PubChem のみの probe(M2x)は 0.046 と小さい。
   - 開発の f1/f2 は PubChem のみの正解が多い(C 層で約 4 割、D でも 1〜2 割;top-25 dump の集計なので厳密な率ではない)。
2. よって、**rrf_e1r_0.5 を Public で一回測ることは、候補(採用し得る方法)としても、構成の仮説の検証としても価値が高い**と考える。開発で設計・評価済み(10/28)で、Public を見て調整したものではない。読みは従来の規則(v8w7a 0.394 比 ≥ +0.008 暫定採用の候補 / −0.015〜+0.008 保留 / ≤ −0.015 点検)。実装は b1_pipeline への E 窓・e1r ranker・identity RRF の移植と parity が必要。
3. MIST は単独の第 2 エンジンにはならない。使うなら ranker の特徴として学習で統合(MSG と重なる学習行は除く)するか、DB の外の生成物(class 3)の選別。
4. class 3: 099 ではパネルで、test 側の親 + train の類縁で正解が生成された分子 54%、選別(gt3)が弱く MRR 0.068。MIST / GLACIER を選別に使い、class 3 の検出と挿入規則を組み直す案(上位 2 チームとの差を生み得る最大の手)。
