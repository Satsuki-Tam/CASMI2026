## 2. 次に調べる観測可能な証拠(Codex Q1、明日)
1. **候補ごとの FPNet 学習露出**(固定した split と checkpoint の台帳から、その候補 identity が FPNet の正例として学習されたか)。隠しテストでは train 構造の 80% が既見で FP が膨らむ一方、PubChem のみ・COCONUT のみの候補は常に未見 → 既見の train デコイが未見のクラス 2 の真を押し下げる仕組みがあり得る。既見/未見で FP の順位差・GL との一致を、C1-seen と C2-unseen の両方を含む学習行で検証する(query の真値を使わない特徴)。
2. **ライブラリ一致の取得条件**:query と参照の装置系列・adduct・CE、複数 query からの支持、独立取得数、参照数が多いほど偶然の最大類似が高くなる効果の補正(`lib_same` は adduct 一致で装置一致ではない)。
3. **候補単位の支持**:最大類似の train 候補が FP/GL でも支持されるか、Pc 側の最良候補との競り具合。一つの高類似候補で全 N を下げる方式は使わない。
- まず G/C2 の悪化例に上の証拠があるかを既存キャッシュで診断し、次の一対比較は一つに絞る。閾値を dev2 上で探し続けない。

## 3. 追記(20:30): 既見領域での w=0.5
- full_eval の表で、パネル C1(identity 既見)の Δ は +0.001 [+0.000, +0.001](fold-0 の未見では +0.006)。dev2(未見)の C1 は +0.006〜+0.048、C2 は −0.013〜−0.001。→ 降格の C1 利得は未見の C1 に限られる。隠しクラス 1 の既見率を q_seen とすると、C1 の効果は概ね (1 − q_seen) 倍に縮む。w=0.5 は「pool probe ≥ 0.374 でも、既見率が高ければ期待値がほぼ 0」なので、probe の結果に関わらず今日の比較提出の優先度は低い(候補としては記録に残す)。
