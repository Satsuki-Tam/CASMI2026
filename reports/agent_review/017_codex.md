# 017 レビュー: dev2 v2、fallback、G 型の追加学習

2026-10-25 09:01 JST。依頼の §4・§5 の追記を含めて確認した。

**結論は、4の既存段階出力の点検を先行・並行し、次の改善実験は2の「残り fold 0 の G 型72群」を使う。3はその結果を受けた追加比較とする。1の今回の `rank_v4b_nogl` は不採用でよい。** 4の完了待ちで2の準備を止める必要はない。§5の1,822群への拡張は有用な候補だが、既存の5モデルを振り分けるだけでは、現在の dev2/locked2 に対する厳密な未見評価は維持できない。

当面 fallback を保険のまま保持する判断には賛成する。ただし理由は「全体に置き換えられる候補が保護条件を満たしていない」ことであり、「隠しテストの未被覆29分子がパネル型だから」ではない。後者の根拠は公開ダミーの集計である。

**判断の前提となる数値の訂正**

**Q1: 順序、保護集合、許容損失**

1. **提案4の段階比較を利用する。** E/F/Gに加えてDも見る。候補窓→shortlist→各engine→BASE→PC mergeの真の所属・順位・ΔRR、GL被覆、選ばれた分岐を、同じquery/maskと全分子分母で記録する。既存016の列要件を引き継げばよい。E0の学習済みidentityは挙動診断として表示する。E0/B1の差をそのまま未見性能の差としない。
2. **次の学習比較は、現行 rank_v4b と「G72群を追加した版」の一対にする。** query、shortlist、特徴集合、hyperparameter、C1の重み、blend21とfallbackの規則をまず固定し、学習例の追加を検証する。追加identityのC1と対応するC2を両方含め、C2では真の参照を隠した上で、類似した誤候補の参照は残す。G/C1の回復とG/C2の誤昇格を一緒に評価する。
3. **提案3は、2で残った失敗に対して一つの条件付き案を比較する。** 「装置が違う／参照が少ないならτを下げる」という方向はまだ仮説。参照が少ないと証拠が弱くなる場合もある。候補ごとの実測可能な参照類似度・1位と2位のmargin・adduct/極性・装置情報を使い、C1救済件数だけでなくC2の誤昇格とΔRRを測る。真のクラス、真候補の参照数、真の層ラベルを推論時の分岐条件にしない。装置不明は独立した状態として扱う。

現在キュー済みのfit pool756群の特徴生成は、この比較に使える。しかし最初からE300/D300/F63/C21も全て混ぜると、G追加の効果と分布・重み変更が分離できない。最初はG72群だけを追加するのがよい。

**実装上の接続漏れがある。** Sparkの現行 `b1_rank_train.py:22` は `for s in ("A_timstof", "B_nplib")` と固定されている。C〜Gの特徴表を作り、`--runs` に足すだけでは学習されない。追加集合の明示的な読込と、実際に使ったidentity数・C1/C2群数・positiveを含む学習群数の出力が必要。756群や72群は選択時の数で、学習に有効な群数とは分ける。C1の3倍反復も独立標本数を3倍にはしない。

保護条件は次のように置く。

| 変更 | 主に確認する利得 | 保護する出力 |
|---|---|---|
| 2: G学習例の追加、fallback維持 | dev2 G/C1の **主出力blend21** | G/C2、C/DのC2、既存A/BのC2とC1評価集合、パネル両view。E/FとG・パネルのfallback出力は同一性を確認 |
| 将来1を再検討しfallbackを変更 | E/Fの各view、GのGL不足群 | パネルGL不足34群の両view、GのGL不足群の両view。GL被覆十分な分子の出力は構造的に同一であること |

損失幅は015と整合させ、まず **各保護対象のΔMRRに ε=0.02** を事前登録する。点推定が−0.02を超えて悪化していないことに加え、非劣性を宣言するには事前に決めた区間の下限が−0.02以上であることを求める。N=34や8では広い区間になりやすいが、それを理由に事後に幅を緩めない。「未確定」として既存候補を保持する。改善対象の利得で他の保護層の損失を相殺せず、同じidentityのC1/C2は独立標本として合算しない。locked2開封前に主比較・保護層・許容幅を固定する。

**2だけではfallbackそのものは改善しない。** GのGL不足8群では、C1の生rankerが0.875、保険＝blend21が0.0625だった。fallbackを保険に固定したままrankerを改善しても、この枝は変わらない。2ではまず被覆群で学習例不足の仮説を検証し、将来fallbackを変更するなら別の出力方針として保護試験を行う。

なお、Gとパネルを同程度の「本命の崩壊」と読むのも修正が必要。全分子のGL判定で分けるとG/C1被覆92群は learned 0.633、**blend21 0.646、lib 0.876**。パネルC1被覆216群は learned 0.746だが、**blend21 0.893、lib 0.914**まで回復している。Gの問題は現行主出力でも残る一方、パネルはblendによってかなり緩和されている。

「timsTOF C1の学習例が7分子」は今回は実学習入力でも確認できた。`run_v3_p1`のA/C1 fitが5群、`run_v3_eval`のA/C1 fitが2群で計7群、いずれも真がshortlist内。学習例不足は有力な仮説である。ただし、他ライブラリ＝必ず他装置ではない。`lib_same`はコード上、同じadductの参照類似度であって装置一致フラグでもない。装置、化学領域、参照数、極性、prior、query数は分離して調べる。「NP queryでは learned ≥ lib」はCで0.916<0.957、E/Fでもlibが上回るので一般化しない。

**Q2: fold 0 の72群を先に使う。1,822群の単純なfold振り分けは最終評価用には保留**

fit poolのCSV・manifestを確認した。Gの適格数は既存集合・p2除外後82群、層間割当て後72群。選択済みfitはG72/C21/F63/E300/D300の計756identity groupだった。初稿の333−200=133群ではなく、追記の72群が正しい。manifestはp2のdev2/locked2と既存集合の除外・交差ゼロを記録している。なおfit poolのmanifestの`split_method`にはdev2/locked2という選択器由来の名称が残るため、`fit_molecules.csv`の実採用数と用途を別に明記する。

fold対応は二つの問題を分けて考える必要がある。

- **各学習行自身に対するOOF:** fold kのqueryを `fpnet_foldk` で計算すれば、そのidentityをFPNetが学習済みという直接の楽観化は避けられる。fold 1〜4の分子を現在のfold0モデルで採点する案より適切。
- **外側のdev2/locked2に対する未見性:** 配布モデルkはfold kとパネルを除外しているが、k≠0ではfold 0を学習対象に含む。`fold_safe_fpnet/README.md` と `make_split.py:23` もその定義である。現在のdev2/locked2はfold 0なので、それを見たFPNetが生成した学習特徴を介してrankerへ情報が入り得る。rankerのfit行からdev2/locked2を除くだけでは、この経路は消えない。

従って「各行はOOFだから、locked2を含めて楽観化なし」とは承認しない。locked2の個票を開く必要はなく、上流モデルの学習集合との交差をメタデータで監査すればよい。厳密に拡張するなら、例えばfold kの追加fit用モデルは **fold 0とfold kの両方を除外**して学習するなど、外側の保留集合を全ての上流モデルから外す構成が必要になる。追加の学習コストとモデル分布差があるため、まず既存fold0モデルとG72群で仮説を検証する。既存5モデルによる1,822群版は、別名の探索実験としては有用だが、そのまま現在のlocked2を独立した最終性能確認とは呼べない。

校正と実装については、foldを拡張する段階で以下を満たす。

- `z_fp`は同じ候補集合に対する正の線形なスケール・オフセットの違いは消すが、順位・裾・誤りの違いは消さない。現行23特徴には**生の`fp`も残る**。窓内でのshortlist生成とshortlist内のz化は別なので、zだけで校正済みとしない。
- queryのidentity groupのfoldでモデルを選び、候補ごとのfoldで振り分けない。C1/C2のqueryは同じモデルを使う。チェックポイント・bit順序・前処理hash・fold・候補集合hashをキャッシュキーとmanifestに含める。
- FP上位候補、FP+prior候補、`fp_rank_window`、shortlist所属からその未見モデルで作り直す。見たモデルが選んだshortlistのFP列だけ交換してもOOFにはならない。候補変更に伴うforwardスコアの不足も監査する。
- fold別にstrict shortlist recall、FP-only MRR、raw FPの位置・尺度、候補内gap、最終ΔRRを出す。foldとquery装置・層の比率の違いも記録する。校正や重みの選択はfit/tune側で行い、locked2で調整しない。
- 提出時のFPNetをfold0のままにするなら、その条件の評価を主にする。複数foldの平均へ変更するなら候補生成から変わる別案であり、別途検証する。混合出所の学習表で良くなっただけで本番への一致を仮定しない。

**朝の資料から除くべき隠し分布の推論**

- 「隠しの被覆不足29/400」「Eは本番の約7%」「Fは0.5%、改善上限0.005」「隠しの未被覆29分子はパネル型」。いずれも公開ダミーからは分からない。
