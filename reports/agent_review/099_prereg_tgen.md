## 追記(02:52、結果未読;Codex 099)
- **A〜D は探索としてだけ読む**(採否の根拠にしない)。既知の不整合: (1) 親 = 他の分子の C2 view の 1 位で、C3 扱いの分子 i の正解の参照・analog が他の分子 j の予測に効き得る(単一の「世界」になっていない);(2) 親の公式 key と同じ構造に戻る無変化の生成物を除いていない(親が i の正解なら漏れになる);(3) test 親の sim 1.0 は実測でない;(4) --parents 0 でも train 親が 1 件残る(A の生成列は「親 0」の基準ではない)。
- 集計で、**正解が生成された C3 分子について、他の分子の 1 位(親)に正解と同じ公式 key があるか**を漏れの候補として別に数える。親数・生成物数・誤挿入数も併記。
- 30%(tgen_panel)は「真の親・真の質量を与えた oracle 到達率」と呼ぶ(予測親での上限ではない)。
- 確認へ進む場合の設計(Codex 099): バッチ単位の単一の世界(C2/C3 の identity の参照・analog を全 query から隠し、C3 の構造は全候補 DB・親資産から除く)で seed の予測を一度だけ作って凍結 → 親 = 他 query の 1 位のうち 1〜2 段の編集と質量が整合するもの、同極性のスペクトル類似で最大 10 → 生成物の最良 1 つを gt3 規則で 3 位に。DB 加点・GL gate・反復はしない。家族構造を持つ別の開発バッチ(パネル以外)で予測親の利得と C1/C2 費用を確かめてから Public の一枠(凍結 v7f + この一変更、対照 0.390)。
