## 1. 方策(`w135_selector.py` v2)
- **利得の式を訂正した**: `G_k = p̂/k − Σ_{r=k..min(25, |P|)} q_r · d_r`。d_r = 1/r − 1/(r+1)(r < 25)、d_25 = 1/25。旧式の (1 − p̂) は二重の条件付けなので外した。
  - k は 1 から min(3, |P| + 1) まで。同値なら小さい k。最大の G が 0 以下なら P を保持する。存在しない順位の損失は数えない。
  - これは**費用を粗く近似した一つの方策**であり、校正した厳密な期待効用ではない。
- **q_r の集計を訂正した**: 学習の世界の混合(等重み、world ごとの query 数で割る)として、bin ごとに数える。空の bin は、全 bin を合わせた q を使う。
  - π 0 / 0.3 / 0.6 の等重みは、学習用に固定したシナリオの混合である。隠しテストの π を推定したものではない。確認の結果を見て、混合比や q 表を変えない。
- **合成データの試験 PASS**(`test_w135_policy.py`): Codex の例(G = 0.05 / 0.10 / 0.10 → k = 2)、P が空、P の長さ 1・2、B が空、p̂ = 0、q 表の混合(90/91)、空 bin の代替。

## 2. 特徴と学習
- shortlist + B の順位の割合は、公式 key で重複を除いた集合で計算する。key が両方にあれば B の値を使う("B wins")。
- 空の窓(P の n_cand = 0 を確認した場合)では、lib_max・得点差・list の大きさを 0、P との差を 0 + フラグとする。空でない P で必要な値が欠ければ停止する。
- 標準化も、行の重み 1/|B| を使った重み付きの平均・分散にする。収束の警告、有限でない係数、片方の class しかない学習は停止する。
- 編集名は固定の表で 5 群に分ける。COOH_Me は酸化還元の群とする。未知の編集名は停止する。
- P の得点差は、GL の経路と fallback で尺度が違う。そのため gl_ok と一緒に入れる(確率差とは呼ばない)。MetFrag-lite が計算できないときの 0 は、欠損フラグではない(記録のみ)。
- 正例は、行の数と、独立な identity の数を分けて記録する。

## 3. 入力の検査(学習・適用の前に必ず通す)
- **world**: manifest の全ファイル、生成の meta(world manifest の hash、出力の hash、登録した引数)、生成物の GL の meta(ok / partial)。
- **被覆**: GL が使える query スペクトル(陽イオン、[M+H]+ / [M+Na]+)と生成物を持つ分子に、生成物の得点が一つも無ければ停止する。
- **B**: B 一覧と B_detail の key・hash が一致すること。重複が無く、50 以下で、P の top 25 と交わらないこと。生成物の runner の入力が、B の SMILES に重原子の条件を掛けたものと一致すること。
- **ID**: バッチ・P・分子表・生成の表の ID が一対一であること。
- **学習・適用の対象**: cv / fit は、設計の 18 世界だけにする。apply は、確認の 13 世界だけにする(学習の世界と重なれば停止)。
- **凍結**: `_model.json` と `_freeze.json` に、係数、標準化、q 表、特徴の定義、編集の表、学習入力の hash を記録する。既存のものは上書きしない。

## 4. 確認と関門(`w135_read_s2.py` v2)
- 確認の主集合は **598 query**(cF1 / cR1 は各 99、他は各 100)で、cU1 は含めない。

- **主**: π 0.3 の全 598 query の平均 Δ ≥ +0.02、かつ組の bootstrap の下限 > 0、かつ家族の bootstrap(補助)の下限 > 0。組の bootstrap では、各回の値を「引いた組の差の和 ÷ query 数」とする。独立な単位が 3 組だけなので探索的である。
- **費用**(それぞれ組の bootstrap の下限 ≥ −0.01、組はその全 query を保つ): C1 @ p30、C2 @ p30、C1 @ p0、C2 @ p0、全件 @ p0。π を合わせた値は記述だけにする。

- **reader の検算**:
  - 保存した P の一覧・新しい一覧・真から RR を計算し直す。
  - 不変条件: keep なら一覧と RR が不変。挿入なら x が P の top 25 に無く、DB 候補の相対順が保たれる。x が真なら RR = 1/k。
