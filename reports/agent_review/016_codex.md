**Q1：層定義、query library、サイズ。**

現行 `p2_select.py` は fold 0、既使用 identity group の除外、group単位の選択を行っている。dev2 の500行は500 groupで、MSGに属する別メンバーを持つ groupとの重複も今回の確認では0だった。方向はよい。一方、237,009は raw key 単位の母集団数で、そのまま選べる独立分子数ではない。選択manifestでは、既使用3,001 **key** が2,944 groupに対応している。

fold 0・既使用group除外後、層間への割当て前の適格 group は C=304、D=2,188、E=649、F=241、G=338。文書末尾の C=284／G=303／D=2,016は、先に他層へ割り当てた group を除いた段階の数である。候補数には、どの段階の除外後かを付けて保存する。

もっと重要なのは層の意味である。現在の dev2 に共通 selector(max8)を適用し、query と同極性の他ライブラリ参照をメタデータで数えると次のようになった。参照数は**重複除外・MAX_REF前の上限**であり、最終 usable 数ではない。

| 層（各N=100） | queryに正イオンあり | queryにH/Na正イオンあり | 同極性の他ライブラリ参照≥20 | 同参照0 |
|---|---:|---:|---:|---:|
| C_np_crosslib | 55 | 53 | **38** | 1 |
| D_np_single | 89 | 87 | 0 | **100** |
| E_np_negonly | 0 | 0 | 1 | 45 |
| F_np_uncovered | **94** | 0 | 0 | 69 |
| G_tims_crosslib | 93 | 92 | 6 | 1 |

したがって、現在の C 全体を「参照多数の C1」とは呼べず、F の6分子は実際の query に正イオンがない。分子の別ライブラリにあるスペクトルの属性と、提出へ渡す query の属性が混ざっている。

層は次の順で定めることを勧める。

- **C**：NP系の query library 候補を列挙し、query側を除いた後に、同極性・重複除外・参照上限を適用してなお十分な参照が残る条件を作る。総数20本ではなく、実際に使う参照数を基準にする。学習融合のC1弱点を調べる主群は native forward が使えるものとし、使えないものは副群として分ける。条件変更後に適格数を数え直し、100×2を満たすために黙って条件を緩めない。
- **G**：query library は `enveda-180` に固定する。ここでライブラリを乱択すると timsTOF query という目的が失われる。他ライブラリ参照の有無・同極性での可用性を記録し、少参照／多参照を分ける。
- **E/F**：選択後の query で判定する。Eは負イオンのみ、Fは正イオンがありH/Na正イオンがない条件。Fは NH4／一段の水脱離など現proxyの対象と、K／その他の未対応条件も区別する。他ライブラリの参照にHがあること自体は、queryがHを欠く条件を無効にしない。
- **D**：独立した真の参照がない群として残す。E/Fとの比較を明瞭にするなら、native forward が使える query を主な対照にする。参照がないのは「真の構造」であり、誤った候補への参照まで全部ないわけではない。

Cの query library は、**条件を満たすライブラリから、ライブラリ別の偏りを記録した固定seedの選択**を推奨する。最多スペクトル方式は query を豊富にする一方、残す参照を減らし、特定の大規模ライブラリへ偏らせる。最多方式を残す場合でも、残存参照の条件を先に満たし、同数時の library 名等の tie-break を固定する。現在の `per_lib.sort("n", descending=True)` だけでは同数時の順序が固定されていない。

「層間排他」の意味も明示する。現コードは選ばれた group の重複を防ぐが、層の条件自体は重なっている。例えばE/Fに選ばれなかった別の未被覆分子はC/Dへ入り得る。主ラベルを一つ付けても、参照数・query被覆・装置等の副ラベルを残す。複数query/viewを作る場合は同じ identity を同じ split に置き、bootstrap も identity 単位にする。

母集団について、二つの補足がある。

1. **「NPかつtimsTOFはパネル以外にない」は、現censusの定義では成立しない。** 自由分子には `in_nplib & has_timstof` が717 raw keyあり、参照≥20・複数libraryまで満たすものも310ある。fold 0・既使用除外後の C/G 交差は53 group。これは「NP系ライブラリへの収載」と「timsTOF測定」が共存するという意味で、天然物構造である証明ではない。既存のCOCONUT等の注釈と照合し、NPライブラリ所属・NP構造注釈・query装置を分ける。交差領域がないと決め付けて捨てない。
2. **Parquetがないことは、priorを選択前に付けられない理由にならない。** 既存処理は `pool_meta.parquet` の `pid` と `pool_lpmid.npy` 等を対応付けている。公式identityへ整列した注釈表を作る余地がある。`lpmid`、`lsid`、`lsynonyms`、合成指標`pop_public`を一律に「文献数」と呼ばない。欠損と真の0を分け、分位境界はdev側で固定する。事後層別から始めてもよいが、真がshortlistにある分子だけを集計して到達失敗を落とさない。

**Q2：Dは落とさず、まず各100を基本にする。**

「B_nplibと似た分布」と「同一identityの重複」は別であり、後者は既使用group除外で防ぐ。今回の D は参照0・native forwardありの対照を提供しており、E/Fの無forward条件との比較に意味がある。C2ではC/Gも真の参照を隠すが、query本数・参照への収載状況・prior・候補到達の分布まで同じにはならない。

現在の F は適格241 groupしかなく、dev2 150＋locked2 150の300 groupは確保できない。query基準へ定義を直せば母集団が変わる可能性はあるが、再集計前に各150を約束しない。なお5層×100は各split500、4層×150は各split600なので、Dを削る案は総量も20%増える。

各100は最初の層別診断には妥当。ただし100や150という数だけで±0.02を判別できるわけではない。例えば paired ΔRR の標準偏差が0.25なら、95%区間の半幅の目安は N=100で0.049、N=150で0.040。C1 usable が100未満ならさらに小さい標本になる。主要比較・保護する層・許容損失を開封前に決め、区間が広ければ未確定とする。

現在の選択は「seed5とseed6で別々に抽出」ではなく、**seed5の一つの並べ替えから先頭100をdev2、次100をlocked2**である。この方式でよいので文書を実装に合わせる。seedが違うだけでは非重複は保証されない。manifestには候補数の各段階、実際の採用数、主／副層、query library方針、除外CSV・fold・census・selectorのhashとgroup交差チェックを残す。除外ファイルの読込失敗を黙ってスキップしない。

すでに生成したファイルは暫定版として保存し、query基準の修正後に版を上げて選定・固定してよい。未開封の locked2 の成績を見ずに行う設計修正である。旧seed4の結果を新しい未使用評価として再利用しない。

**Q3：出力ポリシーとして評価する方針に賛成。ただし現行 B1 は未定義動作ではない。**

proxy offでGL被覆が閾値未満なら、現在の learned／blend の提出関数は**学習器を呼ばず保険を返す**。E/Fではまず `n_gl_finite`、coverage、`fallback_reason`、学習器呼出件数を記録し、本命と保険の順序付き出力が一致することを確認する。差0は「学習が無価値」ではなく、その分岐で使っていない結果である。生の ranker を強制適用する実験をするなら、提出ポリシーとは別の診断として表示する。

E0全体との比較はこの条件でも有用。候補源・参照・prior・生成・merge が異なるためである。未到達や空候補も全Nに残す。DをC1として二重に数えず、C1の適格／usable／不可用件数と条件付き分母を明示する。層全体の提出ポリシー評価から不可用分子を落とさない。

Fの実際にHを持たない、MSG非重複のqueryで行う**同じquery・候補の proxy on/off比較は、それ自体が有効な利用条件の検証**になる。実Hを隠す対応分子の対照は、代理化による情報損失や変換を切り分ける補助であり、Fの検証を始める必須の前置きにはしない。ただし対象adduct別に、proxy適用数・新たに採点できた数・RR差を記録する。proxyによって保険からlearned/blendへ移る効果も含めて評価する。MSG除外だけで E0 のrankerや別のforwardモデルまで未学習と見なさない。
