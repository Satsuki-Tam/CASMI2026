**Q1：placeboの計算と解釈**

指定CSVをset/view/moleculeで一対一に結合し、SparkのCPUで再計算しました。rankerはmainの差、生成はggt3−mainを使い、**両方とも同じfold-1/2 devの18層**、各層n≥20、閾値 −0.01としました。C1/C2は同じidentity groupを持つため、独立反転と、identity単位でまとめて反転する場合を分けています。

| 人工的なゼロ平均分布 | 4,000回中の保護不合格 | 比率 |
|---|---:|---:|
| rank_v8a：各query×viewで独立符号反転 | 3,682 | **0.9205** |
| rank_v8a：identity単位でC1/C2を同時反転 | 3,653 | **0.9133** |
| ggt3：各query×viewで独立符号反転 | 0 | 0/4,000 |
| ggt3：identity単位で同時反転 | 0 | 0/4,000 |
| rank_v8a：block×層内で平均を引き、identity単位でbootstrap | 3,586 | **0.8965** |

乱数seedは20261027です。最初の2行のMonte Carlo標準誤差は約0.0043〜0.0045で、依頼の0.923と同程度です。最後の行は符号対称性を強制しない別の感度分析で、元の予測対をそのまま置換する検定ではありません。結論として、**この差分分布・件数・保護層では、符号を対称化しても多数の点条件を通りにくい**という診断は支持します。18層のうちrankerのRR差が非ゼロなのは10層で、名目上の18個が全て有効な制約というわけでもありません。

解釈には、次の限定が必要です。

**1. 平均0という帰無だけから、符号反転の妥当性は導けません。** `d_i*=s_i |d_i|, s_i∈{−1,+1}` は、観測された絶対差と非ゼロ率を保つ対称なゼロ平均分布を作ります。その人工モデルとしては明確です。一方、現実の `E[d]=0` は、少数の大きな改善と多数の小さな悪化でも成立し、符号が絶対値と独立・等確率とは限りません。paired permutationとして厳密に解釈するには、モデルラベルを対の中で交換できる等の仮定が要ります。[SciPyのpaired permutationの帰無の説明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html)

従って「実際のゼロ効果モデル全般の偽棄却率0.923」ではなく、**「v8aの観測RR差の大きさに条件付けた、対称化nullでの保護棄却率」**と記載してください。観測RR差の足跡は、全候補リストの変更率やモデルの複雑さそのものでもありません。他のFPNet・rankerへ9割という値を一般化しません。

**2. 結合した保護判定では、同じidentityの関係を保ちます。** C1/C2を別々に反転すると依存関係を壊します。同じidentityには同じ符号を使い、元の**符号付き差のベクトル**へ掛けてください。各成分を先に絶対値にすると、同一分子で「C1改善・C2悪化」という関係まで失います。bootstrapでも両モデルを別々に再標本化せず、同じidentityの観測を一緒に引きます。[paired bootstrapの説明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)

**3. これは改善候補を落とす確率ではありません。** 真の効果0は、主指標の真の改善も0です。無害な候補を保護で落とす率と、役立つ候補を全選択手順で落とす率は別です。047の主指標条件、dev2とパネルの保護、候補選択・確認の段階も今回の18層の計算には含まれません。「0.48に必要な変更はほぼ採択できない」までは、この計算だけでは示せません。変更するqueryが多いことと、得られる純利得が大きいことも同義ではありません。

**4. 0/4,000は真の確率0の証明ではありません。** 独立なMonte Carlo反復で0件なら、そのシミュレーション確率の片側95%上限は概ね3/4,000=0.00075です。ggt3に現実の害がないという意味ではなく、今回の足跡を対称化した条件では点閾値を超えにくいという結果です。

**5. 0.923→0.117には複数の変更が混ざります。** 2ブロック18層から、dev2を加えた3ブロックを9層へpoolし、判定も点の −0.01から区間の0へ変えています。poolだけの効果、追加データの効果、判定の効果を分けるには、同じデータで比較する必要があります。0.117の手続きを同じ実装として完全再現したとはしませんが、値自体は不自然ではありません。例えば有効な片側2.5%検定が独立に5個なら、どれかが誤反応する率は約0.119です。この例は今回の検定間独立性を仮定するものではありません。

Holmは、有効な各検定のp値があれば、依存関係を許してfamily-wise errorを制御できます。しかし95%区間があるだけで、その区間を作った手続きのp値が妥当になったり、Holm後の実測誤率が自動的に保証されたりするわけではありません。また「両側95%区間の上限<0」は通常、片側2.5%水準に対応します。片側5%なのか両側95%なのかを登録で揃えてください。[R公式のHolmの説明](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/p.adjust.html)

**Q2：規則をどう作り直すか**

**方向としては、pool・主評価とstressの分離・新登録からの適用に賛成です。『有意な害なし＋主指標の点推定正』だけを最終的な保護合格にする部分を修正してください。**

提案のままだと、例えばΔ=−0.02、区間[−0.08,+0.04]の層を通します。大損の可能性が残るのに、検出力不足のため止まらないからです。逆にΔ=−0.001、区間[−0.002,−0.0002]なら、ごく小さい損失でも止めます。Holmを掛けると「害あり」と呼びにくくなるため、無害候補の誤棄却は減りますが、有害候補を見逃す側の確率も評価しなければなりません。

**実用上の許容損失 ε と、統計的な不確実性を分けます。** ε=0.01を引き継ぐ主保護なら、判定の境界は0でなく −0.01です。

| 区間と許容損失の関係 | 読み |
|---|---|
| 上限U < −ε | 許容範囲を超える害の証拠がある |
| 下限L > −ε | その信頼水準・推定条件で非劣性を支持する |
| L ≤ −ε ≤ U | 害とも保護合格とも確定しない |

これは、18層全てへ厳しい下限条件を新たに追加する提案ではありません。それでは候補を残しにくい問題が悪化します。**本番条件に対応する少数の主保護へ絞り、細かな層は損失の検出・機構の診断へ使う**ことが、049のregime見直しと統計的見直しの接点です。

初期の登録ひな型は、次を勧めます。

1. **主指標を一つ固定する。** C2改善実験ならNP C2のC/D/E/F等重み。C1とC2の総合指標を使うなら重みを結果前に固定し、隠しのclass比率の推定値とは呼ばない。改善として必要な大きさτも、単なる0超えでよいかを先に決める。
2. **主保護を少数にする。** 例えば採用時のモデル露出に対応したNP C1の集約と、NP C2の集約。既存の −0.01 はまずこの集約に対する実用marginとして検討できる。個々のcheckpoint・query取得の条件が違うものを、件数を増やす目的だけで混ぜない。
3. **開発では未確定を即不合格にしない。** 主指標の点推定が目的に沿い、許容範囲を超える害の明確な証拠がなければ、候補として残す判断は可能。ただし、上の区間が未確定なら「保護合格」とは記録しない。大きく動く候補を比較へ進めるための入口はここで広げる。
4. **確認では一つに固定した候補を測る。** 主指標の差と区間、主保護の非劣性、全stress層を報告する。主保護が未確定なら、追加データ待ちか、リスクを明示した限定比較かを登録時に決める。未確定を機械的な害判定にも自動昇格にも変換しない。
5. **細かな層とGは別枠で監視する。** 害の検出へHolmを使うなら、family・片側の方向・実用marginを指定する。Gはchemistryが異なるstressですが、参照を過信する失敗がNPでも起こり得るため、049のとおり「隠しと無関係」とはしない。そこで強い損失が出た場合の機構点検や適用範囲の制限を残す。

「全ての主保護で非劣性を示す宣言」と、「どれか一層の害を探す多重検定」は異なる設計です。後者のHolmを前者へ機械的に移さず、何の誤りを制御するかを明示してください。また、数十候補を同じ開発集合で試すことによる選択の楽観性は、9層のHolmでは解消しません。未使用確認を一回だけ使う方針は維持します。

**poolの定義も登録事項です。** fold-1/2は各fold-safe FPNet、dev2はfull_evalという異なるblockです。一対差は各block内で計算し、等重み等の固定重みで統合して、block別の差も残します。これは固定した複数条件での平均効果であって、全てが同じ母集団から得たn=300とは限りません。C1のusable数でblockの重みが勝手に変わらないようにします。パネルのidentity既見C1は、未見C1をpoolした群とは別です。ensembleの露出条件の注意も049のままです。

**次に校正するのは、ゼロ効果だけでなく選択手順全体の振る舞いです。** 同じコホート・同じ候補の足跡で、旧点条件、poolした点条件、有意な害によるscreen、少数主保護の三状態判定を比較します。最低限、(a)全効果0、(b)主指標に小〜中の正・主保護0、(c)主指標が正でも一つの主保護に −0.02〜−0.04 の害、(d)block間で逆符号、を含めます。無害候補の棄却率だけでなく、改善候補を確認へ残せる率と、有害候補を通す率を並べてください。これらの数値は校正用の例で、採用marginを結果後に最適化するためのものではありません。

今回の追補を踏まえ、049で示した「主評価に近い条件へ役割を整理する」に加え、**多数の層の点差で即停止する運用を、候補選択の主軸から外すことを支持します。** 同時に、有意でない損失を安全と扱う逆方向の誤りを避けます。rank_v8aの旧不合格は変えず、学習重みの対照と新しい評価条件を先に固定してから、未開封の確認を使う順序がよいです。
