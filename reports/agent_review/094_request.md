# 094 相談: B 群(COCONUT・非 train)の並べ方を E0 並みにするための「自前の pool 経路」の設計(明日の BASE_B probe と合わせて)

作成: 2026-10-27 22:22 JST(Claude Code)。読み取り専用で構いません。利用者から「このまま金圏に入れるか」と問われ、正直に「小さな改善の積み上げでは 0.41〜0.43 が現実的、金には E0 との差の大部分を占める B 群(Public の B probe で E0 0.259 vs B1 0.204)を埋める構造的な変更が要る」と答えた。その道筋の設計を相談したい。

## 背景
- B 群の probe は 10/26(M2x 0.354)0.202 → 10/27(0.379)0.204 とほぼ不変 = これまでの改善(full_eval FPNet、analog)は B 群に届いていない。今夜の v8w7a も主にクラス 1(G C1 +0.18)と NP 全般の改善。
- E0 の engine 1: pool(train ∪ COCONUT)±10 ppm の窓(中央値 75)を shortlist で絞らず全部、同じ engine での模擬(c1/c2/c3)で学習した 160 特徴の LambdaRank で採点(人気度の特徴なし、top-60 内で弱い人気度の再順位)。B1: PubChem を含む 1 億件の窓を FP と人気度で約 250 に絞り、全候補を一つの ranker で並べる。
- 090: 人気度を弱めるだけでは開発で悪化(仮説は支持されず)。

## 提案(段階)
1. **明日の BASE_B probe**(E0 engine 1 の BASE 先頭 25 → B に絞る)の読み(1028 plan に固定済み)で、B 優位が engine 1 由来か後段由来かを見る。
2. engine 1 由来なら、**B 経路の専用 ranker** を自前で作る: 学習 = COCONUT 正解の群(np061_f3pool 等、GL あり)で、各群の候補を pool(T ∪ B)または B だけに制限し、特徴は制限した集合の中で計算(z・順位が pool 内の相対になる)。評価 = 開発の「B probe 相当」(COCONUT 正解の分子で、B 候補の中の真の順位の MRR、未到達は 0)を v7f の B 内順位と比べる。最初は既存の表と特徴(v2_noice_ana)だけで、窓の作り直しはしない。
3. 専用 ranker が B 内順位を大きく上げるなら、最終リストへの統合(E0 型: pool 経路のリストを主にして PubChem 候補を固定枠で挿入 / 全体リストと identity 単位の RRF / B 候補の部分だけ並べ替え)を、strict C2・C1 保護つきで比較する。
4. 窓の作り直し(pool 窓を shortlist に関係なく全部採点、生成物も同じ ranker で)は、2・3 で効果が見えてから。
