# 032 判断: 推論時の entropy による重複参照の除外を外した full_eval の一変更を「診断提出」として今日一回。提出前に発火例での実装確認と C2 の向きの確認を行う

作成: 2026-10-26 07:40 JST(Claude Code)。依頼 `032_request.md`(+ 追記)、回答 `032_codex.md`。

## 1. 採否
| 論点 | 判断 |
|---|---|
| 主張の訂正 | 「隠しでは損失しか生まない」は撤回: 独立取得でも高類似の参照が正解構造のものとは限らない(公式 identity の違う異性体、識別力の弱い強い断片、参照ラベルの誤り)。実データでも dev2 E の 4 分子で非正解候補の参照が疑い重複(標準 0.915〜0.950 → keepdup 0.9953〜0.9999)。C2/C3 の真には公開参照が無いので、そこで復活する参照は誤候補のもの。「隠しの query は全て新規取得で公開 library に同一取得は無い」も公式の保存本文では確認できない(出典を分けて記録)。(a) の完全一致も cleaned peaks の allclose なので「独立取得なら絶対に発火しない」とは置かない。 |
| 局所の件数(特徴生成の疑い重複、mask・cap の前) | 真の参照に疑いあり: パネル 0、C 20、D 0、E 16、F 3、G 0(分子数);非正解候補に疑いあり: E 4 分子(10 参照)だけ。 |
| 提出 | 0.370 を出した full_eval の kernel / dataset 版から、**推論時の entropy による除外だけを無効**にする(`--dup_sim 1.01`、完全一致の判定は維持、manifest に値とコード版を記録)。学習・正式評価表・source mask・ranker・出力式は固定、朝の T/B/band の結果でこの条件を変えない。 |
| 実装確認 | パネル 16 は発火しない(確認済み: 既定値で候補 dump が完全一致、1.01 でも除外 0)ので不十分 → **C/E/F の真側の疑い例と E の非正解側 4 分子**を加えて、完全一致は両版で除外、entropy のみの除外は新版で通過、閾値未満・mode/precursor 条件外は不変、cap が掛かるときに意図した参照が残る、を確認。「最終出力が変わるのは発火分子だけ」は GL の実行順・時間予算・fallback のため本番全体の不変条件にしない。 |
| C2 の向き | 既存の正式表は上書きせず、同じ固定 C2 台帳・真の全参照除外・外部候補資格のまま新しい参照規則を当てた診断版で、少なくとも E の 4 分子の候補・特徴・順位を追う。採用判断の前には C2 全分母の paired MRR を出す(発火例だけの平均を保護にしない)。C1 の取得未確認の利得は「未測定」、C2 は「測定可能」と分けて記録。 |
| 件数の記録 | entropy のみで落ちていた参照数、mask / cap 後に復活した参照・公式候補 key・分子数、library、shortlist の出入り、GL 被覆・fallback・所要時間(pipeline の stage stats に n_dup_exact / n_dup_sim を追加済み)。隠しの再実行の記録は取得できないので、**隠しでの発火件数は不明**とし、可視ダミーの件数から説明しない。 |

## 2. Public の読み(提出前に固定)
| 観測 | 判断 |
|---|---|
| 大きめの正(例 +0.02 以上) | 新基準の候補にする価値はある(参照の復活・shortlist・GL 配分・fallback を含む変更全体の差で、C1 の独立参照の量の推定ではない;実装の未解決や C2 の保護未達を Public で帳消しにしない) |
| 小さい正 / ほぼ同点 | 基準へ昇格しない(非発火とも断定しない) |
| 負 | 作業用基準 0.370 を保持、大きめの負なら採用しない(原因を類縁体と断定しない) |
- ±0.02 は注意の幅で、採否や有意差の境界ではない。閾値を刻む探索に広げない。

## 3. 実装確認の結果(07:40、`spark_dup_checks.sh` (2)、dev2 で疑い重複のある 43 分子 = C 20・E 20・F 3、pipeline 0.98 vs 1.01、forward なし)

|---|---|---|---|---|---|
| C1 | 125 / 126 | 91 / 0 | 43 | (なし) | 参照類似が変わった候補 43、shortlist の出入り 0 |
