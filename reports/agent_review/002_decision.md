# 002 判断記録(Claude Code、2026-10-24 04:30 JST)

## 採用する点

1. **本日は E0 のみ提出し、設定変更だけの E3 は提出しない。** 理由は「利益を支持する比較がまだ無い」こと。E2b の比較は z(FP)+z(GL) の補完性を示したが、V18 の融合規則(z(融合順位スコア)+z(GL))の最適性や TOPN/window 拡張を検証したものではない。
2. **結論の表現を修正する。** 「指紋との桁違い」→「同じ候補集合では FP と GL は同程度で、融合が強い」。「V18 の等重みが正しい」→「V18 の融合規則は未検証」。「汚染のない」→「MSG の元の InChIKey14 で除外した集合(公式鍵での再確認が必要、少なくとも 2 件の漏れあり)」。「pool から正解除外 = Class 3」→「主 pool からの除外シナリオ(PubChem 等には正解が残る)」。E2(パネル)の分母は 246 分子(順方向モデルの入力は 212 分子)、`only` 設定は lam=100 であり基準スコアを完全には除いていない。
3. **E2b の評価上の欠陥を修正して再構築する(v2)。** (a) MSG 除外を公式スコアラー鍵で行う(MSG の SMILES を正準化)。(b) セット A の入力スペクトルを enveda-180(timsTOF)に限定し、セット B も選定元ライブラリに限定する。入力スペクトルの装置・出典を記録する。(c) 候補の重複排除と正解判定を公式鍵で行う(窓内候補は raw 鍵で絞った後、選抜候補 + 正解を正準化して併合)。(d) 候補窓の中性質量に電子質量補正を一貫適用する。(e) `truth_in_pubchem` → `truth_in_retrieval_window` に改名し、強制追加の有無で層別する。(f) ランダム基準は解析式 H_min(n,25)/n で出す。(g) `abs(precursor_error_ppm)<10` はラベル由来の品質条件であることを明記し、除外率を出典別に記録する(テスト自体にも整合性クリーニングがあるため選定条件としては残す)。
4. **E2b の位置づけ。** 「分子式と正解候補の存在を与えた異性体識別パネル」として採用し、Class 2 の端から端までの評価には使わない。実運用に近い評価(実測プリカーサ+アダクトからの候補取得、正解分子式なし、強制追加なし、参照スペクトル除外)を別層として整備する。今回の 400 分子は設定比較に使った開発集合として記録し、採用判断には未使用の分子集合を確保する。
5. **投資順序を Codex 案に変更する。** (1) 評価・来歴の修正と凍結 → (2) 学習コード付きの既存 FPNet と凍結 GL による基準系(入賞要件のためだけの 5 fold 再学習は不要、自前変更は 1 fold で比較)→ (3) 実際の shortlist 上で候補・特徴・欠損を揃え、小さな固定融合を基準に OOF 特徴を集めてから LambdaRank → (4) GL 適応は小規模試行で実現可能性を確認(上流 ms-pred の `train_joint.py` / `train_contr_joint.py`、MAGMa の hdf5、README は 24GB GPU ×2 を記載。checkpoint 読み込み・教師データ作成・少数例での勾配更新・保存再読込・Kaggle 側での推論一致までを最初の範囲とする)→ (5) 生成経路(下位挿入も既存候補を置換しうるため無条件に安全とは扱わない)。
6. **E0 の報告表現。** smoke は `scoring_rerun=false`、処理 12 分子、placeholder 388 行、経過 1,329 秒。「400 行の CSV を書けた」と「400 分子を推論できた」を区別する。スコアは API で採点状態が取れるまで推定値で埋めない。
7. **ユーザーへの見通し。** 「数日で 0.480」とは断定せず、到達点を測定可能な形(独立した分子で再現する改善、学習来歴を提示できる基準系、GL 適応の実測可能性)で置く。

修正版(公式鍵での MSG 除外・候補同一性・正解判定、セット A を timsTOF スペクトルのみに限定、電子補正の一貫適用、強制追加群の層別)を 4 セットで再実行した(`experiments/e2_forward/v2/results_*.json`)。
