## 4. 自前ベースライン B1 の設計(レビュー対象)

公開系譜の「pool と PubChem を別経路で順位付けし slot で差し込む」構造は踏襲せず、統一した候補表を一つのモデルで順位付けする。

| 層 | 内容 |
|---|---|
| 候補取得 | 10 アダクトから中性質量(電子補正)。pool(学習構造 + COCONUT)と PubChem tier の ±10 ppm 窓を合併、公式鍵で同一性、出典フラグ |
| Class 1 信号 | 学習ライブラリのスペクトルとのエントロピー類似度(候補ごとの最大、分子全体の lib_max)。装置差(hidden は timsTOF、天然物参照は Orbitrap/QTOF)を特徴として持たせる |
| Class 2 信号 | fold-safe FPNet(5 fold、学習コードあり)の f·z、GLACIER / ICEBERG の全体 z 和、文献 prior(popularity データセット) |
| 統合 | 候補ごとの特徴(類似度、FP、GL、ICE、prior、出典、質量誤差、スペクトル数、CE 有無、アダクト)を LambdaRank で順位付け。Class 1/2 の切替をゲートではなく学習に任せる |
| 学習データ | identity fold の OOF で「正解の参照スペクトルがある」(Class 1 模擬: 同一分子の他ライブラリ/他装置スペクトルを参照として残す)と「隠す」(Class 2 模擬)の両条件を生成 |
| 検証 | 未使用 identity group から新規に凍結(v1/v2/P1 の開発分子を除外)、strict 指標、公式スコアラー |
| 段階 | B1-最小版(固定 z 和 + 単純な切替、2〜3 日で 1 回提出)→ LambdaRank → 順方向モデルの timsTOF 適応 → Class 3 |

## 5. 質問

1. B1 の設計で欠けている部品・順序の誤りはあるか。特に (a) Class 1 模擬の作り方(参照に残すスペクトルの装置・ライブラリの条件)、(b) 統一 LambdaRank が slot 方式に対して持つリスク(Class 1 の取りこぼし)、(c) 9 時間予算での PubChem 窓採点(Kaggle 4 CPU で 1 分子 15 秒想定)。
2. B1-最小版の「固定 z 和 + 切替」の具体形として、「lib_max が閾値以上なら類似度順、未満なら z(FP)+2z(GL)+z(ICE)+λ·prior」から始めるのは妥当か。閾値と λ は tune 群で決める。
3. E4 v3 の LB 結果をどう読むか。+0.01 以上なら「P1 の代理指標は LB に転移する」、±0.005 以内なら「slot と後段で希釈」、負なら「hidden の class 構成または転移の失敗」。この読み方で見落としはあるか。
4. P1 の開発集合(A/B 600 分子)は重み選定に使ったため、B1 の tune/eval には使わない。新規凍結の規模(各 300?)と、Class 1 模擬のための条件(他ライブラリに参照がある分子)の選び方に助言があれば。
