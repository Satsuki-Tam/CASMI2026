## 3. 今日以降の計画(案)— レビューを求める

002 で合意した順序に沿って、最初の 2〜3 日の具体案:

**P1. 評価層の整備(本日)**
- E2b v2 を「Class 2 異性体パネル(分子式既知・正解あり)」として凍結。今後の採用判断用に、未使用の分子で同条件の第 2 パネル(別 seed)を作る。
- 端から端の Class 2 評価層: 実測プリカーサ + アダクト(enveda-180 fold 0・公開 NP ライブラリの MSG 非収載分子、参照スペクトル除外)から PubChem tier + COCONUT の ±10 ppm 窓で候補を取得し、分子式を与えず、正解を強制追加せず、「質量窓 → shortlist → 再ランキング → top-25」の各段で正解到達率を測る。候補数は実運用規模(数千)。
- 公式スコアラーでの照合(`src/metric.py`)を評価関数に組み込む。

**P2. 基準系(2〜3 日)**: 学習コード付き部品のみで構成した自前パイプラインの最小版。
- 候補: COCONUT + 学習構造(主 pool)+ PubChem tier(ゲート付き)。
- スコア: fold-safe FPNet(5 fold、学習コードあり)の f·z、凍結 GLACIER/ICEBERG(MSG 版、許可済み)のエントロピー類似度、ライブラリ検索(エントロピー類似度)、COCONUT/LOTUS 所属などの天然物向け prior、PubChem 文献数(単一 knob)。
- 融合: まず小さな固定融合(z 和)を基準にし、OOF 特徴が揃った段階で LambdaRank。
- 目的: 公開系譜に依存せず入賞要件を満たす基準を持ち、各部品の限界利得を同じ候補行で測れる状態にする。
- 疑問: 公開系譜(0.464)に対して、この最小基準系は当初どの程度下がると見るべきか。どの部品を最初に入れるべきか。

**P3. 学習融合の材料**: P1 の端から端の評価層で、分子ごとの shortlist 上に FP・GL・ICE・ライブラリ類似度・アナログ・prior・欠損フラグを揃えた表を作り、identity fold 単位の OOF で LambdaRank を学習。

**P4. GLACIER 適応の小規模試行(並行、1 日)**: 上流 ms-pred(bundle の commit 708148c2)を取得し、対応 checkpoint の読み込み、enveda-180 timsTOF スペクトルでの教師データ作成(MAGMa 断片木が必要か確認)、少数例での勾配更新・保存・再読込、Kaggle bundle の runner での推論一致までを確認。GPU は RTX 5070 Ti 16 GB。

**P5. Class 3**: P1 の評価層ができてから。
