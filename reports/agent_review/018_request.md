## 3. 仮説: 差 0.13 の本質は「shortlist 到達」と「学習済みモデルの記憶」
- E0 は学習済み FPNet により窓内の真をほぼ常に上位 60 に置く(0.953)。B1 は未見 FPNet で shortlist 到達 0.755(D 層では 0.42)。
- 隠しテストのクラス 1(train に参照がある分子)に対しては、train 全体で学習したモデルの記憶は**正当な強み**(規則上、公開データ・公開コードで学習したモデルは許容)。B1 の提出 FPNet(fold 0 を除く 80% で学習)は、fold 0 相当のクラス 1 分子で不利。クラス 2/3 には無関係(未見)。パネル(NP・timsTOF・train 内分子)で公開 main リストが B1 固定を両 view で ≈0.1 上回った事実とも整合(公開モデルはパネルを学習済み、B1 の fold-safe モデルはパネル除外)。
- 含意: 開発評価は **C1 = 学習済みモデル可(隠しクラス 1 の代理)、C2 = fold-safe(クラス 2/3 の代理)** に分けるべきで、現在の C1 評価(未見 FPNet)はクラス 1 の性能を過小に見せ、本番では E0 に負ける主因になっている可能性がある。

## 4. 検証案(意見を求める)
1. **決定実験(安い)**: パネル 250 の C1 view で、B1 の FPNet を fold-0 から train 全体で学習した `fpnet_full1.pt`(公開資産、学習コード公開;B1 のローダで読めるか確認中)に差し替えて特徴表を作り直し、shortlist 到達・固定・learned・blend21 を比較する。W7 の fold 0 分子に fold-1 モデル(fold 0 を学習に含む)を適用した「学習済み対照」も同様に(C2 代理での記憶の効き)。
2. それが大きければ、提出パイプラインの FPNet を train 全体学習(公開 full1、または自前 `train_fpnet.py` で全 train + パネル)に切り替える候補を作る。評価は (a) パネル C1(記憶込み、隠しクラス 1 の代理)、(b) dev2/locked2 C2(fold-safe、クラス 2/3 の代理)の両方で保護。ranker の学習表は未見 FP 特徴で作られているので、学習済み FP の分布(真の FP 順位が高い)に対する ranker の挙動も確認が必要。
3. shortlist 到達の改善(未見側): k_fpp 拡大は dev2 で損だったので、FP 以外の到達経路(参照類似の上位、prior 上位、GL 事前スクリーニング)を層別に評価。
