**Q1: 筋はよい。ただし、E0 の +0.055 の原因を特定する実験とは分ける。**

異なる事前学習・構造予測器から来る D は、既存 F の誤りを補う候補である。E0 の fzD_gap / fzABD_gap の gain はその仮説を支えるが、相関した特徴の gain から D 単独の寄与量は読めない。今回の「凍結した埋め込み＋新しい MLP」は、E0 の FP 予測へ fine-tune した view とも別のモデルである。成功すれば B1 に有効な表現が見つかったという証拠、失敗すればこの凍結 head・学習量・融合方式が不十分という証拠になる。いずれも E0 の D 成分の効果を直接推定しない。

また、085 の +0.0067 は当該 dev・現在の shortlist での上限であり、隠しの採用損失の上限ではない。E0/B1 には窓・候補資産・shortlist 到達の差も残る。パネルの窓到達 100% は隠し timsTOF で質量誤差の問題が小さい可能性を支えるが、候補集合が同じことまでは示さない。「B 内順位を優先して試す」は賛成、「残差は FP だけ」とはまだ言えない。EXT の B 12 分子や MSG の監査済み対象も、精密な全体平均には小さいが、到達・順位の症例比較には使える。「同じ分子で比較可能なのは隠しだけ」は強すぎる。

**事前学習について、089 の注意書きに重要な追記が必要。** 公式 API は `embedding_model.ckpt` を `ContrastiveHead` としてロードする。論文の埋め込みモデルには、約 25,000 MoNA スペクトル・約 5,500 構造を使った、同一分子を近づける追加学習がある。これは無ラベル GeMS の既視感とは別の、分子同一性による教師あり露出である。今回の `embedding_model_state_dict.pt` がどの checkpoint から変換されたかを既存 manifest/hash と対応させるまでは、「backbone は無ラベル学習のみ」と記述しない。[公式 API](https://github.com/pluskal-lab/DreaMS/blob/main/dreams/api.py)、[原論文の contrastive fine-tuning](https://www.nature.com/articles/s41587-025-02663-3)

ホストが MoNA fine-tuning を説明した質問に対して DreaMS の使用を許可したことは、保存済みの公式回答で確認できる。したがって問題は使用可否より、**ローカルの未見評価という呼び方**にある。新しい head の fold 除外だけでは backbone まで identity 未見にはならない。可能なら実際の MoNA fine-tuning identity との重複を `seen / unseen / unknown` で付記する。別ライブラリ名でも MoNA/GNPS 等の再配布があり得るので、「MoNA query を除いた」だけでは未見を保証しない。[主催者回答](https://www.kaggle.com/competitions/enveda-CASMI26-molecule-id-mass-spectra/discussion/745604)

論文の GeMS の選別は positive mode、当該 contrastive fine-tuning は [M+H]+ を対象としている。adduct・極性を head に足しても、凍結表現の負イオン等への適合を保証しない。positive/negative、H/Na/その他、GL 被覆の有無を先に分けて報告する。近縁 scaffold が fold をまたぐことも、identity の混入とは区別し、既存の最大 train Tanimoto 等で利得が近縁群だけに集中していないかを見る。最初から全 scaffold 再学習を要求する必要はない。[原論文のデータ選別・学習条件](https://www.nature.com/articles/s41587-025-02663-3)

**Q2: 089 の COCO 主層に一本化し、対照を合わせた上で両 fold の +0.01 を維持する。**

088 の「NP 系 library 6種」と、089 の「真が COCONUT、pool src=2/3」は異なる母集団である。B 経路の化学を対象にする目的には後者が分かりやすいので、**089 を主解析、library 別を診断**とする。結果を見てどちらか有利な方で通す運用にはしない。COCONUT 所属も、library 名も、隠しの未知 NP と同じ分布を保証するものではない。

結果を読む前の追記案は次のとおり。

1. **固定するもの**：fold1/2、各 identity の query 選択、候補集合、tie-break、学習30,000 step、seed、head 構成を固定する。主融合は `z(F_current) + z(D)` の一本。`w=0.5`、D 単独、F 単スペクトル平均は診断だけとし、主判定不合格を救済しない。z の母集合は同一の full pool window とし、分散0・欠測時の扱いも固定する。
2. **単位と集計**：COCO identity ごとに RR@25 差を作る。複数 query を評価するなら identity 内で先に固定重みで平均し、スペクトル数の多い identity を重くしない。各 fold の平均差を出し、結合 CI は fold 内で identity を再標本化する paired bootstrap 2,000回で計算する。結合時の重みは結果前に固定する。
3. **進行条件**：両 fold とも平均差が **+0.01以上**、かつ結合した差の **95% CI 下限 > 0**。これは保守的な資源配分基準としてよい。fold ごとの学習集合は重なっているため、独立した二つの学習再現実験が成功したとは言わない。CI も固定したモデルに対する query 変動を表し、学習 seed の変動までは含まない。
4. **併記するもの**：fold・identity数・query数・選択スペクトル数、library/極性/adduct、COCO/非COCO、学習重複の状態、窓サイズ、F/D/E の RR、F が外れ E が救った数とその逆を保存する。同じ分子式だけに絞った順位も補助診断にすると、式の識別と異性体識別のどちらに効いたかを分けられる。真の式を使ったこの補助評価を推論の候補選別には使わない。
5. **欠測を有利に使わない**：D の埋め込み欠測時は E を F に戻す等の方策を事前固定する。両モデルが成功した行だけの条件付き比較と、事前に列挙した評価対象全体の比較を区別する。README の 68%/33% は真が必ず窓内にある、polarity ごとに merge した molecule–polarity 評価なので、今回の絶対値と直接差し引かない。

主対照の変更や query 修正は、**089 の追記として理由と結果未読の状態を残す**。既に成績を読んでいた場合も評価の不具合は直すべきだが、その再評価は開発として扱い、当初の事前登録に合格したと遡って書き換えない。

段(b)は、まず固定 shortlist・固定 v7f・固定した係数一本で D の加算だけを比較するのがよい。現行主出力には既に F の情報が ranker 等を介して入っているため、(a) の +0.01 がそのまま主出力へ乗るとは限らない。053 dev / f1dev / f2dev で確認し、panel C1 clean、dev2 の未見 C1/C2、非COCOを従来どおり保護する。C1 は学習済み identity・query 未見、C2 は head が identity 未見、という評価条件を維持する。panel を丸ごと除外した head の C1 評価と、独立ライブラリ spectra を残した本番 head の評価は別の条件として記録する。

その後に ranker 特徴化を一変更として試す。学習行の D は当該 identity を除外した head から作り、検証行に5本平均を使わない。その他4本は検証 identity を学習しているためである。fold0/3/4 の追加学習は、この段に進んでからでよい。shortlist に D を加えて到達を変える実験はさらに別にする。固定 shortlist の再順位実験では、既に候補から落ちた真は救えない。

**Q3: 第5枠なら BASE_B を先に。T は二枠を確保してから一対で行う。**

10/28 の4比較は維持し、追加一枠が使える場合は、今回の +0.055 と対応する凍結 E0 の **engine1 BASE_B** を第一候補にする。既存の final E0_B=0.259 と比較でき、engine1 単体の方策で B の優位を既に再現できるかを調べられる。T の片側だけを追加しても現在版の一対は完成しない。旧 B1 の T=0.160 を別版の対照へ流用しない。

ここでは probe の順序が重要である。主比較は、公式 identity の重複処理を揃えた **`BASE の先頭25 → 固定した B 判定で抽出、補充なし`** とする。既存 final_B は最終25件から B を抽出したものだからである。BASE は60件、ENG は40件を持つので、先に B を抽出してから25件にすると、順位器に加えて採用枠も変えた別の方策になる。その目的なら明記し、同じ方策の比較とは呼ばない。T/B/Pc の所属判定・資産・query・E0 版も055以来の定義に揃える。

- BASE_B が final_B に近ければ「engine1 の出力だけでも、この B probe 得点をおおむね再現する」。DreaMS が原因、融合が無用、全体スコアも同じ、とは言えない。
- BASE_B が低ければ「後段の候補追加・融合・forward・rank-2 等をまとめた方策が B probe を改善している」。直ちに engine2 単体の寄与とせず、次に ENG_B を見る。
- BASE_B が高ければ「後段の方策が B probe では損失を生んでいる」。T/Pc の利得との交換や、異なる top25 採用も残る。

BASE/ENG/final の ordered keys、候補数、B 件数、fallback/時間切れを保存すれば、Public の集約得点以上の機構診断につながる。一つの Public 差に統計的確証や部品ごとの加法分解を与えない。対応する凍結版の準備・実装確認が間に合わなければ第5枠は空けてよい。これは今後の提出案であり、今回のレビュー中の提出は行わない。
