## 採用(B1 の設計に反映)

1. **統一候補表 + 明示した shortlist + 固定融合 + 公式提出順**を先に完成させ、同じ表で LambdaRank を比較する。重い GL/ICE は shortlist のみ(P1 の K=100、FP ∪ FP+prior ∪ 参照検索上位の和集合)。→ `b1_features.py` で実装済み(shortlist に参照検索上位 20 を明示的に残す)。
2. **Class 1 模擬**: 参照は別 acquisition(原則として別ライブラリ)。同じ分子の C1/C2 を同じ split に置き、bootstrap は identity group 単位。参照のある分子だけで C2 全体を偏らせない(C1 専用集合 `eval_c1` を別に作る。A は 7/300 しか他ライブラリ参照が無いため C1 評価は NP 系で行う)。複製(同一元スペクトルの再配布)の除去は USI/accession が無いため、ピーク hash による同一判定を次段で入れる(未実装、記録)。
3. **FPNet は fold 0 固定**で評価(5 モデル平均は最終推論候補、独立評価値には載せない)。
4. **最小版の固定規則**: S = z(FP) + w_GL z(GL) + w_ICE z(ICE) + λ prior を基準に、参照一致が信頼条件(類似度・次点との差・一致ピーク数)を満たすときだけ参照候補を優先。初期値は w_GL=1, w_ICE=1, λ=0.15 を基準、w_GL=2 と λ=0 を tune で比較。欠損は z=0 でなく、モデル項を外した事前定義の fallback。
5. **特徴**: 参照類似度の生値、別 identity の首位と次点の差、一致ピーク数、複数 query 間の一致、生 FP/forward スコア、欠損・対応 adduct フラグを残す(一致ピーク数・次点差は次段で追加)。
6. **評価集合**: 現在の P1 600 分子 = fit/診断。新規 tune 300(A/B 各 150)と locked eval 600(A/B 各 300)を別 identity group で確保。eval の結果は設定確定前に見ない。C1 部分集合は 100〜150 を目標。N=300 で検出できる差は約 ±0.025〜0.03 であることを明記。
7. **9 時間予算**: Kaggle 実環境で層別した 30〜50 分子を流して起動〜最終 CSV を実測。forward は参照一致の弱い分子を優先し、予算不足なら FP+prior に戻す fallback を実験評価にも入れる。
8. **E4 の読み方**: LB 差の大きさで原因を割り当てない。「P1 では strict 差 A +0.049、B +0.042。LB は改善方向を仮説とし増分は予測しない」と記録し、結果は処置適用範囲と被覆を伴う一回の観測として読む。
9. **E4 の被覆条件**: 50% 被覆の融合は P1 で測った条件ではない → 両モデルが全候補で有限値のときだけ新融合、それ以外は E0 規則(v5)。v3/v4 は提出しない。追加スコアは PC の並べ替えだけに使う(004 判断記録の「後段と共有」は v3 以降の分離構成へ変更済みと追記)。
