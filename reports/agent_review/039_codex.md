**Q2：prior-onlyの情報はある。ただし0.45の仮定と、LAMへの自動分岐は使わない。**

実装は `np.lexsort((-FP, -pop))` でpriorを第一キー、FPを同点処理にするものです。kernelはfull_eval、`k_fpp=200`、`k_pop=50`、`--no_forward`、`EMIT=probe_prior`を指定しています。forwardスコアはこの出力に不要なので、省略する設計自体は適切です。提出対象の凍結版について、0.379版と同じ候補key集合になることと、この順位規則との一致を記録してください。

解釈には三つの条件が付きます。

- shortlistはFP・参照類似・FPとpriorの合成・prior上位枠で選ばれています。従って、これはスペクトル情報を一切使わないpriorの性能ではありません。forwardを省いても、候補選択にはquery情報が入っています。
- `pop` はSID/文献/同義語由来の値にNP・source・LOTUS等の項を加えた混合スコアです。化合物の一般的な「知名度」そのものではありません。
- MRR@25は「最も知られた真の割合」ではありません。例えばP_pop=0.25は、全分子で真が4位という場合にも成立します。top-1率や絶対的な人気分布は別の量です。

候補内に真がある割合をqとすると、概念的には

`P_pop = q × E[prior順位のRR@25 | 真がshortlist内]`

です。qは今回までのMRRや所属oracleから0.45と特定できません。P_pop=0.10でも、q=0.20で候補内MRR=0.50の場合と、q=0.80で候補内MRR=0.125の場合があります。前者を「真が低人気」とは読めません。過去の較正で置いたzero成分の補数や、得点のある分子の割合も、そのまま候補到達率ではありません。

さらに、prior-onlyが高くても、融合器が既に同じ情報を利用していればLAMを下げた方がよい場合があります。低くても、FP/GLが曖昧な一部をpriorが補う場合があります。**単独方策の良さと、現在の融合にpriorを足す/弱める効果は別です。** LAMを0.15にしても、rankerのprior特徴、shortlistのprior項・上位枠は残るため、「priorを切った比較」でもありません。

結果前の読みは、次のように修正することを勧めます。

| 観測 | 読んでよいこと・次の扱い |
|---|---|
| P_pop ≥ 0.25 | この固定shortlistと順位規則の組合せで高めの得点が得られる。prior自体の追加情報量は未測定なので、LAM 0.5が最適、あるいは弱める案を今後出さない、とは決めない。 |
| P_pop ≤ 0.10 | この方策のMRRは低い。候補到達、候補内のprior順位、同点、source/型のずれのどれが原因かは未分解。LAM 0.15を自動的にPublic候補にせず、局所の分解・仮説更新までにする。 |
| その間 | 数値をそのまま診断結果として残す。q=0.45で割って人気の高い真/低い真の比率へ変換しない。 |

0.25/0.10を残すなら、仮定から導かれた境界ではなく、診断上の便宜的な目安と明記します。prior-onlyが本命に迫る/上回るようなら、単純な順位方策に対して複雑な融合の上積みが小さいことを点検する材料になります。しかし本命が正解する分子との重なりは、二つの総得点からは分かりません。

枠2として一度測る価値はありますが、**「低ければλを下げて提出するための判定器」としては不十分**です。LAMの適否への最短の観測は、その係数だけを変えた本命との直接比較ですが、現在は041の条件を満たしていません。今回のprobeをその条件の代わりにしないでください。新しいローカル仮説に進む場合も、同じPublicで閾値やLAMを順に選び、その選択後の得点を独立な検証と数えないことが必要です。

**Q3：041の帯別集計に修正が必要です。ただし不変更という結論は維持されます。**

`/tmp/prior_cmp.py` の `pct()` は `in_short_c2` だけで真の存在と人気百分位を計算しています。実際のC2出力ではさらに `in_tier | in_coconut | in_train_c2` の資格を適用するため、**生のshortlistにはあるが、C2候補としては消える真**が「真がリスト内」の集計に混じります。

041の1,682行を再現すると、**281行がこの不適格な真を含む行**でした。実際のC2候補に真が残る行だけに絞り、既存の百分位帯の定義を変えずに点推定を計算すると、LAM 0.15 − 0.5は次のようになります。

| 人気百分位の帯 | 041のn / 差 | C2資格適用後のn / 差 |
|---|---:|---:|
| 低い帯 | 562 / +0.0163 | **291 / +0.0315** |
| 中央の帯 | 209 / +0.0104 | 207 / +0.0105 |
| 高い帯 | 911 / −0.0201 | **903 / −0.0203** |

低い帯については「+0.02未満だった」という説明を訂正してください。修正後はその点条件を満たします。ただし、高い帯の損失が−0.01以内という条件は依然満たさないので、041の「不変更・Public比較を提案しない」という判断は変わりません。全分母の性能を報告する際には、候補に真が無い行を除かず0点として残します。除外するのは、あくまで「到達した真の人気別」という条件付き分析です。

併せて次を直すのがよいです。

- 資格適用後の上表1,401行は1,061個のmoleculeで、dev2の同じ分子をfull_eval/fold-0で反復しています。pooled区間を出すならidentity/groupでまとめた再標本化とし、採用先full_evalと他checkpointの感度表も分けます。1,401独立分子の区間とはしません。
- 現在の百分位は「真よりpriorが厳密に低いデコイの割合」です。同点が多いと真が同率首位でも低い帯に入ることがあります。実際のprobe順位はFP同点処理を含むので、同率の割合と、実際の並べ方での順位を別に記録してください。帯も等人数のtercileではなく、百分位の三つの区間です。単独候補で百分位が未定義の行も別扱いにします。
- 「パネルの真は全件で最多prior」という説明も強すぎます。確認したfull_evalパネルC1ではprior最大が真なのは **174/250** でした。`pop_only_local.md` のD/E等の値は、候補資格を反映した再計算と一致しており、この別表全体を誤りとするものではありません。
- 真の人気百分位は正解を使う分析量です。「低い帯だけLAMを下げる」を、そのまま推論規則にはできません。将来条件付きのpriorを考えるなら、queryから分かるFP/GL/analogとpriorの不一致等に基づく、別の検証が必要です。

**採用先の既見C1の損失も確認してください。** `prior_compare.md` のfamily欄はfold-0パネルを示していますが、full_evalパネルの表も保存されています。clean202でv7fのLAM 0.5から変更した差を再集計すると、LAM 0.15は **−0.01814（改善3、悪化18）**、0.25は **−0.00695（改善3、悪化12）** でした。

従って、v7f+LAM 0.15のclean202は、現在のanaw0.5に対して約 **−0.03033** となります。037b/038で記録したv7fの−0.0122より損失が増えるので、その例外の自動延長では扱えません。prior-onlyが低いという一つの総得点は、この既見C1の損失や人気の高いC2の損失を解消する証拠にはなりません。
