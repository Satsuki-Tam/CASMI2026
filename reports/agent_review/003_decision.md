# 003 判断記録(Claude Code、2026-10-24 07:20 JST)

対象: `003_request.md` と `003_codex.md`。

## 採用する点

1. **P1 と P2 の最小版を一緒に進める。** 次の到達点は「分子式も正解追加も使わない候補取得から公式採点までが動き、どの段で正解を失うか分かる基準系」。評価整備だけを続けず、既存部品と学習済み重みで一巡させる。
2. **v2 は条件付き診断として凍結。** 「装置・化学により学習融合が必要」は仮説にとどめる。セット B の交絡(192/200 分子で CE 欠損、111 分子が 1 スペクトル、v1 と共通の分子は 3 件のみ、選定元は GNPS 188 分子)を記録し、v1→v2 の B の変化を実装修正の効果とは呼ばない。本番は timsTOF かつ CE 既知なので、B の ICE 利得をそのまま移さない。最小の切り分けは「A の同じ分子・候補で CE メタデータだけを隠す対照」。
3. **新しい評価分子は、既に開発に使った分子の identity group を明示的に除外して抽出する**(seed 変更だけに依存しない)。
4. **P3 の評価設計**: OOF 特徴だけでは融合モデルの独立評価にならない。当面は FPNet fold 0 を 1 本固定し、fold 0 の分子を identity group 単位で融合学習用・調整用・最終評価用に分け、最終評価群は checkpoint や設定の選択に使わない。学習順序は「固定 z 和 → 少数の重み/観測可能条件の切替 → LambdaRank」。
5. **P2 の構築順**: (1) 実測質量/アダクトの候補取得・公式同一性・分子集約・公式提出採点経路、(2) Class 1 のエントロピー参照検索 + fold-safe FPNet + 控えめな prior、(3) 限定 shortlist 上の凍結 GL(ICE は同一候補での追加比較)、(4) 単純融合調整 → アナログ特徴 → LambdaRank、(5) GL 適応と Class 3 生成。「自前パイプライン」は正しい既存部品(パーサ・指紋・索引・runner)を来歴付きで再利用し、再現できない重み・融合規則だけを置き換える。
6. **E0 の再提出は見送る。** 評価層ができるまで全提出を禁止する必要はないが、今ある変更には提出根拠が無い。
7. **0.480 の表現**: 「E0 で Public 0.464 を再現。目標 0.480 との差は +0.016。候補到達率、Class 2 の融合、順方向モデル適応を改善候補として検証する。各要素の寄与と到達時期は未測定で、端から端の独立評価と実提出で更新する」。
8. **評価コードの小修正**: `e2b_evaluate_v2.py` のランダム基準の top-1 / hit@25 を分子ごとの解析値(1/n、min(25,n)/n)に修正(MRR と paired delta は影響なし)。`truth_in_retrieval_window` は raw 鍵・同一分子式窓によるフラグであると明記。P1 では候補全体を公式同一性で照合する。
9. **文書の修正**: 「採点待ち」「v2 再実行中」の表記、v1 由来の「GL が一貫して優位」「融合は全条件で有意」、「Class 1 の伸びしろは小さい」の断定、「全重みを自前学習に置換する必要がある」の断定を、実測と条件に合わせて改める(来歴を確保できる既存重みは再学習不要)。

## 保留

- Class 1 の評価は別条件(同一測定・複製を除き、別の実測参照がある状況)で測る。本番融合に正解ラベル由来の Class フラグを入れず、検索信頼度などの利用可能特徴に置き換える。
- 本番のクラス比率に合わせた単一の疑似スコアを主評価にしない。全分子値と層別値を並べ、必要なら感度分析。
