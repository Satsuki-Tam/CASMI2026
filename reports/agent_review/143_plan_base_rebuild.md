## 何を作るか(我々の実装・我々の検証。E0 の重み・行・LB で合わせた定数は持ち込まない)
1. **第二エンジン E2**:
   - 窓: query の ±10 ppm の、COCONUT・train・PubChemLite / BIO(E key v2)の全構造。shortlist で切らない。
   - 特徴: P と重ならない証拠を中心にする。fold-safe FPNet の f.z と窓内の順位、ライブラリの類似度(view の mask)、analog propagation、MetFrag-lite、ppm。人気度・source・GL は使わない(P との誤りの相関を下げるため)。
   - 学習器: 点ごとの LightGBM binary(固定のパラメタ)。
   - 学習行: fold 3 / 4 の train の identity で、C1 / C2 を模擬した行(W135 の world の mask の仕組み、または b1_features の view)。
2. **融合 F**: P と E2 の identity 単位の RRF。2 本の top-1 が割れるときは、E2 の top-1 を 2 位へ置くヘッジを加える。定数は、開発で決める規則か、事前に固定した値にする(E0 の LB で合わせた α 0.6 / offset 3 はそのまま使わない)。
3. **検証**:
   - 開発: np053 / f1 / f2 の C1・C2 view と、W135 の世界(class の混合 π 0 / 0.3)。
   - Public: 段階ごとに一回ずつ確認する(1 日 5 枠を計画的に使う)。
4. **その上に**: class 3 の生成(W135)と A3(GL の識別)を、融合の中の部品として後から載せる。
