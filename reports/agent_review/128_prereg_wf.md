# 128 事前登録(候補の探索 → 確認;結果の前、2026-10-29、Codex 127 Q2 の設計)— 同じ分子式の中だけの並べ替え(GL / MIST)

## 候補(2 系統、混ぜない)
- 対象: 凍結した主リスト P(v8w7a、gen_eval2fd --v7f --parents 0、既存の開発表と保存済み GLACIER)。各 (set, view, molecule) の view リスト全体で、候補を中性分子式 F(RDKit CalcMolFormula、代表 SMILES)ごとにまとめる。
- 並べ替え: **F の候補が P で占めていた位置だけ**へ、F 内を h = 1/(10 + r_P,F) + α/(10 + r_X,F) の降順(同点は P 順)で詰め直す。式をまたぐ位置は動かさない。P の 1 位も同じ式の中では入れ替わり得る。X が有限な候補が 2 未満の式群は P のまま、X 欠損の候補は F 内の最後(同点は P 順)。K = 10 固定、α ∈ {0, 0.5, 2}(α = 0 は「変えない」= P)。この後に global な融合はかけない。
  - **WF-GL**: X = 保存済みの GL(P が使っているのと同じ GLACIER の得点。新しい証拠ではなく、使い方の変更)。
  - **WF-MIST**: X = MIST(aug、step 430,965)の cos。実装 experiments/mist/mist_score.py:query は b1_features と同じ選択(最大 8)のうち [M+H]+ / [M+Na]+、候補ごとの式、質量整合 max(20 ppm, 5 mDa)の組だけ、(スペクトル, 式, 付加体)ごとに一回予測、候補 FP は Morgan 半径 2・4096 bit、cos を対応 query で平均。
- 実装(gen_eval2fd.py の `--wf` / `--wf_mist`、既定はオフで main は不変): 候補集合不変・式の位置不変・α = 0 で P を再現・P 自身の順位を X に渡すと P を再現、を各行で assert。上限 wf_ub(真をその式の最も早い位置へ上げた RR、25 位以内のみ)と、真の式内順位(P、X の悲観的な同点)を記録。

## 読み(結果の前に固定)
1. **上限での選別**(ラベルを使う): fold 1 の主指標の配置で wf_ub − main の全件平均が **+0.005 未満**なら、この位置保存の方策では関門に届かないので、その系統を止める(X の能力の否定ではない)。
2. **fold 1 での選択**(f1dev / np053f1dev / c1bankdev、111 と同じ関門): 系統ごとに α ∈ {0.5, 2} を評価。関門 = 主指標(1/4 NP_H C2 + 1/4 NP_N C2 + 1/2 D C2、全件の分母、対応の無い分子は差 0)≥ +0.005 かつ 95% 下限 > 0、block A(NP_H / NP_N C2)と block D の下限 ≥ −0.01、保護の下限 ≥ −0.01(旧 B = f1dev C/D/E/F C2 等重み、G C1 = f1dev、NP C1 = np053f1dev H/N 等重み、c1dev の C1 全件)。bootstrap 4000、seed は 111 と同じ割当。通過した中で主指標の最大の (系統, α) を **一つ**だけ選ぶ(同点は WF-GL、次に小さい α)。通過なし → 候補なし。
3. **fold 2 の安定性**(f2dev / np053f2dev、既使用なので独立確認とは呼ばない): 選んだ (系統, α) の主指標が正であることを記録。負なら確認へ進まない。
4. **確認(一候補、一回)**: 未開封の np096_conf093(NP_H 200 + NP_N 200、fold 0)と np102_d0conf(D 286、fold 0)を 1/2 ずつ(平均 ≥ +0.005 かつ下限 > 0、各ブロックの下限 ≥ −0.01)、C1 の費用は c1cost098(E 型 100、fold 0、下限 ≥ −0.01)。開封の前に台帳で未使用・重複・用途を確認し(得点は見ない)、表と GL・MIST の得点を作る。G 型の新しい C1 が無い限界は残す。確認を見て系統・α・候補を選び直さない。
5. **Public**(確認を通った場合のみ、利用者の許可のもと一回): v8w7a(0.394)比 ≥ +0.008 暫定採用の候補 / −0.015〜+0.008 保留 / ≤ −0.015 点検(これまでの読みの規則と同じ)。

## 露出と限界
- MIST の学習(MSG 実スペクトル + GLACIER の模擬)と開発集合: 開発集合は選択時に not_msg。評価の前に MSG の公式 key / alias(data/external/massspecgym/msg_scorer_keys.txt)で照合し直して件数を記録する。aug の模擬構造(約 400 万)への露出は不明として記録する(実スペクトル未見・構造は模擬で既見の可能性)。
- GLACIER も MSG で学習済み。パネル(236 / 250 が MSG)は既知 identity 側の補助の保護に留める。
- この方策は P の式推定の誤り・窓の未到達は直せない。式をまたぐ並べ替え・第 2 ranker・global 融合は後の別登録。
- f1 / f2 は何度も使った開発集合。

## v2(Codex 128 を反映、結果の前 — v1 の評価は途中で止め、出力は未読のまま diag/r128_v1_unread/ に隔離)
- **式**: 評価器と MIST の採点で共通の定義(experiments/b1_baseline/wf_common.neutral_formula)。解析不能・正味の電荷 ≠ 0・同位体指定の候補は**どの式群にも入れず、位置を固定**。
- **X の欠損**: 各式群で X が有限な候補だけを、その候補たちが P で占める位置へ並べ直す。r_P と r_X はその有限な部分集合の中で数える。有限な候補が 2 未満なら不変。**X の無い候補の位置は不変**(assert を追加)。v1 の「欠損は群の最後」は採らない(採点できたこと自体を票にしないため)。
- **MIST の表の照合**: 特徴表の行(molecule, official_key, smiles)と MIST の行を one-to-one で照合し、status(ok / no_qrows / no_mist_adduct / no_formula / mass_mismatch / no_fp)を検査(ok なら有限な cos と n_q > 0、それ以外は欠損)。照合できない・未知の status・重複は停止。採点は v2 の scorer(experiments/mist/scores_v2:選択した分子への限定を常に、no_query の理由の分割、コード・checkpoint・MIST commit・入出力の hash を manifest に)。質量条件は 128 で固定した max(20 ppm × 測定値, 5 mDa)(理論 m/z = 式の単同位体質量 + 付加体の質量、測定 = precursor − enveda-180 の陽イオンの電子補正)。窓の 10 ppm とは別の、採点に使う query の条件。
- **上限**: wf_ub は X の被覆を無視した保守的な上限(全ての真について、その式の最も早い位置)。+0.005 未満なら両系統を止める。以上でも「この上限では除外されない」とだけ読む。被覆を考えた上限 wf_ub_<x> は記述。
- **fold 1 の保護を追加**: c1dev の**陽イオン C1(C1_pos_* 層)の全件**を別の保護(下限 ≥ −0.01)にする(今回の介入は陽イオンでしか動かないため、陰イオンの差 0 で薄めない)。
- **fold 2**: `--pick` は fold 1 の選択(diag/x128v2_selection.json)と一致する場合だけ受け付ける。条件 = 主指標 > 0 **かつ** block A / D、旧 B、G C1、NP C1 の下限 ≥ −0.01。記述は選んだ一つだけを出す。
- **確認の C1 費用**: c1cost098(陰イオンのみ、介入が動かない)をやめ、**c1bank_f1/c1conf の陽イオンの群**(名簿上 366 群)を、未開封・他候補への未使用・開発との非重複を台帳で確かめた上でこの一候補の C1 費用の確認へ予約する。実際の c1_usable と、並べ替えが動く query・式群の被覆は開封前に数える。C2 は np096_conf093(run_np096_f0conf)+ np102_d0conf(run_np102_d0conf)を H/4 + N/4 + D/2 の重みで。
- **MIST の前処理**: CASMI では割当済みの表が無いので、生ピークからの統合 → 部分式割当(MIST の関数)を**この実験の前処理条件として固定**する。検査 C2(同じ割当表からの詰め直しが公式の compact と完全一致するか、生ピーク経路との差の分類、予測の差の分布)を記録する。C の完全一致を「合格」と書き換えるのではなく、条件の違いとして残す。CASMI の成績を見て割当の規則を選ばない。

## v3(Codex 129 を反映、結果の前 — v2 の評価は MIST の入力が変わるため途中で止め、未読のまま隔離)
- **MIST の入力**: 強度の丸めを公式と同じ順に(float32 → float16)。この変更で MIST の得点を作り直す(experiments/mist/scores_v3、scorer v3:--threads、空の窓は分子台帳の n_shortlist = 0 のときだけ受理、全空でも列を持つ表)。
- **評価器の入力検査**: 非 ok の行は cos が NaN かつ n_q = 0(±inf も拒否)、ok は有限な cos が [0, 1]、n_q は 1〜8 の整数、key / status の null を拒否。記述に、真の P 順位を**同じ有限な部分集合の中で**数えた wf_rP_<x>_form と、どれかの真が動ける行 wf_moveany_<x> を追加。
- **入力の記録と照合**: job の開始時に、評価器・wf_common・ranker・MIST の manifest と得点表・選択 CSV・特徴表・分子台帳・保存済み GL・P の基準の sha256 を diag/x128v3_inputs.json に記録し、終了時に変化が無いことを確認。行の manifest は、その run が書いたファイルだけを明示して列挙(+ 入力記録)。
- **読み取り v3**(x128v3_summary.py): 行の manifest = 期待するファイルの集合(欠け・余り・重複を拒否)、入力記録の全ファイルを再 hash、評価器・wf_common・ranker・MIST の scorer / adapter / commit / checkpoint が **128_registered_versions.json** と一致、**MIST の検査 C2 が C2_PASS**(登録した adapter・checkpoint について)でなければ停止、fold 2 の記述は選んだ系統だけ、表の列は fold 2 では stability、選択の JSON に入力記録と reader の hash・登録した版を残す。
- **確認の C1 費用(明記)**: c1bank_f1/c1conf の陽イオン群のうち c1_usable の群で、選んだ候補 − P の **95% 下限 ≥ −0.01 を必要条件**にする(名簿 366 と実際の usable 件数は開封前に数える)。C2 は H/4 + N/4 + D/2 のまま。
- **検査 C2 の合否**(check_c2.py v2): 同じ割当表からの詰め直しが**全 N 行で全項目一致**、変換の失敗 0(唯一の正規化 = 末尾の電荷記号の除去、該当 ID を列挙)、名前の一意・TSV との対応・指紋の形・CLS の位置・padding の確認 → C2_PASS / C2_FAIL を JSON と終了コードに。生ピーク経路との差は ID ごとに分類(同一 / 同点の順序だけ / count・root・intensity・formula・ion・peak_type の flag / 失敗)して CSV に、予測の差は符号付き(平均・分位・改善 / 悪化 / 不変)と絶対値、分類ごと、最大の ID。
