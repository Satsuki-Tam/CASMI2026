- 無条件の Pc 降格(`blend21 − w·1[Pc]`、Pc = train でも COCONUT でもない = PubChem tier のみ;inf = 全順位列から除く = pool probe の手元版)と E0 型の固定枠(Pc を 4,8,…,20 位 / 2,4,…,10 位だけに置く): `docs/validation_design.md` 末尾の 3 表(`diag/pcd_report.md`)。
  - C1 は全層で上がる(G C1: w=1 +0.074、w=2 +0.165、inf +0.257;パネル C1 +0.006〜+0.016)。C2 は Pc の真を持つ層で下がる(D C2: w=0.5 −0.018 [−0.037, −0.003] … inf −0.191;G C2: −0.012 … −0.637)。パネル C2(真の 249/250 が COCONUT)は w=4 で +0.011。どの w も dev2 の C2 保護(点・下限 ≥ −0.02)を全層では満たさない。固定枠は C2 の損失が大きい(G C2 slot4 −0.473)。
- 条件付き降格(train 候補の最大ライブラリ類似 ≥ θ のときだけ N または Pc を w 下げる;格子は結果前に固定 `spark_gd_eval.sh`):train 候補の最大類似は view をよく分ける(≥ 0.7 の割合: G C1 0.91 vs C2 0.31、パネル 0.84 vs 0.27、C 0.81 vs 0.14)。結果は 2 つ目の表(gdN0.7w1: G C1 +0.072 / C2 −0.025、パネル C1 +0.013 / C2 −0.015、D C2 −0.017;gdP0.7w2: G C1 +0.142 / C2 −0.044、パネル C2 +0.001)。損失は小さくなるが消えない(G C2 は合成 timsTOF の類縁体デコイでゲートが誤って開く、D は C1 view が無い層)。
- 解釈: B1 の主出力は「C1 の真(train 構造、他装置の参照と中程度の類似)」と「C2 の真(参照なし、FP/GL/prior が良い)」の間で、開発集合の混合比に合わせた妥協点にある。どちらに寄せても片方が下がり、どの点が良いかは隠しテストの混合比(と COCONUT 所属)で決まる。

## 2. 質問
**Q1** この開発結果から「混合比次第のトレードオフで、観測可能なライブラリ一致だけでは解消しない」と読むのは妥当か。見落としている観測可能な証拠(例: train 候補の参照数・装置の種類・adduct/極性の一致、FP の既見・未見の兆候、COCONUT の NP らしさ)はあるか。
**Q2** Public probe(P_pool、P_Pc)が出た後の採否の決め方。私案:
  1. 事前に混合比のシナリオ格子(p1 = 0.2/0.35/0.5、クラス 2 の真の COCONUT 所属 = パネル型 / dev2 型)を置き、各変種の期待 Δ を層別の開発結果から計算する(結果を見る前に格子と層の対応を固定)。
  2. P_pool − 0.354 の符号と大きさ(≥ +0.02 / ±0.02 / ≤ −0.02)で、シナリオ格子のうち整合する部分を選び、その部分で期待 Δ が正の変種だけを候補にする。
  3. 候補は一つだけ Public で比較(一変更)。dev2 の保護は「点推定 ≥ −0.02」を必須、下限は未確定として記録(022 の 2 行目と同じ扱い)。
  この手順は Public への過学習(130 分子)と、開発集合の混合比への過学習の両方を避けられているか。
**Q3** 隠しクラス 1 の約 80% が FPNet 既見の領域にあるなら(仮定)、既見の FP は C1 の真を強く押すので、開発集合(未見)で測ったクラス間の取り違えは過大評価かもしれない(full_eval のパネル C1 では T のみ − main が +0.020 と、未見 fold-0 の +0.035 より小さい)。降格の採否にこの差をどう織り込むべきか。full_rk の ranker 比較(23:00 頃)をこの判断に待つべきか。
