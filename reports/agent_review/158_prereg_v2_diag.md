## 1. v2 の候補表 U2(fh2 builder、データの準備)
- U2(q) = P の上位 25 ∪ E2 の上位 25(全窓の E2 の順位で)∪ B(最大 50)。official key で一つにまとめる。最大 100 枠。枠の順: P の順位 → E2 だけの候補を E2 の順位で → B だけの候補を key 順。
- 所属の旗: in_P、in_E25(E2 の上位 25)、in_Ewin(E の全窓にある)、in_B、gen_only。
- 代表 SMILES の規則(Codex 156): P にあれば P の代表、無ければ E の代表、無ければ B の代表。共通の特徴(fz、GL、frag)は代表の値。E だけの候補の GL は未計算 → gl_miss = 1(0 にしない)。
- P の特徴(rP、sP)、E2 の特徴(e2_score、e2_rank、全窓での順位、E の源の旗、世界のライブラリの類似度、analog)、生成物の特徴(v1 と同じ)、F の RRF の得点 = 1[in_P]/(10 + rP) + 0.5·1[in_Ewin]/(10 + rE)(rE は全窓の E2 の順位)と、F の候補の旗 in_F_pool = in_P or in_E25。
- **F-world の参照**: 提出の e2_engine.fuse_rrf と同じ関数で、P の上位 25 と E2 の順位から F の 25 件を作り、U2 の F の得点の順(同点は P の順位 → E の順位 → key、in_F_pool の候補だけ)と全件一致することを検査する(一致しなければ STOP)。E が空の query は P に戻る(元の pipeline と同じ)。
- 開発の世界ではラベル y を付ける(全行で y = 1[key == truth])。e の世界は特徴だけ(不透明な ID と許可した列だけで書き出す、v1 と同じ exporter の規則)。
