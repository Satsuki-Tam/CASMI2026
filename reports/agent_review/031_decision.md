# 031 判断: 対称 mask は C1 の追加の感度分析(副表)として採用、隠しに近い C1 の代わりにはしない。朝の三本は予定どおり

作成: 2026-10-26 07:30 JST(Claude Code)。依頼 `031_request.md`(+ 追記)、回答 `031_codex.md`。

## 1. 採否
| 論点 | 判断 |
|---|---|
| 位置付け | 現行 mask = 参照条件の厳しいストレス評価、対称 mask = library をまたぐ参照の評価。どちらも「独立取得の同装置参照は許し、query の取得そのものは除く」隠しの条件の再現ではない(library と instrument は同義でない)。 |
| 訂正 | 「≥ 0.85 で 0.69〜0.77 → 0.83〜0.90」は C1 と C2 を混ぜた率(C2 の c_L は定義上真でない)で、C1 の信頼度とは読めない。Codex が同じ C1 分子(両版で c1_usable 一致)に固定して再集計: c_L が真 — パネル 213 → 213/250、C 89 → 91/95、**G 80 → 98/100(誤 → 正 18、逆 0)**;標準で ≥ 0.85 だった G の 43 分子では 30 → 43。最終 MRR の改善量ではない。`lc_audit.py` は c1_usable で絞っておらず、標準と対称で層の集合も違った。 |
| 実装の注意 | `--sym_lib_mask` は C1 のデコイ類似を C2 にも流用するので C2・library shortlist・runner 入力も変わる(G C2 の高類似デコイ 15 → 0)→ **対称 C2 を C2 の保護の代わりにしない**。登録用には C1 だけに適用する版に分け、manifest に `sym_lib_mask`・`lib_conditions`・対象 library・重複除外と cap の順序・コード / 台帳 / 表の版を記録する。 |
| 使い方の順 | (1) 副表として登録(パネルは clean/uncertain を維持、C/G は同じ分子 ID、分母から落とさない、真の参照類似・順位・c_L の入れ替わり・到達・最終 MRR を併記)、(2) 再学習せず現行 full_eval + rank_v4b で「参照優先あり − なし」の差が view でどう変わるかを測る(閾値の多点探索はしない)、(3) ranker の再比較は既存の一組(旧 / FE_new)に限定し、各 view 内で差を取る。元の保護層は緩めない。 |
| lib_sup2 | 学習見送りに同意。ただし「情報がない」「差は全て mask の近道」とまでは確定しない。 |
| 隠しに近い C1 | 取得の出自(raw file・run・scan・再登録)が要るが、train.parquet には無い → 取得の独立性は証明できない。出自を確認できる小集合を作るのが次の実務。それまでは両 mask を感度分析として残す。 |
| 参照フィルタ | `DUP_SIM = 0.98`(同 mode・precursor 差 < 0.005 で entropy ≥ 0.98 の参照を除く)は特徴表とパイプラインの両方にあり、独立取得の真の参照も落とし得る → 監査の価値あり(今回はフィルタを外さない、朝の probe も変えない)。 |
| 朝の三本 | 登録どおり(旧 M2x の主順位、027/030 の読み)。Public の大小からどちらの mask が正しいかは決められない。 |
