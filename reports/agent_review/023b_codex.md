2. poolとPcの二本から得られる量

公式scorerのidentityで、T=train所属、C=COCONUT所属、B=C\T、K=T∪C（pool）、P=その補集合（Pc候補群）とする。TとKは入れ子で、KとPだけが補集合である。「Pc」はPubChem全体ではなく、TにもCにも属さない候補を意味する。

同じ完全順位列、同じ評価分母、所属の一貫性、空リストの代替値が偶然正解しない条件で、元出力MのK/P真値による寄与をM_K/M_Pとすると、

`M = M_K + M_P`

`P_pool = M_K + G_K`、`P_Pc = M_P + G_P`、`G_K,G_P ≥ 0`

従って、

- `P_pool − M = G_K − M_P`：Pcを除くことによる、pool側の順位改善からPc側の失点を引いた純効果。
- `P_pool + P_Pc − M = G_K + G_P`：真が属する側を完全に選べた場合の、固定順位での回収量。これは所属間の順位競合であり、学習済みクラス判定器の誤分類量ではない。
- `max(0, M−P_pool) ≤ M_P ≤ min(M, P_Pc)`：元出力のPc側寄与の範囲。

これは固定されたランキングと二つのフィルタについての式であり、他のrankerを含む性能上限ではない。Publicでは0.354が過去の別runで、三つのnotebookも別々に推論する。候補・forwardの実行範囲や数値差、表示丸めが残るため、実測値からの代入はその誤差を含む近似として扱う。

**`P_pool − P_T ≈ COCONUT寄与`は撤回する。** pool出力のT真値による寄与をQ、B真値による寄与をRとすれば、`P_pool=Q+R`かつ`P_T≥Q`なので、差は`R−(P_T−Q)`である。COCO-onlyの得点に、T真値がCOCO-only候補から受ける順位損失が逆符号で混ざる。負になることさえあり、COCO∩Tも別扱いになる。三本を出してもこの差から寄与は同定できない。
