# 099 相談: test 集合内の「家族構造」を使う生成(transductive generation)の評価設計

作成: 2026-10-28 02:30 JST(Claude Code)。読み取り専用で構いません。
## 発見(探索、真の構造を使った上限)
- パネル(Enveda の NP 例 250、隠しに最も近い)の **30.0%(75/250)が、パネル内の別の分子を親にした b1_gen の 1〜2 段の生合成的変換(厳密な質量検査つき)で正解の公式 key を生成できる**。無作為の NP 集合(053 dev f1 / f2)では 5.9% / 5.3%。= Enveda の集合は化合物の家族(配糖体・メチル化体などの系列)を含む。tgen_panel.py。
- 隠しも Enveda の NP なので、同じ家族構造を持つ可能性が高い。ホストは test 内のスペクトル関係のラベル無し利用を許可(10/26)。E0 は使っていない。

## 使い方の案
1. **クラス 3(DB に無い)**: 分子 i について、他の test 分子 j の**予測した**上位構造(v7f 主出力の 1 位)を親にして b1_gen.derive(親, i の query 由来の質量)で候補を作り、i の FPNet の f·z で最良の 1 つを、gt3 と同じ規則(主リストの 3 位の f·z 以上なら 3 位に挿入)で入れる。
2. **クラス 2(DB にある)**: DB 候補の key が「他の test 分子の予測構造からの生成物」に含まれれば加点(dv1 型の test 版)。

## 評価の案
- 集合: パネルを fold-safe の fpnet_fold0 で作り直した表(パネルはどの fold-safe FPNet にも未見 = クラス 2 の模擬)+ GL、gen dump つき(Spark で作成中)。C3 view = 正解を DB から除いた主リスト(gen_eval の c3 と同じ)、他の分子の予測は C2 view の主出力の 1 位。指標: C3 の MRR、C2 / C1 の費用(3 位挿入で押し下げられる真)、既存の gt3(train の analog を親)との比較・併用。
- 開発集合が実質パネルだけ(家族構造を持つ集合が他に無い)なのが弱点。パネルの正解は有名で、親(他の分子)の 1 位の正答率も開発より高い可能性。

## 質問
- Q1: この評価で「隠しで効く」と言えるための最低限の条件と、パネルだけで選ぶことの落とし穴(選択の楽観、パネルの有名さ、親の予測の質)。家族構造を持つ別の開発集合を train から作る案(例: ライブラリ内の系列)は妥当か。
- Q2: 親の選び方(全 test 分子の 1 位 / スペクトル類似の近傍だけ / 予測の確信度で絞る)と、挿入規則(3 位固定 / f·z の門 / GL の門)をどう事前に固定するか。
- Q3: Public での確認の形(1 枠で v7f + test 側生成の一変更)と、クラス 3 の比率が未知であることの読み方。
