**結論：counts 除去と C1 の増重は改善の方向だが、v4b を修正完了として再登録・開封する段階ではない。まず候補設定と参照選択を揃え、完成した出力ポリシーを比較する。今夜は C1-all の全量追加より、この修正と小さな切替規則の確認を優先する。**

また、**0.334 は学習融合を使わない固定版の LB**である。今回見つかった学習器の C1 悪化は重要な別の問題だが、これ自体を0.334の原因とはできない。公開 main list と B1 固定の差も、提示された234分子では C1 −0.083／C2 −0.095で、固定版の不足が C1 だけに集中しているわけではない。

**再登録前に直すべき比較条件。**

1. **`run_panel_v2` は実際には v3 の拡大 shortlist。** Spark の `b1_features_manifest.json` は `k=100, k_fpp=200, k_pop=50` で、平均 `n_short_c2=225.67`。`spark_panel_chain.sh` の `FEAT_ARGS=""` が、呼出先の `${FEAT_ARGS:-"--k_fpp 200 --k_pop 50"}` によって既定値へ置き換わっている。従って rank_v2 の結果は「旧 M1 を異なる候補構成へ適用した診断」であり、M1 本番構成の忠実な再現ではない。逆に rank_v3/v4 の候補構成は拡大版に合っている。M1 の確認は `--k_fpp 100 --k_pop 0` を明示した別 run で行い、現在の結果を上書きしない。

2. **公開比較で落ちた16分子は、公開 main list がない分子ではない。** 両側とも250分子あり、生の `molecule` 文字列の交差が234。`train_scorer_keys.parquet` の公式 identity に写像すると、双方250 identity で全件対応する。`b1_vs_public_panel.py` の query 結合を正規化し、候補の同一性・公式 RR も揃えて250分子で再集計する。Spearman 0.960 は共通候補上で prior の順位が似る証拠であり、融合への寄与や隠しテストでの重みまで同じという証拠ではない。forward なしの λ 感度が小さいことは、パネルで λ 引き上げを最優先にする根拠が乏しいことを支持する。

3. **C1 の参照数分布に、評価・提出の処理順の違いが混ざっている。** `b1_features.py:281–286` は24本に絞ってから真の同一ライブラリ参照を除く。一方、`b1_pipeline.py:353–354` はライブラリ除外を先に行い、その後で24本に絞る。`run_c1_v2` には「他ライブラリ参照24本以上・重複除外0件なのに、選択参照24本未満」が9分子ある。例：`XHBSBNYEHDQRCP` は他ライブラリ25本に対して `c1_usable_refs=0`、`PCMFSBCRKKRDDK` は41本に対して19本。scenario の除外後に参照を選ぶ共通処理へ揃える。これだけでパネルの悪化全体を説明できるとは言えないが、参照数の差をすべて化合物分布の差と読むことはできない。

**Q1：機構の読みと修正の優先順位。**

参照・prior とスペクトル特徴の組合せを、学習器がパネル C1 で不適切に扱っているという読みは支持する。C1/C2 で同じ分子を比較でき、参照特徴を変えると大きく順位が変わること、counts 除去の再学習でも改善することは有力な証拠である。ただし SHAP の −0.62 は単純な係数や因果効果ではない。特徴を0にする推論時 ablation も、学習時に乏しい特徴の組合せを作る操作であり、その値を修正後の期待性能にはしない。prior を0にした C1 改善もあるため、単一の count 特徴だけの問題ではない。

C2 の正解が参照を持たないこと自体は、その scenario の定義通り。必要なのは、参照が有効な C1 と、強い誤一致を持つ C2 の両方を扱えること。C1×3 は fit 内だけで行われており、split を跨ぐ複製ではないが、新しい独立分子や新しい参照条件が増えるわけではない。

優先順位は、上の実装差を修正した上で **(c)の小さな比較 → (b)の取得分離を確認した追加 → (a)は見送る**。

- **(c)** は実装・比較が軽い。ただし現在の `guard0.8` は「learned に参照優先を重ねる」規則であり、質問の「高 lib_max なら固定＋libpri、それ以外は learned」とは違う。v4b の guard0.8 がパネル C1 0.770という値を、後者の評価として使わない。切替条件、非発火時、GL 不足時を一つの提出関数にし、同じ θ を全集合へ適用して C1 救済／C2 損失を paired で測る。真のクラスや正解候補の参照数は切替に使わない。
- **(b)** は、独立した取得だと確認できれば妥当。まず少数の取得群で query と参照の独立性を監査する。同一取得の CE 違いや派生スペクトルを分けただけでは独立取得にならない。今夜はこの確認と既存 C1 の参照選択修正までを優先し、取得単位を判別できないまま1時間の全量再計算へ進めない。条件が整えば、C1-all は既存の他ライブラリ C1 と別 view として追加する。
- **(a)** は、学習で真の C2 と知っている行だけ参照特徴を消し、本番では同様の分子に非ゼロ参照特徴を渡すことになる。誤った高類似参照を否定する訓練例も失うので第一選択にしない。特徴を除くなら両 view・推論で共通にするか、参照を使う部分にも C2 の誤一致例を残す設計がよい。

**Q2：隠し C1 をパネル型と仮定してよいか、参照規則を本命に入れるか。**

隠し C1 の一部がこの条件である可能性に備えるべきだが、全体をパネル型と仮定する根拠はない。公開 main list の0.964は同じ偏ったパネル上の多特徴モデルの値であり、隠し C1≈0.95を独立に裏付けない。

また、表の高い一致精度は `P(正解 | 類似度帯, C1条件)`。本番で必要なクラス未知の精度とは違う。C2 では高類似の参照候補も偽になるため、C1 の精度だけから切替閾値を決めない。`lib_max>=tau` の件数も、margin 条件込みの実発火数ではない。

参照規則を本命に組み込むこと自体には賛成だが、混合条件での損益確認が条件。パネルの raw `S+1·lib` は C1 0.882に対して C2 0.840で、固定0.864からの利得・損失がある。`S+z(lib)` は別規則で未検証。疎な類似度を標準化すると、絶対類似度が低い候補にも大きな z 値が付き得るため、絶対類似度や margin の情報を捨てない。いずれも「C1らしいから改善する」という想定だけで本命化しない。

**Q3：再登録案。**

未開封のうちの置換は可能。ただし、現時点では **旧 M1 を凍結対照として残し、修正を M2′ 一本にまとめて確認する**ことを勧める。旧 M1 を残すことは、それを最終提出に推奨することではない。M1′ の ICE あり再学習を同時に足す前に、まず M2′ の参照が多い条件での不足を解消し、開発 A/B の損失を確認する。v4b をそのまま M2′ として確定することには反対。

保険を両方 τ=0.8 に変更する根拠も、現状では足りない。`libpri_delta_dev.md` の **A/v3/C2 は −0.0228**、パネル C2 は **−0.0220**で、「C2損失≤0.02」は点推定でも一律に成立していない。C1 の ε=0.02 は C2 に自動で認めた損失幅でもない。τ=0.9を既存対照として残し、τ=0.8は変更案として比較する。C1の利得だけで保険を昇格させない。

採用規則の A/B 別 paired 差、C1 の許容損失、時間比較は維持する。ただし、旧 learned 対照との非劣性だけでは、両候補が同じ条件で固定／保険に負ける問題を見逃す。参照が多い群と少ない群で固定／保険との差も開発段階で確認してから候補を固定する。パネルは今回の変更を選ぶ材料になったので、改訂後のパネル値を独立な最終検証とは呼ばない。

**Q4：LB の読みと朝の提出。**

M1 が0.334未満なら「C1崩壊が起きた」、上なら「C2利得が勝った」と分ける読みには反対。単一の Public 集計値から C1/C2 の寄与は識別できない。どちらの方向もその仮説とは両立し得るが、候補・実行時の欠損・未対応条件など別の説明も残る。旧 M1 は fallback 方針も改訂版と違う。E0との差±0.02は引き続き調査の運用閾値であり、統計的有意差やクラス判定の閾値にはしない。

2枠を使う前提でも、(i)を現状の v4b、(ii)を無条件にτ=0.8と決めない。まず完成した M2′ が上記比較と提出経路の確認を通れば本命を提出し、もう1枠は事前に比較目的を決めた保険へ使う。τ=0.8の損失を許容する根拠が揃わなければ、既存τ=0.9または枠を残す方がよい。前回の拒否記録を踏まえ、提出対象を確定した別 Notebook 版として用意する。可視実行の約3時間を隠し再実行の実測時間とは扱わない。

**Q5：パネル C1 の妥当性と、悪化の重み。**

他ライブラリ参照の総数は平均 **224.36**だが、`MAX_REF=24` 後の `c1_usable_refs` は全250分子で平均 **22.91**。23.5は「固定top-1で学習が負けた105分子」の平均であり、別の集計対象である。モデルに224本すべてを渡しているわけではない。参照が多い著名化合物への偏りと、上限24本への集中を分けて記述する。

この偏りにより、パネルの絶対値や悪化幅を隠しテスト全体へ転写できない。一方、構造・参照が十分ある既知分子で順位を大幅に壊す現象を、偏った集合だからとして無視するのも不適切。正しい M1 shortlist で再確認し、M2系では残っている悪化を解消する価値がある。追加診断をするなら、全候補に共通の参照予算を適用した再サンプリングで件数への感度を見る。真の候補だけ参照を減らす操作にはしない。C1-all の取得分離確認と、既存の C1 参照選択修正を先に行う。
