- **開発の screening と採用時の確認を分ける**。実用上の許容損失 ε と統計的不確実性を分け、三状態で読む: 上限 U < −ε = 許容を超える害の証拠 / 下限 L > −ε = 非劣性を支持 / それ以外 = 未確定。
- 登録のひな型(053 以降):
  1. 主指標を一つ固定(C2 改善なら NP C2 の等重みマクロ)、必要な改善の大きさ τ も先に決める。
  2. 主保護は少数の集約(採用時のモデル露出に対応した NP C1 の集約 = 例えば full_eval の表でのパネル C1、と NP C2 の集約)に ε = 0.01 の三状態。
  3. 開発では「主保護で U < −ε」が無く主指標が目的に沿えば候補として残す(未確定は「保護合格」と記録しない)。
  4. 確認は一つに固定した候補で、主指標の差と区間・主保護の非劣性・全 stress 層を報告。主保護が未確定のときの扱い(追加データ待ち / リスク明示の限定比較)を登録時に決める。
  5. 細かな層と G は監視(害の検出に Holm を使うなら family・片側の向き・margin を指定)。G は化学が違う stress だが「隠しと無関係」とはしない。
- pool は block(fold-1 / fold-2 / dev2)ごとの一対差を固定重み(等重み)で統合し、block 別の差も残す(C1 の usable 数で重みが動かないように)。
- 次に校正するのは選択手順全体(全効果 0、主指標が正で主保護 0、主指標が正でも主保護に −0.02〜−0.04 の害、block 間で逆符号)— 時間が取れた時に。
