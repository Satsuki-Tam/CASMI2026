## 4. 提案(明日 10/26 09:00 以降の枠)
**(a) T probe(train 構造のみ、同じ M2x の主順位)**: `M_K` を「真が train(クラス 1 型)」と「真が COCONUT のみ(クラス 2 型)」に分ける。新 ranker のトレードオフ(クラス 1 ↑・COCONUT のクラス 2 ↓)の重みづけに直接効き、較正にも観測が一本増える。kernel `casmi26-b1-probe027-train`(未 push)。
**(b) 順位帯 probe(主順位の 26〜50 位)**: B1 がどの構成でも 0 点の成分のうち「shortlist にあって 26〜50 位」の量を直接測る。大きければ shortlist 内の並べ替え、ほぼ 0 なら候補生成(到達)かクラス 3 が主因。pipeline は probe023(sha 1bc93dda)に出力を一つ足しただけ(sha f9122e77、`experiments/b1_probe027/`)。Spark の 16 分子で rc 0、band26 と主出力の重なり 0、長さ 25 を確認。kernel `casmi26-b1-probe027-band`(未 push)。
- どちらも 025 の防護(単一の競技入力を `--test` に明示、ダミーの判定は spectrum ID と file sha256 の両方、全件処理の assert、smoke 12)を入れた wrapper。
**(b2) pool-window 分岐つきの pool probe(`--k_pool 60`、emit pool)**: 今夜の pool probe は B1 の shortlist(FP top-100 ∪ FP+prior top-200 ∪ prior top-50 ∪ 参照 top)を絞っただけなので、**shortlist に入らなかった COCONUT / train の真は回収できない**(G_K ≤ 0.028 はこの制約の下での値)。E0 の engine-1 と同じく pool 窓の FP top-60 を shortlist に足した版の pool probe を 0.336 と比べれば、pool の真の到達不足がどれだけあるかを測れる(局所では k_pool 60 の主出力は G C1 −0.040 で不採用だったが、これは probe)。pipeline = 現行 4dc9e7b3 + probe023 の群フィルタ + band26(sha 6268f24f、`experiments/b1_probe027k/`;主出力の順位付けは不変)、Spark の 16 分子(C2 view、k_pool 60)で rc 0・pool/Pc の重なり 0・接頭辞順 0 違反・band と主出力の重なり 0 を確認。kernel `casmi26-b1-probe027-k60`(未 push)。0.336 との差は「k_pool 60 + コード版(select_queries 一本化は 600/600 一致を確認済み)」。
