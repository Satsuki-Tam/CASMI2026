# 135 計画(草稿、2026-10-29 22:07 JST、Claude Code)— class 3(DB に無い構造)の実現性を、正しい情報条件で先に測る

Codex 131: 「class 3 は並行して評価条件と到達・選別の上限を確かめ、大きな利得を取れる条件が残れば投資を増やす」。本稿は結果を見る前の設計案。

## 0. なぜ今か(数字の根拠と限界)
- 公式: 隠しテストのクラス分布は非公開。コミュニティの推定は class 1 10〜28%、class 2 20〜55%、**class 3 30〜74%**(根拠は弱い)。ライブラリ検索だけの提出は Public 0.15 前後。
- 私たちの Public の probe(10/29、加算できない圧縮した得点): train 構造だけ 0.148、COCONUT かつ非 train 0.220、PubChem のみ 0.046。v8w7a 全体 0.394。class 3 の分子は現状すべて 0 点。
- 仮に class 3 が 30% で、その 1/3 で正解を生成でき、生成できた分子の平均 RR が 0.5 なら全体 +0.05。一方 099(パネル、情報条件に不整合あり)は到達 54%・選別 MRR 0.068、ggt3t(GL で生成物を選別)は Public −0.001。**律速は選別**で、到達は家族(同じ試料の類縁)があれば一定ある。
- Codex 131 の試算: 3 位挿入だけで +0.106 には C3 比率 58.5% 以上が要る(1 位なら 19.5%)。→ 上位に置ける精度(選別)が要。

## 1. 実現性の測定(結果の前に固定する設計の骨子)
1. **バッチ**: fold 1 の NP 系 identity(既使用の開発表の分子を含む)から、(a) 家族バッチ(Murcko 骨格 / 指紋の近さで束ねた N 分子)、(b) 同じ大きさの無作為バッチを作る。各バッチの一部(例: 1/3)を「C3 とする分子」に固定(hash)。
2. **情報条件(全バッチ共通)**: C3 分子の構造(公式 key と alias group)を、全 query の候補 DB(PubChem tier・pool・COCONUT)、ライブラリ参照、analog の親資産、他分子の予測リストから除く。親の予測(各分子の C2 view の 1 位)は、この除外の下で凍結した P で一度だけ作る。
3. **生成**: query 由来の中性質量と、予測した親(同じバッチの他分子の 1 位 + train の analog 親、除外後)だけから b1_gen で生成。
4. **選別**: 生成物と DB 候補を同じ土俵で比べる学習・校正(FP・GL・MIST・質量誤差・親との類似・編集の種類・生成物の数等の観測可能な量)。学習は fold 3 / 4 の同じ模擬、評価は fold 1。低い DB 得点を class 3 の確定検出器にしない(未到達・難しい C1 / C2 でも起こる)。
5. **読み**: (i) 到達 h(正解が生成物に含まれる割合)、(ii) 生成物の中での正解の順位(選別の上限と実際)、(iii) 挿入規則ごとの全体の差(C3 の利得と C1 / C2 の費用を同じ出力で)、家族 / 無作為、バッチ単位の bootstrap。全体への換算は C3 比率 π を仮定した感度表(π を推定しない)。
6. **前提の確認**: 隠しテストの分子に「同じ試料の類縁」がどれだけあるか(test.parquet のダミーでは推定しない;隠しの性質は Public の結果からしか分からない)→ 家族と無作為の両方で測る理由。

## 2. Codex に確認したい点
