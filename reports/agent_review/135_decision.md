## 3. 私が加える点

(a) **W135 は class 3 の測定のためだけの道具ではない。** 推論と同じ候補生成・特徴計算を、規則的に情報を隠した世界で全 query に適用する基盤である。これは E0 の sim1x(069 §P1、E0 の得点の主な源の一つと推定した学習行の作り方)を正しい情報条件で行う基盤と同じである。ranker の学習行を世界単位で作る使い方は、135 の結果とは独立の別仮説として後で登録する。今は作らない。

(b) **事前の期待として記録する**(判断の基準は変えない): E0 は常に生成している(analog の親 6、46 変換、同じ ranker で採点)。公開議論 750241 では「DB に無い 130 分子で 1 位 7」(5.4%)とされる。LB の記録では、親を 6→20 にすると −0.008、生成物の 1 位強制で −0.007 だった。私たちの ggt3t(生成物 1 個を 3 位へ)は Public −0.001。したがって E0 系の class 3 の実力は、Codex が示す必要水準(π = 0.3 で R3 ≥ 0.09)に届いていない可能性が高い。W135 で問うのは「peer 親(同じバッチの類縁)と正しい情報条件で、どれだけ上限があるか」である。

(c) **実装の検算**: W135 の特徴表は b1_features.py の写し(b1_world.py)に、バッチ単位の mask を加えて作る。mask を空にし、分子ごとの view の規則に戻すと、既存の c1 / c2 表(既存 run の分子)と一致すること(parity)を、世界を作る前に要求する。GL の cache は「同じ query のスペクトル・同じ構造・同じ model」の純計算に限って再利用する。cache 経由の得点が、その場で計算した得点と一致することも数分子で確かめる。

(d) **C1 / C2 の適格性**: C2 の代理は、真の構造が train 以外の構造 DB(PubChem tier / COCONUT)にある分子に限る(train だけにある構造は、参照を消すと現実には class 3 に相当するため)。C1 の代理は、独立な取得の参照がある分子に限る。C3 は全員が適格。割当は hash 順で固定し、適格者が足りないときの実際の比率は記録する。
