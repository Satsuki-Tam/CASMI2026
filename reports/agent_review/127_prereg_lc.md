# 127 事前登録(診断、計画のための記述;結果の前、2026-10-29)— ranker は学習データ量で頭打ちか(学習曲線)

## 動機
- 110(FP の seed 平均)と 111(自前の採点器 N)は、単一の証拠を改善しても、凍結した v8w7a の ranker・固定の接続の外から足すと主指標に届かなかった。証拠を使い切るには ranker の再学習が要る。
- E0 の engine 1 の ranker は約 23,748 query、engine 2 は約 6,138 群で学習している(069_e0_inventory)。v8w7a の ranker は 3,931 群(2,879 分子 + C1 の複製)。v8w(f3a/f4a の pool を追加して 1,304 → 3,931 群)は確認で +0.0067、開発で NP_H C2 +0.033 だった。
- 問い: 現在の規模で、ranker は学習群の数に律速されているか。律速なら「学習表を数倍に増やす」(069 の P1:同じ pipeline の模擬で大規模に学習)を主な投資先として Codex に提案する。律速でなければ別の手を探す。

## 方法(固定)
- 学習: pc/jobs/pc_rank087.sh と同じレシピ(v2_noice_ana − lib_nref − in_train、C1 ×3(f3a/f4a は ×1)、rank_params_v7a の固定パラメタ・600 rounds、analog_tr_v8w)。b1_rank_train.py に `--fit_frac / --fit_seed` を追加(既定 1.0 = 従来どおり)。fit の分子(両 view を一緒に)を、ID を並べた順の seed 付き置換の先頭 round(frac · n) で残す。tune / eval は触らない。
  - 対照の再現: frac 1.0 で学習し、既存の rank_v8w7a/lambdarank.txt(fe61dc42)と一致すること(追加した引数の既定が中立で、学習が決定的であることの確認)。一致しなければ曲線は読まず、原因を調べる。
  - 曲線: frac 0.5 と 0.25、それぞれ seed 1 と 2(計 4 本)。
- 評価: 審査済みの評価器(gen_eval2fd_n111.py、sha 1ccf5e35)で、v8w7a と 4 本を一回の pass に入れ(--model の並び)、f1dev / np053f1dev / f2dev / np053f2dev、--views c1,c2、--parents 0。
- 読み取り x_lc127.py(記述のみ): 各モデルの主指標(1/4 NP_H C2 + 1/4 NP_N C2 + 1/2 D C2)を fold ごと・2 fold 平均で、旧 B(C/D/E/F C2)、G C1、NP C1 も。frac ごとに seed 平均。差は v8w7a(frac 1.0)との行単位の差の identity bootstrap(4000、seed 20261029)。

## 読み(結果の前に固定。判定ではなく次の投資先の選択の材料)
- P(f) = 2 fold 平均の主指標の seed 平均。
- **P(1.0) − P(0.5) ≥ +0.010 かつ P(0.5) − P(0.25) ≥ +0.010** → 現在の規模でも学習群の数に律速 → 学習表の大規模化(GL の付け方を含む)を主な投資先として Codex に提案する。
- **P(1.0) − P(0.5) < +0.005** → 現在の規模では飽和に近い → 大規模化を主な投資先にしない。
- その間 → 未確定(層別の形を見て Codex と相談)。
- 限界: rounds を 600 に固定しているので、小さい学習量では過学習の分だけ傾きが大きく見え得る(上限側の推定)。学習群の構成(C1 比率、fold 3/4 の pool)は frac で比例的に縮むだけで、質の違う群を足したときの効果は測らない。f1dev / f2dev は既に何度も使った開発集合で、確認の集合ではない。
