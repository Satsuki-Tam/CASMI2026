# 032 相談: 推論時の重複参照フィルタ(DUP_SIM 0.98)は隠しテストのクラス 1 の最良の証拠を捨てている可能性 — 今日の空き枠での一変更比較の事前登録案

## 1. 事実(コード)
- `b1_pipeline.py:376-387`(Kaggle の推論でも有効): 各候補の参照のうち、query のどれかと **precursor の差 < 0.005 Da・同じ mode** で、(a) peak 列が完全一致、または (b) entropy similarity ≥ 0.98 のものを「同じ取得の再登録」として捨てる(`DUP_SIM = 0.98`)。`b1_features.py` も同じ規則(局所評価では train 由来の query の再登録を除くために必要)。
- 隠しテストの query は Enveda の timsTOF の**新規取得**で、公開 library には無い(再登録はあり得ない)。クラス 1 の真の train 参照のうち、同じ化合物を同じ種類の装置・同程度の CE で測った独立取得(例: Enveda 自身の timsTOF library = enveda-180 や enveda-np-examples)は、query と ≥ 0.98 になり得る → **最も強いクラス 1 の証拠を「重複」として捨てる**。(b) の高類似の規則は、隠しでは利益が無く損失だけがあり得る((a) の完全一致は隠しでは起きない)。
- 公開系譜(E0)は(私の知る限り)この種の除外をしていない → クラス 1 の一部で E0 が有利になる経路の候補。
- 大きさは局所では測れない(局所の query は train 由来で、再登録の除外が必要なため)。隠しの分子に enveda-180 / enveda-np-examples の化合物がどれだけ含まれるかも不明。

## 2. 提案(事前登録案): 作業用基準 full_eval(0.370)に対する一変更の比較提出

- 読み(結果前に固定、028 の運用): Public の差は「隠しテストで高類似の独立参照がどれだけあり、それを使うと得か」の純効果。+0.02 以上なら作業用基準の更新候補(局所の保護は該当なし = 局所では測れない変更であることを明記)、±0.02 は判定保留(フィルタは隠しでほぼ発火しない可能性)、−0.02 以下ならフィルタを戻す(高類似の参照が類縁体のデコイを助けていた可能性)。
