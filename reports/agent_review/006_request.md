C1 専用集合(`run_c1`、GL のみの暫定): S(2,1,0.15) C2 strict 0.399、S(0.5) 0.433、参照のみ C1 0.854(正解の類似度中央値 **1.000**)。

観測:
1. 順方向モデルの全体 z 和が主力。prior 重み 0.5 は 0.15 より A/B/C1 集合で一貫して良い(A +0.007、B +0.034、C1 集合 +0.034)。
2. 参照優先規則は Class 2 を落とす(τ=0.6 で A −0.05、B −0.026)。enveda-180 では類縁体の参照が高い類似度を出す。「S 上位 3 以内」の整合条件を付けても C2 の損失は残り C1 の利得は小さい。
3. **重複参照**: B/C1 集合の C1 で正解の類似度が 1.000 の分子が大半 → 同一スペクトルの再登録(GNPS → MoNA/MassBank 等)。005 の指摘どおり独立測定ではない。`b1_features.py` に「同一プリカーサ(5 mDa)かつ類似度 ≥ 0.98 の参照は同一取得として除外」を追加し、C1 集合を Spark で再構築中(結果は 13:30 頃)。
4. A の C1(7 分子、重複なし)では正解の類似度中央値 0.68 → 本番の timsTOF vs Orbitrap/QTOF でも同程度と予想。τ=0.8 以上の規則はほぼ発火しない。

## 4. 質問

1. 参照優先規則の扱い: 「学習融合に任せ、固定規則では入れない」という判断は妥当か。別案は「同アダクト・同極性の参照類似度が τ 以上かつ次点差 m 以上かつ FP/forward の順位が上位 k」の 3 条件ゲートだが、整合条件(S 上位 3)の結果は利得が小さかった。
2. 重複除外の基準(同一プリカーサ 5 mDa かつ類似度 ≥ 0.98)は妥当か。装置が異なる同一分子の独立測定が 0.98 を超える場合は稀だと考えるが、過剰除外の検出方法は。
3. prior 重み 0.5 の採用: 3 集合で一貫するが、hidden(天然物・timsTOF)で文献数の分布が変われば過大になり得る。LambdaRank に prior 成分を渡すことで吸収できるとみてよいか。
4. LambdaRank の学習データ構成(fit に P1 600 分子を使う: P1 で重み選定に使った分子だが、固定規則の重みではなく学習器の訓練データとして使う)。tune/eval は未使用の eval_set。問題はあるか。
5. B1 v1 の Kaggle 可視実行(400 分子)で実行時間を測定中。9 時間予算の配分に関して、FP 窓採点(Kaggle 4 CPU)がボトルネックになる場合の削減案(pass-1 の部分指紋による絞り込み、K の縮小、窓の ppm 縮小)の優先順位を示してほしい。
