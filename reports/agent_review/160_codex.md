結論: **159 の主要な指摘は解消しており、基準 FH-PEB を測る段階に進む材料は整っている。G0 前の残件は、記録上まだ開発 31 世界だけになっている独立した候補集合・順序の照合を、e の 6 世界にもラベル非依存で通すこと。** 新規学習や資産の一律再生成は不要で、差異がなければ完了ログへの追記でよい。

診断は E2 の並べ替えの有効性を支持する。ただし「到達 0.652 − F の MRR 0.472 = 改善余地 0.18」は母集団が異なるので訂正する。Public 0.500 への見込みは、この診断だけでは数量化できない。

協業ルール、159 の回答・判断、158 の登録・結果、関連スクリプト、v2 の src・refs・仕様・設定・小さな manifest を確認した。ワークスペースは変更していない。新たな性能集計、実モデルの学習、e のラベルの読み取りは行っていない。追加検査は、人工データでの adapter 呼出境界・枠の変換と、小さな query 表の件数・有限値に限った。

**今回の資産の受け入れとしては、大半を満たした。** 担保の場所と範囲は次のように整理できる。

**A1〜A5 だけで、学習境界と予測契約を全て試したとは言わない。** A1 は一つの fold の実学習で有限値と実在する検証枠の採点を確認するが、検証ラベルへの非依存性、余白の厳密な PAD、test の全実在枠の充足、7 fold の平均までをそれぞれ検査しているわけではない。

ここはコード点検に加え、今回、学習器を記録用の代用品にした人工データで補った。

- 検証側の y と特徴を変更しても、学習器へ渡る X・y・重みが変わらない。
- valid/test の実在枠に代用学習器の予測が入り、余白と空 query は PAD のままになる。
- 空 query の RR は 0 で、例えば RR が 1 と 0 の二件を主集合として渡すと score は 0.5 になる。
- 実際のワークスペース内の runner は、7 fold の test 予測を同じ枠で平均する実装になっている。

これは LightGBM の性能の試験ではなく、学習への入力と出力の接続の検査である。既存の実学習を含む A1 と合わせ、初期 adapter の学習境界・枠の契約に具体的な破れは見つからなかった。追加の学習試験は不要。

なお `x160_flags.py` の NaN は報告するだけで FAIL 条件ではなく、Q の数値列も対象外だった。今回、**全 37 個の Q 表、合計約 660 KB**の数値列を読み、3,691 query 全てで有限値を確認した。空の 31 件も n_p/n_b/n_e/n_e25/f_applied=0、e_empty=1 だった。将来の資産にも同じ保証を使うなら、NaN だけでなく Inf、Q 列、空 query のこれらの条件を検査の失敗条件に含めるとよい。今回のデータを作り直す理由にはならない。

e に追加する照合は、候補 key・順位・名簿・hash の技術検査だけで行う。truth/class・到達・MRR を使わず、一致件数と PASS/FAIL だけを残せば、e の一回限りの性能確認は保たれる。

## Q2. analog を round 6 で照合する変更

**採用してよい。** P の保存規則が `round(float(v), 6)` で、E が生値なら、E に同じ保存規則を適用してから比較するのが正しい。性能を読む前に、保存コードから原因を特定して固定した変更であり、性能を通すための許容差選びとは区別できる。

保証するのは「順序を含む key と、保存された精度での値が一致すること」であり、丸め前の bit 単位の一致ではない。同じ丸め区間に入る微小な生値の差は隠れ得る。したがって、以後も「生値が完全一致した」とは記録しない。

大量の値を比べれば、生値と丸め値の最大差が半単位の 5e-7 に近づくことは自然で、表示上その値になること自体は異常の証拠ではない。最大差の表示桁だけで厳密な等号を主張する必要もない。今回の key 完全一致、コード・入力の来歴、同じ保存規則での全件一致を合わせれば、受け入れに十分。**このために全 analog を再生成する必要はない。** 今後、丸め前の微小差が閾値や同点処理を変える疑いが具体的に出た場合にだけ、同条件の少数 query で両経路の生値を比較する。

## Q3. 診断の読みと、+0.01 / Public 0.500 への道筋

**(a) は「一つの改善の方向・規模が整合した」という補助的な証拠まで。** ローカルの +0.0182 と Public の +0.020 が近いことは好材料だが、世界の再現性を一般に検証できたことにはならない。今回のローカルは 398 件・少数のバッチ組で、Public とクラス、化学領域、学習済み identity、源の被覆などの混合比も同じとは限らない。今後の +0.01 が Public に同量移るという校正には使わない。

**(b) の「主因は共通候補の並べ替え」は支持できる。** 根拠は候補の順位が 73.5% 変わったことだけではない。398 件で、真が E25 にあり P25 にない件数は 2。新しい候補の到達から得られる MRR 増分は、両方が 1 位でも最大 2/398 ≈ 0.0050。全体の純増 +0.0182 のうち、少なくとも約 +0.0132 は真がもともと P25 にあった query 側の純増になる。新しい 1 位 14 件のうち少なくとも 12 件も、元の P25 に真があったケースになる。到達の寄与をゼロとは言わないが、主因の判断には根拠がある。

**(c) は母集団と「上限」の意味を直す。** 0.652 は 1,198 件、0.4723 は 398 件なので、その差 0.18 は有効な headroom の実測値ではない。基準を読む際に、同じ主集合 S で

`headroom_U2(S) = mean_S 1[truth ∈ U2] − mean_S RR(F-world)`

を出す。同じ集合なら、これは「全ての到達済み正解を 1 位にできたとき」の上限であって、62 特徴から学習可能な改善量ではない。次の三群に分けると判断に使いやすい。

1. 真が F の上位 25 にある: 順位を改善できる余地。
2. 真が U2 にあるが F の上位 25 にない: F の出力に残らなかった E/B 等を選ぶ余地。
3. 真が U2 にない: 現在の候補表と ranker の調整では回復できない領域。

117 件の「E 源の外」も、現在の実装での定義は **C1/C2 の真がその query の E 窓にない**というもの。DB 全体に構造が存在しない場合だけでなく、質量・adduct・窓の条件で外れた場合も含み得る。DB 不在と同一視せず、この層で F が P を傷つけないかも補助的に見る。

**FH-PEB は本質的な問題の一つに向いている。ただし突破を予測できる段階ではない。** E2 の有用な順位情報と B を同じ候補表へ接続した点には意味があり、+0.01 は測る価値がある。一方、固定 RRF は既に強い規則で、二値学習がその順位を崩す費用もある。到達率の高さだけを根拠に突破見込みを高く置かず、基準と PE の比較で判断する。

C3 については、この主集合では 360/1,198 が C3、B の到達が 0.225。**現在の B を完璧に順位付けして C3 だけで増やせる全体 MRR は、最大でも約 (360/1,198)×0.225 = 0.0676**である。これは到達済みの真を全て 1 位にし、C1/C2 を全く傷つけない楽観的な上限。現状の Public にそのまま移せる上限ではないが、同じ混合を仮定してさえ +0.086 の全てを C3 だけに期待する計画には足りない。C1/C2 の順位改善と、必要なら候補の被覆改善も要る。

また、C3 は 1 位でなければ無価値ではない。回復できた真の順位ごとに RR は積み上がる。ただし B の誤挿入による C1/C2 の損失を差し引いて評価する必要がある。

**次の最小の判別は、予定している基準と PE の比較で行える。** seed 11 の OOF について、F、独立に学習した固定 FH-PE、FH-PEB を比較する。追加の記述として、同じ FH-PEB の得点から PE 資格だけを残した順位も読める。これは新しい学習済み PE 対照ではなく、同一モデルで B の追加出力を許す費用を分けるための反実仮想である。

- 固定 FH-PE が F を改善するが PEB で失うなら、DB 候補と生成候補を一緒に学ぶ・競争させる部分が問題。
- PEB の PE 限定順位はよいが全候補では悪いなら、主に B 追加候補と PE の間の得点の比較・挿入判断が問題。
- PE 限定順位も悪いなら、B を含む学習が PE 内の順位まで変えている可能性がある。
- 到達済みの同じ候補で全方式が失敗するなら、設定探索だけで十分な識別情報が得られるとは考えない。

構造的な次案としては、上の結果が混在による損失を示した場合に、**PE と B追加候補の順位付けを分け、観測可能な P/E の一致度・参照強度・B の支持から両者の競争を調整する二系統のモデル**が考えられる。最小の比較は、同じ U2・外側 fold・情報・seed・計算予算で単一 PEB と一案だけを比べるもの。調整器がモデル得点を学習入力にするなら、学習 fold 内でも OOF で作り、真の class/pi を入力や適用条件にしない。これは現行の TUNABLE/rounds 調整とは別の設計変更として扱い、基準の途中で切り替えない。

候補の被覆を変える必要があるかは、「E の全窓にはあるが U2 にない」と「全窓にも U2 にもない」を先に交差集計すれば判別できる。前者なら shortlist の選び方、後者なら窓・源・生成の問題である。新しい巨大な生成を先に始める必要はない。Public 0.500 へ向けた次の投資先は、この分解と基準の結果から選ぶ。

## Q4. 空の U2 の 31 query

**分母に残し、RR=0 とするので正しい。** 空の query は Q/validation/test_ids に残り、予測は全 PAD、metrics は RR を 0 にして主集合の平均へ含める。人工データでもこの経路を確認した。

31 は dev と hold、複数の π の合計である。主指標の 1,198 件から一括して除くなどの扱いはしない。学習には候補行が存在しないが、identity ごとの単位数を数える Q の名簿には残す、という現在の重みの定義とも整合する。

合法的に空になった候補表と、未生成・欠損・失敗した入力は区別する。後者は停止すべきで、空の候補表に置き換えて正常な 0 点に混ぜない。今回の名簿・hash・件数検査は、この区別のために必要である。

## Q5. G0 後の順序

**基準 PEB の seed 11/12/13 → 固定 PE の seed 11 → 結果に基づく内側ループ、に賛成。** 次の運用を固定する。

- 三つの基準は同じ source/config/データで完走させる。σ は同一母集団の主 MRR の seed 間標準偏差であり、標本抽出の不確実性や Public の誤差ではない。3 seed なので粗い推定でもある。max(2σ, 0.005) の下限を維持する。
- 初期 PE の対応先は seed 11 の PEB。11/12/13 の最大値を後から初期対照にしない。平均 ensemble を候補にするなら、別の登録された候補として数える。
- **基準 3 seed は exploit 6 枠のうち 3 枠を使う。** 同じ 48 時間の窓で、その後に新規で使える exploit は原則あと 3 件であり、さらに 6 件ではない。自動 ensemble も枠を使う。
- 固定 PE は規定どおり探索枠 0 件でも、計算費用は 0 ではない。一度だけ作り、CPU 並列数・メモリ・時間の記録に含める。調整した PEB と固定 PE の差を、生成物の純粋な効果とは呼ばない。
- F に対する主差、組の区間、保護層、PE/B の費用を一緒に読み、突破しない原因に応じて残りの枠を使う。e は凍結した最終候補の一回確認まで未開封を維持する。

残る e の技術照合を通した後は、準備を繰り返すより、この順序で基準を測ることを勧める。本レビューは利用者による G0 操作の代行ではない。
