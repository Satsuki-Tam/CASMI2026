# 111 依頼: 自前の対照学習スペクトル–分子採点器(別系統の第二の証拠)を 1 位を守る形で融合する計画

## 根拠
- 今日の結論: 同じ証拠の並べ直し(E-lite)・GL の要約・ICE・データ拡充はいずれも不通過。監査 v2 では主リストの誤りは強い同分子式の decoy で、どの単独証拠も 1/4〜1/3 しか正解側を支持しない → **別系統の証拠**が要る(文献: 系統の違うリストどうしの誤りの相関は 0.03〜0.3)。
- 公開系譜(公開 notebook「LB 0.477」の自己記述、docs 外の Kaggle Code;読んだのは説明と推論コードのみ、重みは使わない): 0.465 の基盤に、Saner Turhaner の **SpectrumCandidateModel**(スペクトル符号器 → 埋め込み Z と FP 予測 P、分子符号器 = 指紋ビット → 埋め込み M;score = cos(Z, M)/T + w_fp·(P·F)/bits、分子のスペクトルごとに採点して平均、マージなし)を RRF 1/(3+b) + w/(3+n) で融合。**leader-safe**(1 位は w 0.25、2〜25 位は w 0.50〜0.75)で 0.465 → 0.468 → 0.472。1 位を自由に動かすと悪化(w 0.50 で 0.448、1.00 で 0.359)、長く学習した重み(40×2000 step)は 0.453 に悪化。
- 104 の t1E(1 位固定 + 2〜25 位を E-lite で並べ替え)は手元で +0.0019(同じ証拠だったため)。別系統の採点器なら 2〜25 位の並べ替えで正味の救済が増える可能性。

## 計画の案(自前実装、公開の重みは使わない)
1. モデル: スペクトル符号器 = 自前の FPNet と同じ前処理・符号器(学習済みの fold-safe FPNet の符号器から初期化 or 小さな新規の transformer)、分子符号器 = 指紋ビット(FPNet の bit 集合)の MLP。損失 = InfoNCE(バッチ内負例 + **同じ分子式の hard negative** を pool から)+ 補助の FP BCE。
2. 学習データ: train のスペクトル(fold-safe: 評価する fold の identity を除外;最初は fold 1 を保留して f1dev / np053f1dev で評価、FPNet の fold 1 と揃える)。
3. 評価: (i) 単独の識別(同じ shortlist 内で正解の順位、同分子式群内の MRR、主リストが誤る行での救済率);(ii) **接続**: v8w7a の 1 位を固定し、2〜25 位を RRF(主順位, 採点器の順位)で並べ替え(104 の t1E と同型、E 窓ではなく全候補)。関門は 102〜108 と同じ主指標と保護。
4. 本番: full_eval と同じ露出条件(パネルの query 取得を除く全 train)で学習し、Kaggle の pipeline に組込み。
