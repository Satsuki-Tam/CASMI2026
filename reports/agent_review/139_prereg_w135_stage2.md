# 139 事前登録(案、2026-10-30 02:2x JST、Claude Code)— W135 段階 2: 生成物の selector(一方策)を学習し、別の世界で全件の差を測る

136 の段階 1 は INVEST(U = +0.0683)。Codex 135 (iii)・(iv) と 137 の素案に沿って、**selector と挿入の方策を一つだけ**登録する。selector の学習・評価の数字は、この登録と Codex の確認の前には計算しない。いま走っているのは、生成(p0 / p60)と、B の生成物の GL の採点だけである(結果は読まない)。

## 1. 方策(一つ)
- P の DB 候補の相対順は固定する。各 query で、B(≤ 50)の生成物から、selector の確率 p̂ が最大の一つ x を選ぶ。
- 挿入の位置 k ∈ {1, 2, 3} の期待利得を計算する(MRR@25 の変化):
  `G_k = p̂ / k − (1 − p̂) · Σ_{r = k..25} q_r · (1/r − 1/(r+1))`。r = 25 の項は 1/25(押し出し)とする。
  - x が真なら P の top 25 に真は無い(構成上)ので、利得は 1/k。
  - x が誤りなら、P の r 位(r ≥ k)の真が一つ下がる。q_r は「P の r 位が真である確率」。
- k* = argmax_k G_k。G_{k*} > 0 なら k* 位に挿入し、そうでなければ P を保持する。閾値を手で選ぶ所はない。
- **q_r**: 学習の世界(π 0 / 0.3 / 0.6 を等重みで合算)の P の実績から、順位 r(1〜25)× 区分の表として推定する。区分は、ライブラリの支持(lib_max ≥ 0.9)/ GL の経路(gl_ok)/ fallback の 3 つ。

## 2. selector
- **モデル**: ロジスティック回帰(L2、C = 1.0、max_iter 2000)。特徴は学習の分布で標準化する。パラメタの探索はしない。
  - 正例が少ない(設計の世界の全体で約 100〜150)ので、変数の少ない頑健なモデルを選ぶ。
  - 行の重みは 1 / (その query の B の件数)。生成物の多い query が学習を支配しないようにする(Codex 135)。
- **行**: 設計の 18 世界(dF1-3・dR1-3 × π 0 / 0.3 / 0.6)の、全 query の B の全生成物。正例 = 公式 key が真。真が生成されなかった query の生成物も、全て負例として残す。
- **特徴**(観測量だけ。真・クラス・P の真の順位は使わない):
  - 生成物: f.z、GL(released、world と同じ runner の設定。欠損は「欠損フラグ + 0」)、MetFrag-lite(b1_frag、query の全スペクトルの最大)、親得点 apsc、親の数、親の由来(train / peer の 2 値)、編集の段数、編集の種類の 5 群(糖、メチル、酸化還元・水酸基、アシル、その他)、off_mass、B 内の f.z の順位、B の件数。
  - 比較: f.z − P の 1 位の fp、GL − P の 1 位の GL(どちらかが欠ければ 0 + フラグ)、MetFrag − P の 1 位の MetFrag。f.z と GL の、DB の shortlist(view の list)+ B を合わせた中での順位の割合。f.z と fp は同じ関数・同じ bit なので、同じ尺度である。
  - query: P の 1 位と 2 位の得点差、gl_ok、lib_max、P の list の件数、analog の最大類似度、peer の構造の数、train 親の数。
  - 生成物には人気度・source の値が無い。その特徴は使わない(未知を 0 と混同しない)。
- **交差検証(開発の推定、記述)**: (dFj, dRj) の 3 組を単位にした leave-one-pair-out。同じ組は π が違っても同じ fold にする。q_r の表も、学習側の fold だけから作る。
- **最終モデル**: 18 世界の全部で学習し、凍結する(係数・標準化・q_r の表の sha を記録する)。

## 3. 確認用の世界(段階 2 の評価。学習・設計に一度も使っていない)
- **母集団**: fold 2 の COCONUT の真(census_fold2)。W135 の設計と selector の学習は fold 1 だけなので、fold 2 はどちらにも使われていない。
  - 既使用(B1 の開発で使った identity)の印は残し、記述として層別する。Codex 136 Q4 の指摘どおり、これを独立確認と呼び直すことはしない。この評価は「W135 の方式の設計・学習から独立な、fold 2 での確認」と呼ぶ。
- **バッチ**: 既存の cF1 / cR1 に、新しい cF2 / cR2 と cF3 / cR3 を加え、3 組とする(w135_batches.py。既存の cF1 / cR1 / cU1 の identity と家族を除いた fold 2 の母集団から作る)。cU1(未使用だけ)は C2 / C3 の補助とする。

## 4. 判断(確認用の世界、凍結した方策 vs P、全件の MRR@25 の差)

- **費用**(下限 ≥ −0.01): C1 の query の Δ(π 0.3 と 0)、C2 の query の Δ(π 0.3 と 0)、π = 0 の全件の Δ。
- **PASS** → Kaggle への組み込み(時間の上限を含む)を別に登録する。**それ以外は NO** とし、記述から律速(到達 / 選別 / 費用)を記録する。結果を見てから特徴・モデル・q_r・挿入の位置を選び直さない。
- **記述**: 挿入率、k 別の件数、C3 の平均 RR、到達した C3 での選別の正解率、cU1、家族 / 無作為、隔離の感度、設計の CV の推定。
