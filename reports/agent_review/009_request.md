## 3. 意見がほしい点

**Q1 候補の構成**: M1 を「v2 + 単調制約」(C2 同等、C1 +0.011)に差し替えるべきか、事前登録どおり plain v2 を維持すべきか(4 変種から eval 群で選ぶ選択バイアスの扱い)。M2 の学習融合は v2_noice(C1 −0.047)だが、M2 では ICE が無いので選択の余地がない。M2 に単調制約を付けるか。

**Q2 ICE の扱い**: 固定規則で寄与なし、学習融合で C2 ±0 / C1 +0.047。Kaggle の 9 時間に収めるため M2 では ICE を外す計画。中間案として「GL 融合後の上位 25 候補だけ ICE を回す」(ICE の計算量 1/5〜1/8)は、評価方法(shortlist 全体の ICE スコアとの整合、z の分布の変化)を含めて価値があるか。

**Q3 shortlist 配分**: FP+prior 200 + prior 50(候補 2 倍、GL のみなら時間は現行の GL+ICE より短い見込み)を M2 に採用。候補が増えると z 分布が変わり順位付けが悪化し得る(Codex 008 §4)ため、v3 の開発集合評価では「新たに回収した分子の利得」と「元から入っていた分子の順位変化」を分けて報告する予定。他に見るべき指標はあるか。

**Q4 locked の採用規則**: 「C2 strict が高い方、差 < 0.01 なら M2」で妥当か。C1 視点はどう扱うか(クラス 1 比率が不明なので主指標にしない方針)。両候補を同時に開くことで locked は使い切りになる。その後の改善(例: v3 の派生)の確認は開発集合のみで行い、最終 2 提出は locked の結果 + LB で選ぶ(W10)という運用でよいか。

**Q5 Kaggle 実行時間**: GL は GB10 で約 140 ジョブ/秒(ジョブ = 候補 × スペクトル条件)。隠しテスト 400 分子 × 候補 ~230 × スペクトル ≤ 8 → 約 50〜70 万ジョブ。T4 を GB10 の 1/3〜1/4 と見ると 3〜4 時間、FP 窓採点・参照類似の CPU 部分(4 CPU)が 1〜2 時間。9 時間に収まる見込みだが、Notebook 実測が無い状態で M2 を提出する際の安全策(GL の時間予算を超えた分子は固定規則 S(1,0,0.5) = FP+prior で埋める、候補数上限)についての意見。

**Q6 LB の読み方**: E0 = E4 v5 = 0.464。B1 v2 Notebook(M1 相当、ICE あり)の LB が出た場合、手元の strict(A 0.671 固定 → 学習で +0.075)との対応をどう読むか。公開 LB の分子数(全体の何割か)が不明な点を踏まえ、「方向のみ」の判定閾値(例: ±0.02 以上を差とみなす)を先に決めたい。
