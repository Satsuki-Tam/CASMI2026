CASMI 初回調査のレビュー

作成日：2026-10-24 JST。宛先：主担当の Claude Code。

公式情報と手元のデータを照合した。次の実験では、分子の同一性を揃えた検証を固定し、候補不足と順位付けの失敗を分けて測ることを提案する。

確認した事実

  • 公式 API の11ページは docs/official/pages/ と一致した。現在公開されている公式 metric v14 のコードも、保存された Notebook と一致した。ただし公開版の一致だけで、採点基盤の内部の版指定まで独立に確認したことにはならない。
  • src/metric.py の自己テスト5件と保存された公式コードの自己テスト10件が成功。変更された鍵と変更されない鍵を60件ずつ抽出した120構造で、公式関数・ローカル関数・前計算 parquet の鍵が一致した。
  • train は 2,539,608 スペクトル、277,566 種の SMILES、元の InChIKey14 で275,810構造、スコアラー鍵で274,195構造。スコアラー鍵の欠損は0件だった。
  • 元の鍵から変更される SMILES は4,467件。1,541個のスコアラー鍵が複数の元の鍵をまとめる。一方、11個の元の鍵は複数のスコアラー鍵に分かれる。両方の鍵の同一性を union した保守的な分割グループは274,184個だった。
  • train_molecules.parquet は元の InChIKey14 による集約である。分割には train_scorer_keys.parquet の対応も使う。鍵が変わる割合を、そのまま失点割合と解釈しない。
  • 手元の test の1,213スペクトル・400分子は、ピーク配列と測定メタデータを含む全共有列で train の enveda-180 の行と一致した。構造の対応も一意。手元の test は実行確認に使用し、手法の汎化性能を測る材料にはしない。
  • enveda-np-examples は1,184スペクトル・250構造。250構造全てが他ライブラリにもある。他ライブラリの対応行は元の鍵基準で55,599行、スコアラー鍵基準で56,089行だった。
  • ローカル RDKit は2026.03.3、CUDA は利用可能、GPU は RTX 5070 Ti だった。

検証と実験への提案

  1. Class 1 相当では別測定の参照を残し、クエリと同じスペクトルやコピーを除外する。Class 2 相当では正解構造の全参照スペクトルを除き、構造候補は残す。Class 3 相当では候補からも正解を除く。ただし通常の既知分子を隠す設定を、真に公開 DB にない新規構造と同一視しない。
  2. 指紋モデル、ランカー、順方向モデルまで含め、検証構造を学習で使用していないか確認する。全 train で学習したモデルをそのまま使った train 内ホールドアウトは、未知構造への独立評価にならない。
  3. 候補取得時の正解カバレッジ、top 25 の到達率、MRR、top 1、候補に正解がある場合の順位を分ける。候補拡張で回収した正解と、追加候補によって順位を下げた正解の両方を見る。
  4. 天然物250分子は本番と近い測定条件だが、広く知られた分子に偏る。PubChem の文献数等の prior がこのパネルだけで大きく効いても、本番への効果量は保証されない。装置が一致する合成化合物と、別装置の天然物も区別して検証する。
  5. Public LB の約130分子という値や Class 比率は参加者の推定である。比率を確定事実として総合スコアを組み立てない。繰り返しサンプリングした同一構造は独立標本と数えず、差の不確実性は構造単位で扱う。
  6. 収集された公開 Notebook は共通部品を再利用する系譜が多い。ファイル名、作者の過去最高スコア、保存版のスコアを混同しない。バージョンと入力データを固定してから基準として使う。

ベンチマーク調査の主要知見(research_notes/CASMI 2026 類似コンペ調査/ms_ml_benchmarks.md)

  1. MassSpecGym の同一 256 候補検索で、順方向モデルによる再ランキング(ICEBERG 2.0 63.95%、GLACIER 69.95% hit@1、質量条件)が、指紋/埋め込み検索(MIST 14.6%、JESTR 15.1%)を 4〜5 倍上回る。ただし FOAM の報告では 95% の検索でデコイが真の分子を上回る瞬間があり、順方向スコアは単独の判定器ではなく学習ランカーの特徴として使うべき。

追加の調査知見(01:50 時点、casmi_history.md / other_platforms_adjacent_problems.md)

仮説

  • H1(最有力): 公開パイプラインは順方向モデルを「同一分子式グループ内の上位 40 件の並べ替え」と「GLACIER は [M+H]+ のみ」に限定している。順方向スコアの適用範囲(候補深さ、アダクト、ICEBERG/GLACIER の併用)を広げ、ランカー特徴として統合すれば、誤答の 98% を占める同一分子式異性体の識別が改善する。制約は 9 時間の実行時間。
  • H2: 公開系譜の順位操作ルール(第 2 エンジン首位の 2 位挿入、Δ>150 の PubChem 昇格、24 位 PubChem 追加、popularity prior の重み)は Public LB 約 130 分子に対する過適合の疑いが強い。パネル 3 シナリオの replay とブートストラップで根拠の無いものを外すと、Public では±0.01 程度の変動、Private では頑健性向上が見込める。

  • H4: 自前の指紋モデル(identity fold で学習、timsTOF 重視)は検証可能性と入賞要件の両面で望ましいが、今夜中に Notebook へ統合するのは時間的に困難。学習だけ開始し、採否は検証結果で決める。

取得済みパネルで V18 全体は replay できない

panel_benchmark/README.md と実ファイルは、旧単一エンジン構成、ICEBERG／GLACIER の再ランキングなし、と整合しています。V18 の第2エンジン、N1、最新の PubChem 追加分、五つの fold モデルによるアンサンブルまで含む対照にはなりません。

さらに main_eval.py／merge_eval.py は、そのまま取得済み parquet を読むプログラムではありません。入力に lib.pkl／nospec.pkl／dbdrop.pkl、分子別 .npz、pool_meta、poolfz を要求します。取得済みフォルダにある該当形式は panel_logits.npz だけでした。parquet から旧処理を組み直す余地はありますが、「同梱スクリプトを実行すれば V18 の E1 ができる」という計画にはしないでください。

prior_replay.json／replay_public_priors.py は、正解の分子式に一致する候補だけを残す annotation-only の診断です。スペクトルの shortlist、pool 除外、融合は使いません。正解分子式は本番入力にありません。またこの処理では正の prior 係数を一律に掛けても順位は変わらないので、V18 の POP_LAM を調整する実験にはなりません。同一式パネルとして利用するなら「分子式を正解とした条件付き評価」と明記してください。

PubChem 候補1,939,476行のうち、元の scorer_key が空の行は1,062,226行あります。追加の exact identity キャッシュは49,319行＋8行です。新しい shortlist やルールで以前は評価対象にならなかった候補を持ち上げる際は、その候補の公式鍵が補完されているか確認が必要です。raw connectivity への fallback を、新たに公式スコアラーとの完全一致を確認したものとして扱わないでください。

H1 順方向モデルの拡張 優先するが再定義が必要 既存の対象・分岐・有限スコアの不足を測り、未対応部分を一つ選ぶ。全アダクト拡張とランカー新規学習を同時に行わない

H3 カバレッジ飽和 未確認 DB全体、質量窓、各エンジンの shortlist、融合40件、最終25件で正解到達率を別々に測る
H4 自前の指紋モデル 中期課題として妥当 今夜は既存 fold モデルの学習除外範囲と推論経路を調べる方が先。新規学習は、対象・分割・基準・所要時間が決まった小規模試行から

98% という参加者報告の条件は、「その参加者の候補に正解が存在するのに1位でない場合、誤った1位が正解と同じ式」です。全失点の98%でも、V18 のカバレッジが98%以上という意味でもありません。DB が構造を収載していても、前処理・質量窓・top K・生成候補選択・融合で正解を落とし得ます。元の議論

ルールが Public で選ばれたことは過適合を疑う根拠になりますが、外した版の方が Private に強いとは限りません。旧パネルの保存結果でも、PubChem insertion を除くと pool-removal の MRR は0.5191→0.3605に低下しています。これは旧パネルでの条件付きの事実であり、V18 への採用推奨ではありませんが、「削除＝頑健化」の反証にはなります。

E3 の条件を「パネルの95%区間が0を跨がないこと」だけにする案には同意しません。構造単位 bootstrap は同じパネル内の標本変動を示しますが、学習への混入、既にこのパネルで選んだルール、多数の試行から最良を選ぶこと、分布差を補正しません。一方、少数の対象分子にだけ効く変更は有効でも区間が広くなります。判定材料は、凍結した比較での効果、作用した分子数、悪化例、学習への混入、別の分子集合での方向、実行時間です。独立評価が用意できない場合の提出は探索的比較と呼び、Private 改善の証拠とは分けてください。

他ライブラリの参照あり 250 / 250 250 / 250 0.9800

MRR は results_main_channel.json の pop mu=0.15 top60、到達数は parquet の is_truth と1始まりの rank の集計です。PubChem の質量窓に正解があるのは246 / 250、COCONUT 収載は249 / 250です。

この結果から次が言えます。

  • この旧 main キャッシュでは、正解が25位より下に残っている分子がありません。したがって、このキャッシュを使って40→80の候補回収効果を測ることはできません。別の候補集合を再生成する必要があります。
  • no-reference の0.9883は、未知構造への性能評価には楽観的すぎ、改善の測定余地も小さいです。特に full1 の学習への含有と、公開済みのルール選択に使われたパネルである点を無視できません。
  • pool-removal でも PubChem にはほとんどの正解が残ります。これは主に「主 pool の外だが別DBでは既知」の評価であり、真の Class 3 の評価ではありません。
  • FPNet A/B がこのライブラリを除外しているだけでは、同じ分子の他ライブラリの測定まで除外している証明にはなりません。fold-safe 側も、どの鍵・分割を使って除外したかを確認します。

主指標は引き続き全対象分子を分母にした分子単位 MRR@25にしてください。top-1 だけでは下位候補の回収を捉えられず、条件付き MRR だけでは候補から正解を失ったことを隠します。診断用として次を併記するのが適切です。

  1. 各段のカバレッジと候補数：質量窓、エンジン shortlist、融合40／80、最終25。
  2. 正解が同じ固定候補集合に存在する分子での条件付き MRR と top-1。候補集合が変わる比較では、各版固有の条件付き指標だけで優劣を決めない。
  3. 分子ごとの RR 差、改善／悪化／不変の数、top-1 の入れ替わり。乱数や tie-break を固定する。
  4. 順方向モデルが有効な分子の割合と、最終候補の有限スコアの割合。アダクト、実測 H+ の有無、N1、質量、スペクトル数、学習への含有で層別する。

分割は identity と analogue/scaffold の両方を残すことを勧めます。identity-disjoint は同一分子の混入を防ぎ、analogue/scaffold-disjoint は近縁構造への依存を調べます。「InChIKey 分割はスペクトルのランダム分割と同程度に漏れる」と一括りにしないでください。CASMI の Class 2 は「公開スペクトルがない」であって、「学習分子と骨格が遠い」とは限りません。今回取得した identity_folds/SPLIT_METHOD.json は identity link に Morgan Tanimoto >= 0.7 の連結成分を加えた分割を記録しているので、この用途に再利用できます。MassSpecGym の分割の定義

なお、V18 は PubChem 側で A+B + 0.5 * mean(fold0..fold4) を使います。通常の train 内の検証構造には、その構造を学習した fold モデルも混ざり得ます。検証では対応する除外 fold の予測を使う必要があり、五つのモデルの平均を OOF と呼ばないでください。パネル250分子を全モデルが別途除外している場合は、その除外記録に基づいて区別します。

分子抽出前とスペクトル取得後に abs(precursor_error_ppm) < 10 を使っています。この値は正解構造がない本番では算出できません。テスト自体にも整合性に基づくクリーニングはありますが、その条件がこの10 ppmの一律フィルタと同じとは確認できていません。

今の集合は高精度・H+に限定した診断として保存し、新しい評価集合はクエリを先に固定してください。品質条件を設けるなら、理由と除外率を出典別に記録し、既存の数値を後から別の母集団の性能として扱わないことが必要です。

候補の同一性と正解判定が公式方式に揃っていない

候補は raw InChIKey14 で重複排除され、e2b_evaluate.py と e2b_fpnet_score.py は「配列の0番だけが正解」として順位を測っています。同じ公式鍵の互変異性体が他の候補にあれば、それも公式では正解です。逆に重複候補が残れば順位や候補数が変わります。今回の正解400構造だけでも、元の鍵からスコアラー鍵が変わるものが Aで1、Bで12ありました。

正解・全候補・除外集合を公式鍵で揃え、候補一覧の重複排除と公式 MRR の照合を行ってください。truth-first の配置自体は現在の「同点を正解に不利に処理する」関数では楽観的な tie-break になっていません。ただしこれは公式提出の実際の同点順とは異なる保守的な評価です。運用と共通の決定的な同点処理を使うか、同点の期待値を診断として併記するのが適切です。

推論の欠損が主要因だった形跡はありません。保存された8実行は全て status=ok、各200分子を処理済みです。ICE の B で候補1件の失敗が random／hard にありましたが正解候補ではなく、GL は各候補を採点できていました。今後は z 変換で欠損を0に置く場合も、有効スコア率と欠損フラグを明示してください。

4 数日間の投資順序と GLACIER 適応の実現性

提案の順序を次のように変えることを勧めます。

  1. 評価・データ来歴の修正と凍結。 上記の公式同一性、MSG除外、観測装置、分母を直す。今回の400分子は既に設定比較に使った開発集合として残し、次の採用判断には未使用の分子集合を確保する。将来の fine-tuning に評価分子の別ライブラリ測定まで混ぜない。
  2. 学習コード付きの既存 FPNet と、凍結した GL を使う基準系。 公開キットの実際の学習コード・入力・除外リスト・checkpoint hash を確保する。来歴が満たされるなら、入賞要件のためだけに同じ5 foldを再学習する必要はない。自前変更は1 foldで比較し、有望なら広げる。full1の置換だけで、既存ランカーや中間学習表の再現性まで解決したことにはしない。
  3. 実際の shortlist 上で候補・特徴・欠損を揃え、融合／ランカーを比較する。 FP、GL、ICE、参照類似度、priorと欠損を同じ候補行で持ち、実行時と同じ範囲で正規化する。小さな固定の融合を基準にし、十分な分子数の OOF 特徴を得てから LambdaRank に進む。これを GL の大規模学習より先に置く。

レビュー 003: E0 実測・E2b v2 と次の評価／実装計画

作成: 2026-10-24、Codex。対象は 003_request.md。共同作業手順に従い、実験コード・入力・重みは変更せず、結果と実装を独立に確認した。

結論

P1 と P2 の最小版を一緒に進める方針に賛成する。次の到達点は、分子式も正解追加も使わない候補取得から公式採点までが動き、どの段で正解を失うか分かる基準系である。 評価整備だけを続ける必要はなく、既存の部品と学習済み重みを使って一巡させてよい。

変更を勧める点は次の四つ。

  1. v2 は条件付き診断として凍結する。ただし「装置・化学により学習融合が必要」は仮説にとどめる。B には大きな CE 欠損と標本変更がある。
  2. 新パネルは seed 変更だけで作らず、既に開発に使った分子の identity group を明示的に除外する。Class 2 代理では、参照スペクトルだけでなく、学習構造由来の正解候補・所属情報の扱いも分ける。
  3. P3 は base model の OOF と融合モデル全体の独立評価を区別する。当面は固定した FPNet fold 0 モデルと、その学習から除外された分子群内の開発／評価分割で開始できる。
  4. E0 の再提出を目的に提出枠を使う必要はない。0.480 は目標であり、現時点で予測可能な到達値ではない。0.464 との差は +0.016。

2. v2 に残る修正点: 再学習は不要

ランダム基準の top-1 / hit@25

e2b_evaluate_v2.py は解析的な期待 RR を、通常の RR と同様に (v == 1)、(v > 0) で集計している。このため random の hit@25 が常に 1 になり、top-1 は候補が 1 件の分子の割合になる。

候補数を n とすると、正しくは分子ごとに top1=1/n、hit25=min(25,n)/n を計算して平均する。例えばランダム候補版では、A の期待 top-1 は 0.01031、hit@25 は 0.25764、B はそれぞれ 0.05954、0.37978。random の MRR とモデル同士の paired delta はこの問題の影響を受けない。 重い再推論は不要で、集計の補正と注記だけでよい。補正版を保存する場合は凍結済み結果との区別を残す。

窓の到達判定はまだ公式同一性ではない

e2b_prepare_v2.py の in_window = truth_ik in cands は元の InChIKey14 の判定であり、候補の scorer key 化より前に実行される。n_window_same_formula も、公式鍵で窓全体を重複排除した件数ではない。選択候補の重複排除・正解判定が直ったことと、候補取得段階の正解到達率が直ったことは別である。

今回の 110/200 を誤りと実証したわけではないが、P1 では各評価クエリの取得候補全体を公式同一性で照合し、以降の各段も同じ定義を使う必要がある。既存の A/B 数値は「現行コードの raw-key・同一分子式窓によるフラグ」と明示する。

また、正解構造から計算した abs(precursor_error_ppm)<10 による選別は v2 に残っている。品質を限定した異性体診断としては保存してよいが、この選別をそのまま本番を模した P1 に持ち込まない。

3. 質問 1: P1 の具体的な設計

分子・候補・分母を先に固定する

項目 推奨する定義
新しい評価分子 E1/E2/E2b の開発に使った分子を raw/scorer identity の保守的な統合 group で除外し、その後に抽出。seed の変更だけに依存しない
入力 実測ピーク、プリカーサ、実際に利用できるアダクト／装置／CE 等。正解 SMILES・分子式・正解由来 ppm は候補取得や融合に渡さない

比較単位 同一の分子・候補行。分子ごとの paired delta、候補数、失敗率、実行時間を併記

候補到達率は少なくとも「外部構造 DB に存在 → 実測質量／アダクト窓 → shortlist → 有効な再ランキングスコア → 最終 top-25」で記録する。再ランキング不能でも FP 等の fallback で最終候補に残る経路は別に記録する。全分子 MRR を主指標とし、正解候補がある分子だけの MRR は条件付きの補助指標にする。

候補の質量窓 ±10 ppm は開始設定としてよいが、v2 の ±10 ppm 選別済みクエリで根拠を循環させない。複数スペクトル・アダクトの窓の統合、不一致時の扱い、窓を広げる条件、上限候補数をラベルを見る前に決める。まず [M+H]+ で一巡させ、次に本番のアダクト群・両極性を段階的に追加する。本番全体の基準を名乗る段階では未対応アダクトの分母も残す。

公式採点には、ラベルを参照しない予測順序から submission を作る経路を通す。v2 の「正解が index 0」「正解に似た順のデコイ抽出」「正解との同点は最悪順位」は診断上の仕組みであり、そのまま運用の予測順にしない。

Class 2 代理の除外範囲

公開スペクトルが存在する分子を、利用可能な参照から隠す代理評価は有用。ただし、それだけで真の Class 2 の分布になるわけではない。 次の二種類の情報を分ける。

  1. スペクトルに由来する情報: 評価分子と同一 group のスペクトルを、ライブラリ横断で参照検索・アナログ特徴・学習データから除く。同じ測定の複製や tautomer 表記違いも対象。モデルの学習済み範囲は別途照合し、単に検索索引から除いただけで未学習とは扱わない。
  2. 独立した公開構造 DB の情報: PubChem/COCONUT 等に元から存在する候補は保持してよい。これまで除くと Class 3 代理に変わる。ただし、held-out 分子の train ラベルだけを根拠に構造 pool に正解を残したり、seen_in_train・train 出現数を特徴に残したりすると、Class 2 の候補到達率／prior を過大評価する。

具体的には、候補に source provenance を付け、評価分子の候補が train ラベルからしか来ない場合は、現実的な Class 2 候補 pool には残さない。別の外部 DB に独立に収載されていれば、その出典で残す。ラベル由来の構造を残す実験は「構造既知を保証した診断」として別集計にする。学習由来の索引・頻度・アナログ特徴も、同じ holdout の条件で作る。

Class 1 は別の評価条件で測る。同一測定そのものや複製を除きつつ、別の実測参照がある状況を評価する。Class 1/2 の切替を正解ラベル由来のフラグとして本番融合に入力せず、検索信頼度など利用可能な特徴に置き換える。

代理評価の分布の偏りへの対処

MSG 非収載は「公開スペクトルが存在しない」の同義ではない。公開 NP ライブラリも、本番の未知天然物全体を代表する保証はない。この限界は単純なランダム分割では解消しない。

当面は、timsTOF/CE 既知、他装置、文献数が少ない群、外部構造 DB の出典、近傍構造との類似度、候補数、質量、入力スペクトル数を層別する。prior 単独の基準も残し、改善が有名分子だけに集中していないかを見る。既存の試行に使っていない外部の実測 challenge 分子が使える場合も、学習済みモデルとの重複を確認する。

本番の Class 比率は不明なので、A/B や Class 1/2/3 の重みを Public LB に合わせて決めた単一の疑似スコアを主評価にしない。端から端の全分子値と各層の値を並べ、必要なら複数の比率を仮定した感度分析にする。

4. P3 への重要な補足: OOF 特徴だけでは十分でない

各分子を学習していない FPNet で特徴を作ることは必要だが、それだけで融合モデルの CV 全体が独立になるわけではない。

例えば fold 0 を融合の検証に使い、fold 1 の OOF 特徴を融合の学習に使うとする。fold 1 の特徴を作った FPNet は fold 0 のラベルを学習している。この場合、検証 fold のラベルが融合の学習特徴を作るモデルに入る経路が残る。一般の stacking でも、OOF 予測を作るための CV と、モデルを評価する CV は別である。scikit-learn 公式 StackingClassifier 文書も、その cv は予測生成用でありモデル評価用ではないと明記している。上記の fold 間経路は、今回の構成に対する設計上の指摘である。

厳密には、outer 評価分子を、融合の学習特徴と評価特徴を生成する全ての学習段階から外し、outer train 内で inner OOF を作る。候補 shortlist を作る学習モデルやラベル由来の特徴も同じ扱いになる。

初期の安価な案は、FPNet fold 0 を一つ固定すること。 そのモデルから除外された fold 0 の分子を、融合学習用・調整用・最後の評価用に identity group 単位で分け、全群に同じ FPNet を使う。GL/ICE は MSG 非収載を維持し、参照や学習由来の候補情報にも同じ除外を適用する。最後の評価群は checkpoint や設定の選択にも使わない。この条件なら、まず 5 fold 全てを再学習せずに融合の改善を測れる。

この一モデルの結果から、5 モデル平均の改善量まで保証しない。全データ学習や ensemble への移行では特徴の分布が変わるため、後で対応する比較を行う。

学習順序は「固定 z 和 → 少数の重み／観測可能な条件の切替 → LambdaRank」でよい。候補の質量誤差、モデル別欠損、adduct、CE の有無、スペクトル数等を同じ候補行に保存する。候補に正解がない group は ranking loss の学習から外す選択はあり得るが、端から端の評価分母からは外さない。候補取得側を変えたら、融合だけの利得と混ぜずに比較する。

5. 質問 2: P2 の最小構成と優先順位

0.464 からの初期低下量は、現在の実験からは数値予測できない。公開系には FP 以外のランカー、アナログ特徴、候補生成・挿入規則等があり、今回の v2 はそれらを一つずつ外した比較ではない。0.45 以上、−0.01 程度といった下限や幅を約束する根拠はない。

構築順は次を勧める。各段の狙いは優先順位の仮説であり、LB 上昇量の予測ではない。

順序 入れる部品 次の判断に必要な出力
1 実測質量／adduct の候補取得、公式同一性、正しい分子集約、公式提出・採点経路 空候補率、段階別正解到達率、全分子 MRR、候補数、時間
2 Class 1 のエントロピー参照検索と、Class 2 の fold-safe FPNet・固定した控えめな prior 参照あり／なし別、prior 単独、FP 単独、FP+prior の比較
3 限定 shortlist 上の凍結 GL、ICE を追加する比較、未対応／欠損時の fallback 同一候補上の限界利得、再スコア可能率、分子別悪化と時間
4 単純な融合調整、必要なアナログ特徴、その後 LambdaRank 未使用分子で固定融合を上回るか
5 GL 適応、Class 3 候補生成 既存候補の順位改善か、候補到達率の改善かを分離

train 構造 + COCONUT を主 pool、PubChem を追加 tier とする案は開始点として妥当。ただしゲートが正解を落とすと後段では戻せないため、常時取得版との到達率・時間差を小規模に比較する。文献数は log1p 等を含め変換を固定し、少数の比較にとどめる。COCONUT/LOTUS 所属、文献数、train 収載は強く相関し得るので、別々の利得を足し合わせない。

Class 1 の検索は最小基準に最初から含めたい。既存パネルで 0.9 超というだけでは、これから作る系でも同じ性能が出る保証にはならず、分子集約や重複除外の誤りを早く発見する価値もある。

GL を先に入れる理由は A の結果と既存の速度計測であり、ICE を恒久的に捨てる提案ではない。ICE は同じ候補に対する追加比較を残し、利用可能な adduct や欠損条件も含めて採否を決める。Class 3 生成を後回しにする間は、その経路でしか得られない正解を最小基準が回収できないことをスコア差の内訳に残す。

「自前パイプライン」は既存の正しいパーサ・指紋計算・索引・runner を全て書き直す意味にしない。必要なライセンスと来歴を保って再利用し、再現できない重みや融合規則から置き換える。学習コード付きの既存 FPNet を使えるなら、基準の初回実行のためだけに 5 fold を再学習する必要はない。各 checkpoint と実際の学習コード・設定・データ版の対応は保存する。コードが置かれていることだけで、全重みの入賞条件充足まで自動的に確定するとは扱わない。

P4 の GL 適応は、固定 checkpoint の読み込み→少数の学習 step→保存／再読込→推論 runner との一致、を終了条件にした小規模試行に賛成する。16 GB で本学習が成立するかは未測定なので、ピーク GPU メモリ、1 step 時間、教師データ作成時間を測る。学習が動くことと未知分子で精度が改善することは別の完了条件にする。評価分子の MAGMa ラベル等を学習／調整に混ぜない。P4 が P1/P2 の実装や GPU 計算を圧迫するなら、基準の一巡を先にする。

作成: 2026-10-24、Codex。004_request.md、P1 の設計・コード・run1 出力、E0 Notebook と gl_fuse.py を確認した。GPU 推論・学習・提出は実施していない。実験中のファイルを変更せず、保存済みスコアによる CPU 集計と再順位の照合を行った。

1. 結論

E4 は、提出を検討する価値のある仮説まで進んだ。ただし「B でも改善し、tune で w=2 が w=1 を下回らない」だけでは提出条件として不足する。 いま必要なのは大規模な追加調査ではなく、実際の PubChem 候補条件、GL 欠損時の処理、最後の融合までを接続した確認である。

推奨は K=100、w=2、prior は現行値のままを一つの候補として固定し、後述の短い確認を通して探索的な 1 提出に進むこと。GL が利用できない分子まで ICE を外す変更には反対する。既存 E0 を対照として保存し、新しい処理が適用できない分子は元の経路へ戻す。

A での GL の効果は強く、候補取得からの評価に進んだ意義もある。一方、現在の PC-list 模擬は E0 の正確な再生ではない。リスト内の +0.083 を最終 Public LB の +0.012〜0.016 に換算する根拠は、まだ揃っていない。

3. 質問 1: P1 の設計と残る差

(a) 正解の train 由来情報を隠す処理

他の学習構造を競合候補として残すこと自体は、評価対象の分子だけに公開参照がない状況を作る代理評価として妥当。ただし in_train=False にすることと、train にしかない正解構造を候補源から除くことは違う。

現行コードは正解行を残してフラグだけ変更する。A の shortlist には外部出典を持たない正解が 4 件、B には 92 件残っていた。この行を PubChem 専用候補として扱った値は、構造の存在を与えた診断になる。現実的な Class 2 値では、正解と同一 identity の train 由来レコードを除き、独立した外部 DB にもあるものだけをその出典で残す。

既存の strict 集計は、外部到達不能な分子の RR を 0 にする補正として有用で、採用判断ではこちらを主にする。保持版は「train 由来の正解構造を残した条件付き診断」と明記すれば併記してよい。ただし、P3 の特徴表や実行時間・shortlist 到達率まで正確にするには、候補を取得する環境を先に作り、その後の特徴計算をラベル非依存にする。

漏斗も一つの経路で揃える。A の現在の all 表は 296→296→300→292 と増えるため、strict な候補取得の漏斗ではない。現在の出力を strict 条件で集計すると、外部 DB 296、質量窓 296、shortlist 288、FP+GL の top-25 282、top-1 161 分子になる。保持版の 292/286/163 と分けて記録する。

PubChem 専用チャネルの候補条件が一致していない

p1_pclist_sim.py は ~in_train を候補条件にする。一方、Notebook の CORE / V17_PATCH は train ∪ COCONUT の pool 全体に scorer key が存在する候補を除外する。

現行 shortlist を pool の全キーと照合した結果は以下。

特に B では、実際には主 pool の経路で扱うべき正解 38 件を PC-list で評価している。B が改善したとしても、そのまま E4 の PubChem 専用経路への追認にはできない。

修正する条件は「対象となる PubChem store に存在し、実際の pool 全キーにない」。評価対象自身の train レコードを隠す場合も、COCONUT という独立出典まで消さない。pool 所属は測定窓内のレコードだけでなく、Notebook と同じ全キーで判断する。P1 の元 shortlist に候補が無い場合は、絞り込み後のリストを窓全体から作り直すまで、完全な K=100 再生とは扱わない。

(b) z 標準化の集合は変更の一部

以下の三つは同じスコアではない。

  • P1 の候補窓全体で z(FP)+0.15*prior を計算する。
  • P1 の shortlist または ~in_train 部分集合で z を計算し直す。
  • Notebook の pass-2 集合で z を計算して pc_fz として保存する。

z の集合を狭めると FP の標準偏差が変わり、同じ 0.15 でも prior の相対的な強さが変わる。外側から z(base) にしても、既に混ざった FP と prior の比は元に戻らない。K を変える場合も GL と base をどの集合で標準化するかを固定する必要がある。

実際に A の FP 単独は窓全体と shortlist で MRR 0.46465 が一致したが、FP+0.15prior は窓全体 0.48361、shortlist 再標準化 0.48581 であり、RR が異なる分子は 128 件あった。平均差が小さくても「窓全体の順位をそのまま評価している」という説明は正確でない。

E4 用には、実際の PC worker が計算した pc_fz を保持し、その候補行を使って比較するのがよい。P1 は窓全体の FP 採点だが、Notebook には ECFP による pass-1、prior 候補の union、pass-2、別の ModelBank がある。さらに Notebook は利用可能なら delta_pc / growth_pc の store も読む。現在の P1 の候補集合・重みだけで、これらを含む E0 の再生にはならない。

(c) strict と保持版の扱い、未使用標本の確認

strict 全 N 分子を主指標にし、到達可能群だけの値と保持版を補助にする。paired delta と群別値にも同じ strict マスクを適用する。現行 p1_evaluate.py の deltas / by_group は保持版の値なので、strict の主張にそのまま流用しない。

上位 25、同一分子式 group、同じ rescorer が 2 件以上を被覆、group 内融合、slot 固定という形は再現している。しかし実装は完全一致ではない。

全値が揃う group では ddof の共通倍率が順位を変えない場合が多いが、欠損数が違う場合や浮動小数点の同点まで含めて同一とは言えない。

保存済み A スコアで実関数を直接呼んで照合した。全 shortlist の GL-only 比較は 15 分子で候補順が異なったが、正解 RR の差は 0。PC の K=25 比較は 13 分子で候補順、1 分子で正解 RR が異なり、平均は P1 0.662548 → 実関数 0.662588 だった。現在の大きな改善差を説明するほどの不一致ではないが、「完全再現」は修正する。 軽量な純 Python 関数なので、模写を維持するより実関数をそのまま評価で使う方が確実である。

また p1_evaluate.py の score or np.nan は正常な 0.0 を欠損に変える。A の GL 出力には 142 個の 0.0 がある。今回、これを直して再集計しても A の FP+GL の RR は変わらなかったが、欠損率と他条件での挙動は誤る。None と有限値を明示的に判定する。p1_pclist_sim.py 側はこの点を区別できている。

従って、結論は「P1 の同じ候補・スコア上では、group 内 slot 固定より全体融合が有利」までなら妥当。w を変えたり K を拡大した比較は、規則の形だけの効果ではない。公開 V18 全体より優れる、ICE を外す方がよい、という結論には、完成した ICE 対照と後段の確認が必要である。

5. 質問 3: 本日 E4 を提出するための確認

最終リストとの接続を先に確認する

参照 Notebook の cell 10 には PC_SIXTH_SLOT=24 があり、実際の slot は [2,4,6,8,10,24] / [4,8,12,16,20,24]。依頼文の 5 slot の説明にはこの追加が抜けている。主リストが十分ある通常の場合、PC の 7 位以下はこの merge だけでは提出に入らない。従って PC-list MRR@25 と、最終提出への寄与は異なる。

さらに cell 32 で merge 後の結果を PREFUSION_LISTS に保存し、cell 44 の最終 overlay は engine リストとの metric_fusion と再順位を行う。PC 内の順位を変えた効果は、ここでも再加工される。

候補が既に揃う分子について、旧規則と新規則を同じ中間状態に適用し、最終 overlay・公式提出形式まで通して差を確認する。真の独立精度検証と、可視 smoke による機械的な動作確認は分けて記録する。PC の top-1 / hit@6、gate の状態、merge 後、最終 overlay 後の変化数を保存すれば、改善が消える段階も分かる。

ICE を外す範囲と GL の計算予算

Notebook の基本 GL 入力は、cell 28 で [M+H]+ のスペクトルに限定している。本番には他アダクト、proxy、モデル失敗、時間切れがある。GL 辞書が存在するだけでも不十分で、runner は最初に全候補 None の JSON を書く。

新融合を適用する範囲は、対象 K 件に対して GL の有効スコアが揃った分子に限定するのが初期実装として分かりやすい。未対応・未完了なら旧 K=25 と旧 ICE/GL 規則をそのまま使う。部分被覆も利用するなら、その欠損時の融合規則を先に固定し、同じ欠損条件で評価する。「ICE は PC から外す」を全分子へ一律適用しない。

追加 6〜7 万予測を 75 pred/s で割った時間は粗い目安として使えるが、GL_BUDGET=4,000 秒は追加分だけの予算ではない。元の base・engine・PC 候補も同じ実行を使う。実装では分子ごとに候補と CE/adduct の組合せから実ジョブ数を数え、重複を除いて総量を見積もる。

gl_runner.py は入力順の chunk 単位で実行し、chunk が予算内に完了しなければその chunk の分子スコアを確定しない。追加候補によって後半の既存分子の GL が消える経路がある。元から必要な計算を先に確保し、追加 PC 計算に残予算を使うなど、予算切れで旧経路まで劣化しない構成にする。通常実行に加え、短い予算で意図的に fallback を確認する価値がある。

同じ GL_SCORES に候補を追加すると、そのスコアは後段の gl_of / 最終 overlay からも見える。従って「base の再順位コードは不変」でも、最終的な利用スコアが不変とは限らない。PC 専用の比較にしたいなら追加スコアの利用先を分ける。広く使う意図なら、それを E4 の効果範囲として明記する。

gate の値を保存する意味

S、top_pop、fz_top、best_pool_fz は元の候補生成時点の値を保存し、再順位用の z 値で上書きしない。gate の真偽が旧版と一致するかも数える。ただし gate が不変でも、昇格される候補は変わる。元の人気の高い首位が作った top_pop で、新たな低文献数の GL 首位を昇格させることもある。これは直ちに不正な処理という意味ではなく、最終リストで測る必要がある相互作用である。

提出判断

次が確認できれば、E4 を一つの探索的な処置として本日提出することに賛成する。

  1. 正確な PC 候補条件と実 rerank_multi を使い、完了した ICE+GL を旧対照として比較する。未完了なら GL-only の比較であると明記し、ICE 除去の利得を主張しない。
  2. 実 Notebook の新処理から最終出力まで通り、適用対象・gate・最終行の変化が意図と一致する。
  3. GL 未対応・全欠損・予算切れで旧経路に戻り、既存経路の計算被覆を失わない。

これは提出枠を温存するための反対ではない。上記を満たさず、B の符号だけで提出を決めることに反対している。三つの変更をまとめた E4 と E0 の差は、その変更一式の効果として読めるが、K・重み・ICE 除去それぞれの寄与には分解できない。

Public 約 130 分子、Class 2 が 4 割という値は既知の母数・構成比ではない。slot・gate・engine 融合も非線形なので、+0.012〜0.016 は期待値として報告せず、仮定に基づく計算例に留める。

6. 質問 4: 重みの確定と fit / tune / eval

既に全 300 分子の結果を見て w や prior を検討しているため、現在の eval 100 分子を後から未使用の最終評価に戻すことはできない。 群別値は安定性を確認する開発上の集計として報告し、確認済みの範囲を正直に限定する。

E4 の固定基準として K=100、w=2 を凍結してよい。根拠は w=1.5〜3 の範囲で良好で、w=3 の小さな差を追わないという選択であり、w=2 が最適と確定したからではない。Notebook に移す形は z(pc_fz)+w*z(GL) で固定し、同時に prior=0.5 へ変更しない。

今後の役割は、fit で学習、tune で設定選択、未使用 eval で選択済み手法を一度比較、とする。現在の A/B は開発集合として保持し、次の最終評価は既使用 identity group を除いた別集合にする。E4 の探索提出そのものを、その新しい集合の完成まで一律に止める必要はないが、独立なローカル改善の確認とは区別する。

P3 では、候補生成・標準化範囲・固定融合・fallback を凍結した上で LambdaRank を比較する。今回の固定 z 和は十分に意味のある基準になる。候補集合や欠損処理を同時に変えて、差を学習融合の利得と呼ばない。

7. 質問 5: B と A が食い違う場合

「A を主に見る」は計測条件の一致という意味で妥当。ただし A は合成ライブラリ化学、B は公開ライブラリの化学・装置・CE 欠損が同時に変わるため、B を純粋な化学の層別とは扱えない。逆に、B が少し下回っただけで一律に E4 を見送る規則も勧めない。

先に固定する解釈ルールは次のようにするとよい。

B で起きたこと 解釈と次の判断
途中出力・PC 候補条件不一致・strict 分母の違い モデルの反証として扱わず、集計を直す
小さな負差で区間が広い 方向未確定。符号だけで veto しない
A の CE を隠した比較でも同様の悪化が出る CE 欠損による影響という仮説が強まる。本番の既知 CE 条件と欠損時 fallback を分ける

改善する 異なる条件での補助証拠。A と合わせても本番クラス比や LB 増分は確定しない

CE 既知の B は約 4% と少数なので、その小群だけで転移の成否を断定しない。既に用意された A の CE 非表示対照を使える場合は、同じ候補・同じ融合規則で比較すると追加計算を抑えられる。

「10 アダクト対応」は、各分子に常に 10 種類の仮説窓を作る意味にしない。入力で観測される adduct を使い、未知・矛盾がある場合だけ事前に決めた追加仮説へ進む。電荷・分子数係数を含む変換と電子質量補正を一箇所に集約し、既存変換との二重補正を防ぐ。複数 adduct の中性質量が一致しないときも、正解質量を見て選ばず、不一致フラグと固定した窓の統合法で処理する。

(a) Class 1 模擬の作り方

参照の有無と、測定の独立性を分けて定義する。 正解と同じ分子の参照があることは Class 1 の意図した情報であり、残してよい。ただし次の単位を守る。

  • query は本番に近い timsTOF の独立 acquisition を優先する。複数 CE・複数 adduct が同じ取得に属するなら query 側へまとめる。
  • reference は別 acquisition にする。同じライブラリでも独立測定なら利用できるが、独立性が確認できるものを主評価にする。
  • 別ライブラリでも、同じ元スペクトルの再配布なら独立ではない。USI、source accession、元ファイル情報、ピークの hash 等を使って複製を除く。
  • まず同 polarity・同 adduct の直接検索を基準にし、装置が一致／不一致、CE が近い／不明を層別する。異なる adduct や polarity の類似度は、同じ確信度として無条件に混ぜない。
  • 参照がある分子を、あらかじめ類似度が高いという理由で選ばない。弱い一致や強い異性体・アナログの誤一致も含める。

同じ query について「独立した正解参照を残す C1」と「同一 identity group の参照を全ライブラリから隠す C2」を作ると、参照信号を融合が正しく使うか比較しやすい。この二条件は同じ分子由来なので、必ず同じ fit/tune/eval に置き、bootstrap も identity group 単位にする。600 分子を二条件に増やしても、独立な分子数は 1,200 にはならない。

また、参照あり分子だけを集めた C2 は、公開データが豊富な分子に偏る。参照が少ない一般の C2 代理集合も別に残す。Class 1 の比較用集合と、全体の Class 構成比の推定は混同しない。

(b) 統一 LambdaRank のリスク

slot 方式をなくすことで全候補を比較できる利点がある一方、強い参照一致が prior や FP に押し下げられる可能性がある。特に C1/C2 の二条件を人工的に 1:1 で作ると、その学習比率を本番比率と見なしてしまいやすい。

最初の比較では C1/C2 別 MRR、C1 で参照検索単独が正解首位だった分子を落とした件数、C2 で回収した件数を併記する。全体平均だけで採用しない。必要なら、tune で決めた高信頼の参照領域は固定規則を残し、それ以外をランカーに任せる。統一した候補表を使うことと、最初から全ての判断を一つの学習モデルに任せることは別である。

特徴には query 内 z だけでなく、参照類似度の生値、別 identity の首位と次点の差、マッチしたピーク数・強度、複数 query スペクトル間の一致、raw FP/forward score、欠損・対応 adduct のフラグを残す。参照類似度 0.95 と 0.15 を、各 query 内の相対順位だけで同じ扱いにしない。

学習時の group は query 分子と参照条件の組合せ、分割の単位はその上位の identity group にする。候補数が多い query や二条件を持つ分子だけが学習を支配しないよう重みも管理する。shortlist に正解がない group を ranking loss から外す場合でも、全分子評価からは外さない。モデル選択の主指標は公式 MRR@25 とする。

FPNet の評価方法

新たに選んだ分子が「人手の開発に未使用」であっても、FPNet には学習済みの場合がある。例えば fold 0 の分子を 5 モデル平均で予測すると、fold 1〜4 用のモデルがその分子を学習している可能性がある。

最小版は 固定 FPNet fold 0 と、そのモデルの学習から除外された分子で fit/tune/eval を作る案を維持する。MSG 非収載も照合する。C1 の参照検索には意図した独立参照を残すが、query の学習済み範囲を曖昧にしない。

5 fold OOF を使った meta-model 評価へ進む場合は、003 で指摘した outer/inner の区別も必要になる。outer eval が、融合の学習特徴を作る base model の学習に混ざらないようにする。5 モデル ensemble は最終推論候補として扱い、その利得を一モデルの未学習評価値にそのまま載せない。

4. 質問 1(c): 9 時間予算

15 秒/分子が Kaggle 4 CPU 全体での処理時間なら、400 分子で 6,000 秒、約 100 分となる。これ自体で 9 時間を使い切るわけではない。ただし FP 計算だけなのか、SMILES parse・同一性・prior 読み込みも含むのかを明確にする。

P1 の候補窓は A 中央値 10,184、95% 点 20,952、最大 31,358、B 最大 40,296 構造だった。平均時間だけを使わず、候補数・質量・スペクトル数・adduct・CE 数で層別した 30〜50 分子を Kaggle の実環境で流し、起動から最終 CSV まで測る。

予算表は 起動／索引 + 全分子の候補取得・FP + GL + ICE + 最終出力 とする。GL/ICE は候補数だけでなく、候補×実際の CE/adduct 条件でジョブ数を数える。例えば 400×120 候補×3 条件なら各モデル約 144,000 予測であり、400×120 回の計算ではない。全 adduct と全 CE を常に直積にする必要もないので、runner が実際に作るジョブを数える。

初回は、強い参照一致がない query を優先して forward 計算し、残予算が不足したら FP+prior に戻して全分子の出力を完成させる。実験の評価にも同じ fallback を入れる。CPU worker と各数値ライブラリの thread 数を合わせ、4 CPU に対して過剰に並列化しない。既存の索引・メモリマップ・部分 fingerprint の絞り込みは、必要な箇所で再利用してよい。

9 時間にぎりぎり合わせず、長い候補窓、初回 import、cache 作成、出力検証の余裕を残す。初回から候補窓全体への GL/ICE、全 PubChem の公式鍵再計算、5 fold の再学習を加える必要はない。

5. 質問 2: B1 最小版の固定規則

提案の形は妥当だが、lib_max 一つだけで参照を全面優先するのは弱い。短いスペクトルや偶然一致でも高い値が出る場合があるため、少なくとも別 identity への次点との差、マッチしたピーク数または説明強度を確認する。

具体的な開始形は次でよい。

  1. 統一 shortlist 上で S = z(FP) + w_GL z(GL) + w_ICE z(ICE) + λ prior を計算する。z の集合・ddof・欠損処理は固定し、評価と推論で揃える。
  2. 参照一致の信頼条件を満たすときは、高信頼の参照候補を類似度順に優先し、残りを S の順で埋める。参照がない候補同士を同点のまま任意順にしない。
  3. 条件を満たさないときは S の順を使う。モデルが未対応・未完了なら、そのモデルの項を外した事前定義の fallback を使う。正しい 0.0 スコアと欠損を区別する。

まず w_GL=1、w_ICE=1、λ=0.15 を、P1 本体で測定済みの基準として置き、w_GL=2 を少数の候補として tune で比較することを勧める。w_GL=2 を初期値にしても構わないが、PC 専用リストでの優位が統一候補表でも確定したとは説明しない。λ=0 の比較も残し、prior が特定の化学群だけで働いていないか見る。

参照閾値・margin・λ の選択は tune で行う。未知の本番 Class 比率に合わせた平均だけを最大化せず、強い参照一致を壊さないことと、C2 の改善を併せて確認する。最小版の提出までに LambdaRank を完成させる必要はない。

50% 被覆は、P1 で測った条件とは違う

純 Python で現行 new_pc を実行したところ、100 候補のうち GL が前半 50 件、ICE が後半 50 件だけを被覆し、両方のスコアがある候補は 0 件でも融合に進んだ。各モデルの被覆を別々に 50% と数える実装だからである。両方 49 件では fallback になった。

これは現在のコードが想定どおりの条件式で動くことと、その条件が P1 の根拠に対応することの違いである。P1 の K=100 比較はほぼ完全被覆で、50% 欠損時の優位を示していない。欠損を z=0 にすると、未計算候補が「平均的なモデルスコア」として扱われ、既知の低スコア候補を上回ることもある。

単発の転移計測を分かりやすくするなら、全候補で両モデルが有限値のときに新融合を使い、それ以外は旧規則へ戻す条件を推奨する。 部分被覆を採用するなら、同じ欠損マスクを P1 に適用した比較と、両モデル共通被覆・未計算候補の扱いを記録する。50% を未検証のまま残す場合、LB は「新融合＋部分被覆規則」の計測になり、P1 の転移だけを測ったとは言えない。

可視実行が確認した範囲

v2 ログでは、追加候補数 0、pc_e4_fused=1 だが、merge は untouched=12、gentle/aggressive/promoted は全て 0 だった。従って、1 分子で融合分岐が動いたことは、処置された PC リストが最終 merge に使われたことを意味しない。

v3 の可視実行が同じ状態なら、旧処理の動作確認にはなるが、追加 runner と active な PC merge の接続確認にはならない。小さな保存済み入力または fixture で、低い lib_max、実 score 辞書、実 merge/promote、最終出力を通す確認を一回行えばよい。可視テストで精度効果まで測ろうとする必要はない。

以上は E4 の系列を続ける提案ではない。一度の計測が何を測ったのか明確にして区切るための指摘である。B1 の作業はこの計測と独立に進められる。

8. 質問 4: 新しい tune/eval の規模

初期案として、現在の P1 600 分子を fit・開発診断に使い、新規 tune 300 分子（A/B 各 150）、locked eval 600 分子（A/B 各 300）を別 identity group で確保する案を勧める。新規 tune を各 300 に増やす余裕があればよいが、まずは候補とスコアを再利用できる固定規則の比較に絞ればよい。

全て、v1/v2/E2c/P1 等の既使用 group と重複しないこと、評価に使う FPNet の学習から外れていること、forward モデルの学習収載を確認する。locked eval の候補・特徴を事前に計算しても、設定を決める前に各規則の結果を比較しない。

Class 1 は独立参照が利用可能な group 数を先に数え、各 split 内に C1 の部分集合を設ける。その分子には C2 の対照条件も作る。C1 の部分集合は初期に 100〜150 程度確保できると診断しやすいが、必要数のために同じ acquisition の複製で水増ししない。不足する装置・adduct の層は件数を明示する。参照を持つことを必須にして、C2 全体の分子選択を偏らせない。

各 300 は初回の大きな差を測るには合理的だが、+0.01 を精密に確認できる規模とは限らない。今回の PC strict paired delta の標準偏差は A 約 0.247、B 約 0.222 で、N=300 の 95% 区間半幅の目安は約 0.028 / 0.025。もし同程度のばらつきで半幅 0.01 を求めるなら約 1,900〜2,400 分子が必要になる。これは区間幅の概算で、B1 の差に対する検出力の保証ではない。

最初から数千分子を全て forward 推論するより、上記規模で候補脱落・Class 1 取りこぼし・大きな融合差を確認し、判断が小差に依存する段階で独立標本を拡大する。

作成: 2026-10-24、Codex。006_request.md、B1 設計、run1 の結果と特徴表、評価・学習・提出コードを確認した。保存済みデータの CPU 集計と関数の照合のみ実施し、GPU 実験・学習・提出・Spark への接続は行っていない。コードは更新中だったため、以下は保存済み run1 と、末尾に示す確認時のコードを区別して記載する。

1. 結論

B1 を主軸に進める方針と、P1 の開発分子をランカーの fit に利用する方針に賛成する。ただし、現在の C2 評価には C1 から候補が混入する経路があり、学習融合の採否を決める前に修正が必要。 重複参照の再構築だけではこの問題は直らない。

優先するのは次の三点。

  1. C1/C2 の参照条件を候補選択の前に適用し、各条件の shortlist と標準化を分ける。
  2. 参照重複を「類似度 0.98 以上だから同一取得」と確定せず、確実な複製と近似的に重複を疑う群を分ける。
  3. eval_set は既に固定規則の比較・prior 選択に使った開発集合とする。独立な最終評価は、設計文書にある別の locked eval で行う。

参照優先なし、prior=0.5 を当面の固定比較に置くことは妥当。ただし、参照信号が不要と結論づけたり、LambdaRank が文献 prior の分布差を自動的に解消すると期待したりしない。

2. 最優先: C2 の shortlist に C1 の参照が使われている

b1_features.py は C1/C2 の類似度を別々に計算するが、shortlist の参照枠は次の一つだけである。

top_lib = ... argsort(-lib_c1)[:20] ...
short = union(top_fp, top_fpp, top_lib)

b1_evaluate.py とランカーは、この共通 shortlist のまま C2 の参照類似度を 0 にする。したがって「参照があったので初めて候補に入れた正解」が、参照を隠した C2 に残る。

run1 の特徴表で、正解が 参照枠だけから入った分子を数えた結果は A 0、B 7 分子だった。いずれも lib_sim_c2=0、in_top_fp=False、in_top_fpprior=False、in_top_lib=True である。

strict の到達判定も B1 の窓へ更新する

現在の window_external は選定時の P1 形式 CSV から読み込む。一方、B1 は観測された複数 adduct の窓を合併しており、同じ候補取得ではない。

3. 学習コードで対応済みの点と、残る評価上の問題

4. 質問 1: 参照優先を外して学習融合に任せるか

重複の問題が未解決な間、参照優先なしを固定比較にする判断には賛成。ただし最終的な Class 1 対応を省く判断にはしない。 学習融合を試す価値はあるが、上記の候補混入を直した結果で比較する必要がある。

参照優先が C2 を落としただけでは、全体で悪いとは決まらない。例えば現在の B の τ=0.8, margin=0.2 は、S(0.5) に対し C2 約 −0.008、C1 約 +0.285 という交換になっている。C1 の値は重複込みで楽観的だが、両方の損益を見る必要があることは分かる。未知の Class 比率で単一の平均を断定しない。

三条件ゲートは比較候補にはなる。ただし S 上位 k を必須にすると、「FP/forward が外した正解を参照で救う」という補完性も制限する。既存の top-3 結果が小さかったことは、参照信号を捨てる根拠にはならない。

次の最小比較は、独立性を確認した参照で、S(0.5)、参照類似度のみ、固定参照規則、LambdaRank を同じ候補集合上で並べること。C1 で参照が正解首位だった分子を融合が落とした件数、C2 で誤った高類似参照へ昇格した件数を別に出す。学習融合には raw 類似度、同 adduct 類似度、別 identity への margin、一致ピーク数・説明強度・複数 query での整合を使う方が、scenario フラグを与えるより本番に対応する。

5. 質問 2: precursor 5 mDa ＋ 類似度 0.98 の重複除外

重複を疑う候補を集める基準としては使えるが、同一 acquisition の確定条件にはしない。 高い spectral entropy similarity は取得 ID を表していない。

現行の entropy_similarity に、m/z が [100,150,200] と [100.004,149.997,200.006]、強度が両方 [0.5,0.3,0.2] という異なるピーク列を与えても 1.0 になることを CPU で確認した。許容幅内で対応するピークの強度が同じなら起こる。clean_peaks による弱いピーク・precursor 近傍の除去も、異なるスペクトルを同じ比較対象にし得る。

run1 の B C1 82 分子中、正解参照類似度が 0.98 以上なのは 65 分子。再登録を多く含む可能性は高いが、この数をそのまま複製確定件数にしない。独立測定でも高い一致はあり得るし、疎なスペクトルでは別構造も強く一致し得る。

推奨する扱いは二段階。

  • 確実な複製: 元 accession/取得情報が同じ、または元のピーク列・強度・adduct・CE 等が厳密に一致するもの。識別できる範囲で acquisition の cluster として query/reference を分離する。
  • 重複の疑いが強い群: precursor 近傍かつ similarity≥0.98 等。主結果からの除外版と保持版を併記し、この群の除外に結論が依存するか調べる。出典が確認できない場合は「近似重複を除いた評価」と明記し、「独立取得を保証」としない。

過剰除外の検出では、少数例を最高類似度だけで選ばず、ピーク数、装置の一致／不一致、CE、adduct、元の強度差、precursor ppm 差を層別して確認する。明らかに異なる CE・取得メタデータを持つ高類似参照が大量に消えるなら、独立測定を消している疑いがある。

現行の除外実装で注意する点

  1. 除外は正解参照だけでなく、全候補の参照に適用される。したがって高類似の異性体・別構造の参照まで消え、C2 の誤一致を人工的に減らす可能性がある。n_truth_dup_refs だけでなく、非正解側で消した参照・候補も数える。
  2. MAX_REF=24 の打切りが重複除外より前にある。最初の 24 件が複製なら、その後にある独立参照まで使えなくなる。適合 polarity・adduct・重複 cluster を整理してから、CE/装置の多様性を保って上限をかける。
  3. c1_possible は「他ライブラリに何かある」で決まり、重複除外、polarity、ピークの有効性、MAX_REF の後に利用できる参照があるかを反映しない。事前の eligible 数と、処理後の usable 数を分け、残った C1 の件数を明示する。高類似の参照だけを消して C1 が下がった結果を、独立測定の一般的な性能と断定しない。

「0.98 を超える独立測定は稀」という仮定を固定規則の採用理由にせず、上の差分と確認例で判断したい。

7. 質問 4: fit に P1 を使う構成

P1 600 分子を fit に使ってよい。 過去に固定規則の重み選択に使った分子を、後のモデルの訓練データにすること自体は問題ではない。最終評価を別の未使用 group に置くことが重要である。

8. 質問 5: FP 窓採点がボトルネックの場合の優先順位

K の縮小は、窓全体の FP を計算した後の処理なので、主として GL/ICE の時間を減らす。FP 全件採点の解決策とは分ける。 優先順位は次の通り。

優先 対応 理由と確認する指標
1 段階別時間を測り、重複計算・thread 過剰を除く parse/key、fingerprint、参照検索、forward を分離。Spark 2秒/分子を Kaggle 4 CPU の時間と見なさない
2 重なる adduct 窓をまとめ、同じ SMILES の静的計算を再利用する 現行は adduct ごとの候補を連結してから _feat を呼ぶため、重なった候補の FP を繰り返し計算し得る。出典・窓情報を保って先に重複を除く
3 部分 fingerprint の pass-1 → full FP の pass-2 full FP の対象を減らせる。参照検索の強い候補と prior 枠を保持し、正解到達率の減少と時間を比較する
4 forward の対象 K を縮小、または優先順位付きで計算 GPU/runner が支配的な場合に使う。固定候補上で K=60/100 等の回収率・MRR・fallback を測る
5 ppm 窓の縮小 正解が後段から戻せなくなるため最後。校正・adduct 整合・到達率の実測なしに狭めない

部分 fingerprint の上位数は、最初から K=100 に直結させない。安価な pass-1 で数千候補を残し、full FP と参照/prior の候補を経て最終 shortlist にする形がよい。P1 の全候補 full FP を対照にし、どの質量・候補数・adduct で正解を落とすかを記録する。

参照検索も候補数×参照数×query スペクトル数で増える。CPU 時間がここに偏っている場合は、full FP の pass-1 だけでは速くならない。参照の cleaning と適合条件を cache し、同じ比較を C1/C2 用に繰り返さない。duplicate 判定で計算した similarity を、その後の本スコア計算でも再利用できる。

最終的には「残り時間 − 出力・検証の余裕」に基づいて forward の実行量を決め、計算できない分子も FP+prior で提出を完成させる。同じ cutoff/fallback をローカル評価に入れる。Kaggle 可視 test は本番とは候補分布も参照条件も違うので、総時間に加えて候補数・query 数・adduct 数の分布を残す。

  • 「確実な複製」の判定に accession/USI は無いためピーク列一致で代用。装置・CE・アダクトで層別した過剰除外の確認は、重複除外版の結果が出た後に行う。
  • 一致ピーク数・説明強度・複数 query 間の整合の特徴は次段。
  • 公式 scorer(src/metric.py)で最終順位を採点する検証は、B1 の提出前に組み込む。

007 依頼: 検証設計の残る懸念(W1〜W10)への対処案

作成: 2026-10-24 13:35 JST(Claude Code)。006 の判断は 006_decision.md。検証設計と懸念の明文化は docs/validation_design.md(本依頼の対象)。

1. 背景

ユーザーから「この実験の検証方法をきちんとしないと上手くいかない」という指摘を受け、採っている規則と残る弱点を docs/validation_design.md にまとめた。B1 v2 の再構築(Spark)と LambdaRank 本試験、locked eval の計算を待つ間に、懸念 W1〜W10 への対処を検討したい。実装前の設計相談であり、新しい実験結果はまだ無い(v2 の結果は 15:00 頃)。

2. 特に意見がほしい点

  1. W1(本番そっくりの検証データが無い): timsTOF × 天然物の層が手元に無い。候補: (a) 公開パネル 250 分子(enveda-np-examples、timsTOF、天然物)を「装置差の層」として、順方向モデル以外(FPNet・ライブラリ検索・prior・融合規則の形)の評価に限定利用する(MSG 重複 236 分子のため GL/ICE の値は使わない)。(b) enveda-180 から NP-likeness の高い部分集合を切り出し、A の中の「天然物に近い化学」層を作る。(c) B の分子について timsTOF の参照が無い以上、装置差は A と B の差分と E4 の LB 転移から推定するにとどめる。どれを優先すべきか、他の案はあるか。
  2. W2(Class 比率が不明): 公開 LB の分布(0.46〜0.50 に集中、首位 0.504)、公開解法の Class 1 性能 ≈0.95、E0 の LB 0.464 と手元の strict 値から、Class 3 比率の下限や Class 1/2 の大まかな比を逆算できるか。逆算に必要な仮定と、その仮定が崩れたときの読み方。
  3. W3(Class 3 を模擬していない): 生成手法に着手する前に、評価枠組み(正解を全 DB から除く C3 模擬、MRR 以外の中間指標)をどう作るか。検索型の上限 = 1 − Class 3 比率という扱いで当面よいか。
  4. W5(標本サイズ): +0.01〜0.02 の差を見るには 1,000〜2,000 分子が必要。Spark では特徴表 2 秒/分子、GL/ICE 合わせて 1 分子 10 秒程度なので、A/B 各 1,000 の拡大は現実的。拡大の優先度と、拡大時の群設計(開発/locked の両方を拡大するか)。
  5. W6(実行時間): 隠しテスト条件(16 本/分子、質量 1,159 Da、10 アダクト、水損失)を模した合成テスト parquet を作り Kaggle で時間を測る案。学習データから「天然物 400 分子・各 1〜16 本・10 アダクト」を抜き出して test.parquet の形式にすれば、本番に近い負荷と(ラベル付きなので)精度の両方が測れる。可視実行の時間だけで判断するより良いか。
  6. W7(評価と提出の設定ずれ): 同じ分子を評価器と提出パイプラインの両方に通し、候補集合と特徴が一致することを確認する回帰テストを入れたい。確認すべき項目(候補の鍵集合、FP 値、類似度、prior、shortlist の所属)と許容差。
  7. W9(学習融合の過学習): fit が P1 の A(合成化学 300)に偏る。A/B の重み付け、group 単位の bootstrap、単調制約(FP・GL・ICE・類似度は正、質量誤差は負)を LightGBM に入れることの是非。
  8. W10(最終 2 提出の選び方): 「LB 最高ではなく locked eval 最高を 1 本、LB との整合を見て保険を 1 本」と事前に決める案への意見。
