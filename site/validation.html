検証設計と残る懸念(2026-10-24 13:30 版)

この文書は「何をもって改善と認めるか」の規則と、まだ解けていない弱点を明文化したもの。更新はコミット単位で追う。

1. 本番条件(分かっていること)

  • 隠しテスト: 天然物 約 400 分子、約 1,500 本、1〜16 本/分子(中央値 3)、timsTOF(Bruker)、10 アダクト(水損失を含む)、質量 157〜1,159 Da。
  • Class 1(ライブラリに参照あり)/ 2(構造は PubChem・COCONUT にある)/ 3(新規)の比率は非公開(推定は 3 割〜7 割まで割れる)。
  • Public LB は約 130 分子と推定(参加者推算。1 分子の最大寄与 ≈0.0077、順位 1→2 なら ≈0.0038)、1 日 5 提出、採点は E0 で約 4.5 時間かかった(観測値、保証ではない)。

2. 採っている規則

原則 具体 根拠
分子単位の分離 公式同一性(立体除去 + タウトマー正規化 InChIKey14)で identity group を作り、fit / tune / eval を group 単位で分離 同じ分子の別スペクトルが両側に出ると類似度検索が自明になる
未学習分子で測る FPNet は fold 0 固定、fold 0 の分子のみ評価。GLACIER/ICEBERG は MassSpecGym 非掲載分子のみ E1 でパネル 250 分子の 236 が MSG に含まれ、順方向モデルの評価が汚染されていた
クラス別の模擬 C2: 参照スペクトルを全て隠し学習構造としての存在も隠す。C1: 別ライブラリの独立参照だけ残す。同じ分子で両条件を作り同じ split に置く Codex 005/006
ラベル非依存の候補取得 分子式・正解追加を使わず、実測 m/z とアダクトから ±10 ppm で候補取得。到達不能な正解は 0(strict) P1 設計
同一候補での比較 融合規則の比較は同じ shortlist 上で。候補取得の変更は同一 query 台帳で経路全体を比較し、到達率と条件付き順位を分ける。分子ごとの paired delta と bootstrap 95% 区間(identity 単位で全 view を一緒に再標本化) 002/003/007
層別報告 A(timsTOF・合成化学)と B(天然物化学・他装置)を別々に。本番比率を仮定した単一指標は作らない 003
視点別 shortlist C2 の shortlist に C1 参照由来の正解が入らないよう、参照枠は視点ごと 006(B で 7 分子の混入を検出)
複製参照の除外 ピーク列一致群(同アダクト・ Δprec
出典なし候補の除外 C2 視点で、外部出典が無く学習構造としての存在も隠された候補は除く(残すと「出典の無い候補 = 正解」という漏れ) 006(予備試験で +0.11 の見かけの利得を作っていた)
最終判断は 1 回 開発集合(eval_set)で設定を決め、未使用の locked eval(seed 4)で 1 回確認。eval を見て設定を変えたら開発集合に降格 006
公式スコアラーで採点 src/metric.py(公式メトリックの複製)で最終値 003
LB の使い方 1 変更ずつ、方向の確認のみ。増分を予測しない 005

採否(007 で改訂): (1) 機械的条件(候補・特徴・公式出力の parity、分母、欠損処理、時間予算)を満たす。(2) 固定した対照に対する paired delta・効果量・区間を報告し、A/B の一方の小さな負差を直ちに矛盾と扱わない。(3) C1 の保護は事前に決めた非劣性幅 ε で判定。(4) 開封前に主候補・保険候補・規則を固定し、locked で 1 回確認。(5) LB は不整合の大きさと処置の適用範囲を調べる材料で、符号一致を必須にしない。

3. 残る懸念(優先順)

# 懸念 影響 現状の対処 検討したいこと
W1 本番そっくりの検証データが無い(timsTOF × 天然物)。A は timsTOF だが合成化学、B は天然物だが Orbitrap/QTOF 装置差 × 化学差の交互作用を見落とす。A・B の差分からの推定に頼る A/B を別々に報告。E4 v5 の LB で転移を 1 回計測 パネル 250 分子(enveda-np-examples、timsTOF 天然物)を「装置差の層」として限定利用できるか(MSG 重複 236 分子 → 順方向モデル評価には使えないが、FPNet・ライブラリ検索の装置差測定には使える?)。enveda-180 から天然物様の部分集合(NP-likeness 高)を切り出す
W2 Class 比率が不明 何を優先すべきか(Class 2 融合 vs Class 1 保護 vs Class 3 生成)の重みが決まらない。LB 上限も不明 層別報告のみ 公開 LB の数値分布(0.46〜0.50 に集中、首位 0.504)と、公開解法の Class 1 性能(≈0.95)から比率を逆算できないか。E0/E4 の LB と手元の strict 値の比から Class 3 比率の下限を推定
W3 Class 3 を模擬していない 検索型では 0 点。生成手法の評価枠組みが無い 上限 = 1 − Class 3 比率として扱う 「正解を全 DB から除いた」C3 模擬(近縁構造・部分構造一致の部分点は MRR では 0)。生成の評価は別指標(Tanimoto)で先に測る
W4 複製参照の判定が近似 C1 の値が楽観的/悲観的にずれる 確実な複製と疑いを分け両方併記 装置・CE・アダクトで層別し過剰除外を確認。ピーク列一致の閾値の感度
W5 標本サイズ 各 300 分子では 95% 区間の半幅が約 0.025〜0.028(paired delta の SD ≈0.22〜0.25)。+0.02 を検出力 80% で見るには約 1,000〜1,200、+0.01 には約 4,000〜5,000 分子 区間が 0 を含む差は「点推定は正だが未確定」 開発側 各 500〜1,000、locked 側 初回 各 1,000(未開封、結果を見ながら追加しない)
W6 実行時間の検証が本番でしかできない 9 時間超過は 0 点 Notebook 可視実行で段階別時間、fallback(順方向なしでも提出完成) 隠しテスト条件(16 本/分子、1,159 Da、10 アダクト)を模した合成テスト parquet で Kaggle 実行時間を測る
W7 評価と提出の設定ずれ ローカルの利得が提出に移らない query 選択・候補源・λ を統一(v2) 評価器と提出パイプラインで同じ候補表を作る回帰テスト(同じ分子で特徴が一致するか)
W8 アダクト別の性能が未測定 負モードのみの分子(公開テストで 7%)は順方向モデルが使えない FP + prior + ライブラリで順位付け アダクト別・極性別の strict MRR を報告に追加
W9 学習融合の過学習 fit が合成化学(P1 の A 300)に偏ると B で悪化 tune/eval を A・B 両方で見る A/B の重み付け、group 単位の bootstrap、特徴の単調制約
W10 Public LB への過適合 130 分子で ±0.01 1 変更ずつ、方向のみ 最終 2 提出の選び方(LB 最高ではなく locked eval 最高)を事前に決める

5. Codex 007 の判断(14:05)

優先順位: W7(評価/提出の一致、固定分母)→ W4/W8(参照条件・adduct 層の台帳)→ W1 限定診断(パネル 250 は FP/参照/prior/規則の形の診断、同一 identity の装置差組、A の事前固定した化学層)→ W9(学習融合の比較、identity 単位 bootstrap、単調制約は 1 変種)→ W5(拡大)。W6 は並行。W3 は「DB holdout の C3 代理」の枠組みだけ先に決める。 Class 比率は LB から逆算しない(純検索型なら p3 ≤ 1 − S の上限のみ)。最終提出は開封前に主候補・保険候補を固定。詳細は reports/agent_review/007_decision.md。
