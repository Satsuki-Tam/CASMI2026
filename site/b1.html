B1: 自前ベースラインの設計(2026-10-24 10:30 版)

方針(ユーザー判断 09:45): 公開ノートブックへの局所修正で改善を積まず、調査と P1 の結果から自前のベースラインを作る。E4 v5 は P1 の代理指標が LB に転移するかを測る 1 回限りの計測提出。目標は金圏 0.480 以上(できれば 0.500 以上)。

1. 課題の構造(調査と P1 から)

  • 隠しテスト: 天然物 約 400 分子、timsTOF 約 1,500 スペクトル(1〜16 本/分子、中央値 3)、10 アダクト、157〜1,159 Da。Class 1(ライブラリに参照あり)/ 2(PubChem・COCONUT にある)/ 3(新規)の比率は非公開。
  • Class 1 はライブラリ検索でほぼ解ける(公開系譜で 0.95 超)。Class 2 は「同一分子式異性体の識別」が本質で、P1 では fold-safe FPNet が分子式をほぼ決め(top-1 誤りの 91% が同一分子式)、GLACIER + ICEBERG の全体 z 和が異性体識別の主力(timsTOF 300 分子で FP 0.465 → 0.723)。文献 prior は窓全体では無力だが shortlist 上では小さく効く。
  • 公開系譜の構造的な弱点: PubChem 候補を slot(2,4,6,8,10,24)に差し込むため、Class 2 の正解は昇格されない限り最良でも 2 位。候補 25 件・同一分子式 slot 固定の再順位は、全体 z 和より 0.03〜0.08 低い(P1 模擬 v2、A・B で一致)。

3.1 アダクトと順方向モデルの被覆(公開テスト 400 分子で測定)

  • スペクトル数/分子: 中央値 3(最大 9)、アダクト種/分子: 中央値 1(最大 3)。
  • 順方向モデル(GLACIER / ICEBERG は正モード [M+H]+ / [M+Na]+ のみ)が使えない分子: 29/400(7%)。すべて負モードのみ([M-H]- 51 本、[M+CH2O2-H]- 3 本)。
  • B1 の扱い: 負モードのみの分子は FPNet(負モード入力対応)+ 文献 prior + ライブラリ類似度(同極性参照)で順位付けする。順方向モデル項は欠損として外す(z=0 ではなく項を落とす)。隠しテストは 10 アダクト(水損失を含む)なので、負モード比率は公開テストより高い可能性がある。

読み取り: - 順方向モデルの全体 z 和が主力(A: FP 0.49 → S 0.67、B: 0.14 → 0.35)。prior 重み 0.5 は 0.15 より一貫して良い(A +0.007、B +0.034、C1 集合 +0.034)→ B1 の既定値を 0.5 に変更。 - 参照優先規則は Class 2 を落とす(τ 0.6 で A −0.05)。合成ライブラリ(enveda-180)では類縁体の参照スペクトルが高い類似度を出すため、「高い類似度 = 正解がライブラリにある」が成り立たない。Class 1 の利得は重複除外後の C1 で測り直す。学習融合(LambdaRank)に類似度・次点差・参照数・同アダクトを特徴として渡す方が筋が良い。 - B の C1 で類似度 1.000 の参照が大半: 同じスペクトルの再登録(GNPS → MoNA/MassBank)。参照の独立性を保つため、同一プリカーサ・類似度 ≥ 0.98 の参照を重複として除外する処理を追加し、C1 集合を Spark で再構築中。

6. 学習融合(LambdaRank)の統合(12:30)

  • 共通特徴モジュール b1_rankfeats.py(学習と推論で同じ関数): z(FP)、z(GL)、z(ICE)、生スコア、prior 成分(SID/PMID/synonyms/NP/寄託源/LOTUS)、ライブラリ類似度・同アダクト類似度・参照数・次点差・分子内最大、出典フラグ、質量誤差、FP の窓内順位、候補数、欠損フラグ、query 数、CE 既知。シナリオ(C1/C2)のフラグは推論時に分からないため特徴に入れない。
  • 学習(b1_rank_train.py): 行 = shortlist 候補 × 視点(C2 と、参照のある分子では C1)。C2 視点では「外部出典が無く学習構造としての存在も隠された候補」を除外する(残すと『出典の無い候補 = 正解』という漏れになる。予備試験でこの漏れが +0.11 の見かけの利得を作っていた)。fit で学習、tune(C2 strict + 0.5·C1)で設定選択、eval 群で固定規則 S(2,1,0.5) と比較。
  • 推論(b1_pipeline.py --rank_model): モデルファイルがあれば LightGBM で候補を並べ替え、無ければ固定規則。Notebook 生成時にモデルを同梱。
  • 予備試験(fit = 新評価集合の fit 群 186 group のみ、eval 群 199 分子): C2 strict 0.490 → 0.517(+0.026 [−0.005, +0.057])、C1(n=29、重複込み)0.392 → 0.696。本試験は P1 600 分子を fit に加え、重複除外版の特徴で行う。

7. v2(Codex 006 対応、12:50、commit 7af074d)

  • 視点別 shortlist: 参照枠を C1/C2 それぞれの類似度で作り、保存表は和集合 + 所属フラグ。旧版では C2 に C1 参照由来の正解が混入していた(B 7 分子、MRR 寄与 0.0097)。
  • 到達判定: reach_external_b1(B1 自身の窓で、正解の raw 鍵またはタウトマー別名が tier/COCONUT 出典の候補として存在)を strict マスクに使う。
  • 重複参照の 2 段階: 確実な複製(同アダクト・|Δprec| < 5 mDa・cleaned ピーク列一致)は常に除外。疑い(類似度 ≥ 0.98)は主類似度から除外し *_keepdup を併記。非正解側の除外数も記録。MAX_REF は分類後。C1 の分母は処理後に参照が残る分子(c1_usable)。
  • C2 視点で出典なし候補を除外(評価・学習とも)。空候補の分子も分母に残す。paired delta は strict でも報告。fit/tune/eval の identity group 共有を assert。
  • λ の分離: shortlist 0.15 / 融合 0.5。提出パイプラインの query 選択(アダクト round-robin、最大 8)と候補源(tier + pool + prvsiyan COCONUT)を評価と一致させた。アダクト窓をまたぐ SMILES の重複を指紋計算前に除去。
  • 評価集合の役割: eval_set は開発集合(prior 選択に使用)。採用判断は locked_eval(seed 4、A/B 各 300、未使用 group)で 1 回だけ。
  • 再構築(Spark): run1_v2(eval_set)、run_c1_v2(C1 集合)、run_p1_v2(P1 600、LambdaRank の fit)。

8. 評価モード付き提出パイプライン(14:10、Codex 007 W7)

b1_pipeline.py に評価用の入力を追加: --exclude_rows(query 自身の取得行を参照から外す = C1 模擬)、--exclude_identities(正解 identity の参照を全て外し、学習構造としての存在を隠し、外部出典の無い候補を候補集合から除く = C2 模擬)、--solution(公式スコアラー複製で採点、分子別 RR と set/group/lib 別の集計)。参照側の複製除外(ピーク列一致・類似度 ≥ 0.98)も提出コードに入れた(本番では発火しない)。 make_eval_test.py が選定 CSV から test.parquet 形式(新評価集合: 600 分子・2,221 本・10 アダクト)と正解・マスクを作る。これで評価と提出が同じコードを通り、特徴表方式(b1_features.py)との parity 確認にも使う。Spark で C2/C1 の端から端の評価を連鎖に追加。

4. 進行中(10:30)

  • eval_set A/B の特徴表構築(約 9 秒/分子、CPU 競合時)→ GL/ICE → b1_evaluate.py。
  • eval_c1 の選定完了後に同じ流れ。
  • E4 v5 の可視実行 → ログ確認 → 計測提出(自動)。
