144 事前登録(2026-10-30 10:04 JST、Claude Code)— 第二エンジン E2 と P の融合(143 の主軸、土台の作り直し)

E2 の学習の結果も、開発での数字も、まだ一つも見ていない時点で登録する。

1. E2(独立した第二エンジン)の定義

  • 窓(experiments/e2/b1_ewin.py)
  • query の ±10 ppm にある、次の源の全構造を窓に入れる。shortlist で切らない。
    • v2 pool(train / COCONUT)
    • COCONUT store
    • PubChemLite(tier 行のあるもの)
    • BIO
  • 構造は official key で統合する。
  • view ごとの扱い(e2_common.view_frame):
    • C1: 全行を使う。
    • C2: 正解の「train だけにある行」を除く。C2 の前提では、正解は train に無いからである。
  • 特徴(e2_common.FEATS、21 個)
  • fp(f.z)と、窓の中での順位・z・最大値との差、窓の大きさ、ppm 誤差
  • view の train の印
  • ライブラリ類似度(sim / same / nref と、窓の最大値との差)
  • MetFrag-lite(値・順位・差)
  • analog propagation(ap / a1 / best_tan / top_tan / mean_tan と、ap の順位・差)
  • 使わないもの: 人気度、GL、train の印以外の source の印。
  • FPNet は各分子の fold の fold-safe 版を使う。P の表と hash が一致することを確認済み(fold 1 1739d568、fold 2 257062cb、fold 3 ac61125e、fold 4 ad0b2a43、パネル full_eval 5b8d1c31)。
  • 学習(e2_train.py)
  • 学習行: fold 3 / 4 の pool の 6 ディレクトリの C1 群と C2 群。
    • C2 群: 正解が窓の中にある群。
    • C1 群: そのうえで、除外の後に参照が 1 本以上ある群。
    • 分子が重なる場合は、最初のディレクトリの行だけを残す。
    • 行の重みは 1 / 群の大きさ。
  • 学習器: LightGBM binary。パラメタは固定する(lr 0.05、葉 63、min_data 50、feature/bagging 0.8、l2 1、seed 7)。
  • 木の本数: {100, 200, 400, 800} の中から選ぶ。
    • fold 3 → 4 と fold 4 → 3 の、学習 fold の中だけの交差で決める。
    • 基準は、(方向, view) の 4 区画の MRR@25 の平均。
    • 開発の fold 1 / 2 とパネルは、学習にも本数の選択にも一切使わない。

2. 融合の候補(定数は固定。E0 の LB で合わせた値は使わない)

  • 開発の比較の対象は、P の上位 25 件と同じ (set, view, 分子) の群で、対にして比べる。
  • P の上位 25 件 = diag/top102_.parquet、v8w7a の main の順。
  • 比べるリスト:
  • P
  • E2 単独
  • rrf0.5 / rrf1: s = 1/(10 + r_P) + w/(10 + r_E)。
    • 候補は、P の上位 25 件と E2 の上位 25 件の和。
    • r_E は view の窓全体での E2 の順位。
    • 欠ける項は 0 とする。
  • hedge: P の順で、E2 の 1 位が P の上位 2 件に無ければ、2 位に挿入する。
  • rrf0.5_h / rrf1_h: rrf の順に、同じ挿入をする。

3. 開発での読み(主指標 = Public への射影 PD)

  • 層
  • T = C1 の群。G(合成の timsTOF)と、パネル C1 の非 clean は除く。
  • B = C2 の群のうち、正解が COCONUT の構造であるもの。
  • R = その他の C2 の群(G は除く)。
  • PD = 0.148·r_T + 0.220·r_B + 0.026·r_R
  • r_g = Σ RR(リスト) / Σ RR(P) − 1 を、層 g の群をプールして求める。
  • 係数は、Public で確定済みの v8w7a の群の寄与である(1029: v8w7a_T 0.148、v8w7a_B 0.220、残り 0.394 − 0.368 = 0.026)。今回の候補を見て決めた値ではない。
  • 区間: 各 (tag, set, view) の区画の中で分子を再標本する。2000 回、seed 144 で 95% 区間を出す。
  • 選択
  • c* = 5 つの融合候補(rrf0.5、rrf1、hedge、rrf0.5_h、rrf1_h)のうち、PD の点推定が最大のもの。
  • 同点の場合は、hedge → rrf0.5 → rrf1 → rrf0.5_h → rrf1_h の順(単純なものを優先)。
  • 関門(Public の 1 枠を使う条件)
  • PD(c*) ≥ +0.005、かつ下限 > 0。
  • 保留
  • 関門を通らないが r_B(c*) の下限 > 0 の場合は、Public には出さず、原因を分析する。
  • 不採用: 上記以外。
  • 記述だけ(判定に使わない): E2 単独の層別、1 位の相補性(P だけ正しい / E2 だけ正しい)、区画表、窓の中に正解がある割合、G の層。

  • 暫定採用: 0.402 以上。新しい土台にする。

改訂 v2(2026-10-30 10:07 JST = git 1b7b19b の時刻、Codex 143 の回答を受けて。E2 の学習も評価もまだ走らせておらず、数字は一つも見ていない)

§2〜§4 を、以下で置き換える。 旧 §3 の射影 PD は、判定に使わない。理由は、Public の T/B の probe は候補を絞った順位の値であり、通常の MRR の寄与の分解にならないからである(Codex 143 Q1)。

2'. 融合の候補(定数は固定)

  • F: identity 単位の RRF。
  • 候補は、P の上位 25 件と E2 の上位 25 件の和。
  • s = 1/(10 + r_P) + 0.5/(10 + r_E)。r_E は view の窓全体での E2 の順位。欠ける側の項は 0 とする。
  • 同点は P の順位 → E2 の順位 → key の順で決め、25 件で切る。
  • E2 が空なら、F = P になる。
  • F0: 重みを 0 にした同じ処理で、E2 の候補は加えない。全ての群で P と完全に一致することを、技術検査とする。
  • H: F の順で、E2 の 1 位が F の 1 位でも 2 位でもなければ、2 位へ移すか挿入する。
  • F の 1 位は保つ。その他の相対順序も保ち、25 件で切る。
  • 対照・記述用(判定には使わない):
  • pe: P を view の E 窓の候補に制限した順。
  • Fpe: RRF(P, pe)。候補源の重み付けだけの効果を測る。
  • Hp: P に同じ挿入をしたもの。
  • F1: 重み 1 の RRF。
  • E2 単独。

3'. 開発での読み(102 の最終登録を継承する: experiments/e2/e2_eval.py)

  • 事前の検査(読む前に全て通ること)
  • 群が P の群と完全に一致すること。
  • F0 = P であること。
  • E2 が空の群で F = P であること。
  • 値が [0, 1] にあること。
  • 主指標: 1/2 A + 1/2 B_D(F − P)。
  • A = 053 の NP_H / NP_N の C2(両 fold、4 区画を等しく重み付け)。
  • B_D = f1 / f2 の D の C2。
  • F の関門: 主指標 ≥ +0.005、かつ下限 > 0。そのうえで、以下の下限が全て −0.01 以上であること。
  • A、B_D
  • 旧 B(f1/f2 NP C2 の C〜F)
  • E 源の外の正解の C2(プール)
  • G C1
  • パネル C1 clean
  • 053 NP C1
  • 区間は、区画の中で分子を再標本して出す(4000 回、102 の seed)。
  • H の関門(F とは別に読む): H − F の主指標の点推定 > 0、かつ下限 ≥ −0.005。加えて、H の P に対する保護の下限が全て −0.01 以上であること。
  • Public の診断経路(Codex 143)
  • F がローカルの関門を通らなくても、次の両方を満たせば、F を「ローカル不合格の診断提出」として Public へ一度出してよい。
    • (a) E 源の正解の C2 で、F − P が両 fold とも正である。
    • (b) A + 旧 B の C2 で、新たに 1 位になった分子が 10 以上ある。
  • この場合、P の置き換えを先に決めない。
  • 記述(判定には使わない):
  • 層別の各リスト、oracle max(P, E2)
  • 窓への到達 → E2 の上位 25 件への到達 → F の上位 25 件
  • 救済と損失、F − Fpe(候補源の重み付けを超える E2 の順位の価値)
  • 混合の感度(E 源の内の利得 g と外の費用 c、損益分岐 w*。隠しの w の推定ではない)
  • 旧 PD は参考値に留める。

4'. Public での読み

  • 第 1 枠: F の通常の出力(関門を通過、または診断経路で出す場合)。
  • 0.409 以上: 明瞭な正方向。新しい土台の候補とする。
  • 0.379 以下: 負方向。
  • その間: 保留。
  • これらは有意差検定ではない。
  • 第 2 枠: H。H の関門を通った場合だけ出す。
  • H − F ≥ +0.015: 正。
  • H − F ≤ −0.015: 負。
  • その間: 保留。差が小さい場合に、E0 の +0.010 を理由として採用へ繰り上げない。
  • F と H を同じ日に出す場合は、どちらの Public も見る前に、両方のコード・入力・出力の規則を凍結する。
  • 132 との関係: 132 は別の凍結候補として結論を残す。132 の順位を F の対照へ置き換えない。

1' への補足(学習)

  • 各群の総重みは 1 とする(行の重みは 1 / 群の大きさ)。C1 と C2 の比は、群の数のままにする(追加の重み付けはしない)。
  • 正例の無い群(正解が view の窓に無い群、C1 で参照の無い群)は学習から除く。除いた数は、view ごと・ディレクトリごとに manifest に記録し、黙って除かない。
  • E 窓の被覆の限界: PubChemLite のうち tier の SMILES が無い 51,516 件は、窓に入らない(E key v2 の manifest)。被覆の不足として開示する。
