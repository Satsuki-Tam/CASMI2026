なぜ変えるか

  • 現在 0.394。0.500 まで +0.106。これまでの部品(MIST、GL の適応、class 3 の selector など)は、どれも登録の基準に届かないか、効果が +0.01〜0.02 の規模だった。全部を楽観的に足しても 0.45 前後で、届かない。
  • E0(0.464)との差 0.07 の内訳は、Public の診断で分かっている。
  • COCONUT 群(train 外): E0 0.259 対 P 0.220。
    • E0 の一本目だけでは 0.213、二本目だけでは 0.223 で、どちらも単独では P と同程度。
    • 融合で 0.249(+0.026)、2 位ヘッジで 0.259(+0.010)。
  • train 群: +0.012。残り: +0.019。
  • 利得の源は、性質の違う二つのエンジンの融合である。
  • 132 の E-lite の二本目は、P の shortlist の中で、P とほぼ同じ特徴の ranker を使っている。誤りが P と似ているので、融合の利得が小さいはずである(102 の開発でも費用が出た)。
  • E0 の二本目は、窓・学習器・証拠・学習行の全てが一本目と違う(069 §2.3)。
    • 窓: COCONUT・BIO・PubChemLite・train の全窓で、切り詰めない。
    • 学習器: 点ごとの GBDT。
    • 証拠: GL を使わず、ライブラリ・analog・MetFrag を使う。
    • 学習行: ライブラリから class 1/2 を模擬した行。

何を作るか(我々の実装・我々の検証。E0 の重み・行・LB で合わせた定数は持ち込まない)

  1. 第二エンジン E2: - 窓: query の ±10 ppm の、COCONUT・train・PubChemLite / BIO(E key v2)の全構造。shortlist で切らない。 - 特徴: P と重ならない証拠を中心にする。fold-safe FPNet の f.z と窓内の順位、ライブラリの類似度(view の mask)、analog propagation、MetFrag-lite、ppm。人気度・source・GL は使わない(P との誤りの相関を下げるため)。 - 学習器: 点ごとの LightGBM binary(固定のパラメタ)。 - 学習行: fold 3 / 4 の train の identity で、C1 / C2 を模擬した行(W135 の world の mask の仕組み、または b1_features の view)。
  2. 融合 F: P と E2 の identity 単位の RRF。2 本の top-1 が割れるときは、E2 の top-1 を 2 位へ置くヘッジを加える。定数は、開発で決める規則か、事前に固定した値にする(E0 の LB で合わせた α 0.6 / offset 3 はそのまま使わない)。
  3. 検証: - 開発: np053 / f1 / f2 の C1・C2 view と、W135 の世界(class の混合 π 0 / 0.3)。 - Public: 段階ごとに一回ずつ確認する(1 日 5 枠を計画的に使う)。
  4. その上に: class 3 の生成(W135)と A3(GL の識別)を、融合の中の部品として後から載せる。

  • 132 が保留 / 不採用: 「P に似た二本目では融合が効かない」と読み、E2 をより独立に作る設計を、むしろ強める。E0 自身の診断で、二本の融合が Public で +0.026 だったことは確定している。
